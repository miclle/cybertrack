# 泡泡表演编排

## 体验与执行边界

明确进入编排时，先保存草稿，再预览和修改，最后由家长在网页确认。首版仅编排行走和泡泡，保留既有 1–16 步、各步独立速度和时长范围；每步至少一个动作，喷水和点火字段固定为 0。普通直接语音动作仍按现有工具执行，编排模式不替换直接遥控。

草稿接口没有输出调用，保存、查询、替换一步、删除一步均不启动执行器。新草稿或每次修改产生递增版本；无有效草稿时 `revision=0`。编辑必须携带读取的版本，冲突返回 `draft_changed`，不能静默覆盖或自动重试。`replace_step` 只替换指定一步，其余步骤由设备复制保留；删除最后一步拒绝，应明确取消整份草稿。

草稿在最后修改后 5 分钟失效；时钟回退、故障、BOOT／统一停止、Wi-Fi 中断或关机也使草稿失效。网页来源草稿随对应网页会话释放／失租失效；语音来源草稿随语音连接关闭失效。失效后需要重新创建，不恢复旧草稿。仅查询不会刷新草稿寿命。

执行确认由已有网页会话发出，仍需新的设备窗口、递增请求序号和**预览中的确切版本**。匹配的确认只消费一次草稿；即使因通道忙碌／冷却等原因未启动，也不会排队或保留为自动重试。确认后复用现有设备序列调度、间隔与停止逻辑，来源标为 `web`，网页会话断开或失租时取消当前和后续步骤；语音连接变化不取消仍有效的网页序列。统一停止仍优先。

这是网页控制会话内的显式确认，不是家长身份认证。设备不能从语音转写独立证明人的意图；候选角色与评测负责区分“编排”与“直接执行”，本地草稿 API 只保证自身不输出。不能声称任何模型误选普通动作工具都被本机制阻止。

## 设备状态

`capabilities.show_draft=true` 表示设备实现草稿契约；不表示网页已接入。`show_draft` 返回：

```json
{
  "active": true,
  "revision": 7,
  "expires_in_ms": 299000,
  "source": "voice",
  "steps": [{"direction":"left","move_ms":880,"water_ms":0,"bubbles_ms":0,"ignition_ms":0,"speed_percent":100}],
  "nominal_duration_ms": 880
}
```

`nominal_duration_ms` 是各步最长通道时长之和，加步骤间 200 ms，供预览参考，不是实测总时长、转角或位移。调度延迟或中断会改变真实运行。草稿内容由固定存储在互斥锁内复制，JSON 在锁外编码，不在截止任务中分配内存。

执行仍查询 `sequence_active/step/steps/result`，新增 `sequence_source` 区分 `web`／`voice`／`none`。近距离保护取消前进和序列时，已开启泡泡按原独立通道规则结束；残留通道继续保留网页来源，释放网页仍会关闭它，不形成失去所有者的输出。

## HTTP 契约

沿用 `/api/action`、同源限制、令牌与设备窗口，不新增开放端口。示例只说明结构，不能将示例窗口／序号用作设备实测。

```json
{
  "operation": "show_edit", "sequence": 1, "window": 1,
  "draft": {
    "edit": "replace", "revision": 0, "step": 0,
    "steps_json": "[{\"direction\":\"none\",\"move_ms\":0,\"water_ms\":0,\"bubbles_ms\":1000,\"ignition_ms\":0}]"
  }
}
```

| edit | step | steps_json | 行为 |
|---|---|---|---|
| `replace` | 0 | 完整 1–16 步数组字符串 | 创建／替换草稿，返回 `draft_saved` |
| `replace_step` | 1–当前步数 | 只有一步的数组字符串 | 只替换该步，返回新版本 |
| `remove_step` | 1–当前步数 | 空字符串 | 删除该步；剩余必须至少一步 |
| `cancel` | 0 | 空字符串 | 取消匹配版本草稿，返回 `draft_cancelled` |

确认使用 `{"operation":"show_confirm","sequence":2,"window":2,"revision":7}`。`accepted` 只表示执行开始，不能说整段表演完成。直接网页动作若中断正在执行的网页表演，返回 `show_cancelled`，该次不会自动启动新动作。

`/api/action` 最大 JSON 请求体为 8192 字节，以堆内存承载，支持编码后的 16 步；其他接口仍为 384 字节。缺字段、额外／重复字段、非整数、错误索引、超限或不支持的效果均拒绝。原 16 步 JSON 字符串上限仍为 4096 字节。

## 灵矽工具与角色

新增 `self.tank.compose(edit, revision, step, steps_json)`，只负责草稿创建／修改／取消，使用相同解析和版本检查。候选角色要求先查询版本，模糊时长先澄清；保存后简短说明变化，请家长在网页核对。没有语音确认执行工具，不用 `sequence` 或单项动作工具绕过网页确认。普通直接动作仍遵守原默认时长、参数、停止与成功静默约定。

[角色唯一源](../firmware/esp32-audio/role-prompt.txt)已加入编排优先规则，删除旧格式示例以保留平台字符上限内的语义约束。该候选未同步到平台；在网页完整体验、固件及工具发现验证准备好之前，不单独替换线上角色。

[8 条编排增量用例](validation/compose-cases.json)与原 80 条直接动作集分别评分。用例定义模拟状态上下文和允许的工具；禁止在草稿场景调用直接动作，即使总准确率达到门槛也不通过。执行：

```sh
python3 scripts/evaluate_voice.py <实际捕获轨迹.json> \
  --corpus docs/validation/compose-cases.json --output output/compose-score.json
```

目前只有评分器与主机回归结果，没有实际模型分数或真人语音成绩。
