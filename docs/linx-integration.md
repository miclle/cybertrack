# 灵矽接入方案

更新：2026-10-24。以下区分官方协议事实和 CyberTrack 拟定行为。设备绑定、WSS、工具发现、状态及停止闭环已通过，见[实测记录](linx-validation.md)与[联网固件](../firmware/esp32-linx/README.md)；水枪已另完成本机单次授权台架联调；音频、自主动作及其他执行器保持关闭。

## 官方资料核实

- [设备接入入口](https://linx.qiniu.com/docs/xrobot/platform/)提供 OTA 网关、WebSocket、MQTT 和配网文档。
- [OTA 网关](https://linx.qiniu.com/docs/xrobot/platform/OTA)：设备上报后按绑定状态获得激活信息或连接参数；绑定后重新上报取得 WebSocket 地址和令牌。HTTP 200 仍可能含业务错误，不能只检查状态码；未绑定的无效固件地址不能用于升级。
- [WebSocket](https://linx.qiniu.com/docs/xrobot/platform/websocket)：支持 WSS；握手包含设备／客户端标识、令牌和协议版本，随后交换 `hello`。控制消息为 JSON，音频为二进制；官方示例支持 Opus／PCM，音频参数需按服务端响应核对，不能把所有示例中的采样率混为固定值。
- [端侧 MCP](https://linx.qiniu.com/docs/xrobot/mcp/hardware-mcp)：平台是 MCP 客户端，设备是服务器；设备声明能力后处理 `initialize`、`tools/list`、`tools/call`，JSON-RPC 封装于基础传输消息中。

## 本项目拟定方案

首版采用 ESP32-S3 + Wi-Fi + WebSocket/WSS + 端侧 MCP，减少首次联调的传输分支。MQTT 保留为资料入口，当前不实现第二套传输。优先使用网关返回的受信任地址，验证 TLS 证书与主机名；若返回明文 WS，进入配置错误或受控联调状态，不静默降级携带凭据联网。

接入顺序：配网 → 上报设备信息 → 完成绑定 → 获取连接参数 → 安全握手及 `hello` → 音频测试 → MCP 能力发现 → 只读状态 → 有限动作联调。整个绑定和更新过程执行器保持禁止状态。

首轮使用按键开始语音，验证麦克风、编码、播放链路后再评估唤醒词及全双工。带载时须评估电机／风扇噪声和回声；主控已指定 ESP32-S3 N16R8，[板卡原理图与排针资料](../hardware/components/ESP32-S3-N16R8/README.md)已整理，实物版本及存储配置待核对，麦克风、功放与扬声器尚待选择。

已完成[接收边界与连接生命周期的离线模拟](../firmware/TRANSPORT.md)，覆盖分片、超时、重连与发送失败。connected／ready 是测试注入的本地门槛；该模拟不代表真实 TLS、hello、音频或账号绑定通过。2026-10-24 新增独立 ESP-IDF 状态／停止联网工程，实现 HTTPS 绑定网关、WSS、hello 及文本 MCP 路由；真实结果单独记录，音频仍未实现。

## 候选工具契约

以下是项目拟定的工具名和语义，**不是灵矽预置 API**；状态／停止已完成真实发现与调用；水枪仅由 0.2.0 单次授权台架开放，正式动作核心仍未开放。参数上限在实物台架验证后写入版本化配置；缺少限制值时执行器工具不可用。

F1 已实现独立[离线协议适配层](../firmware/PROTOCOL.md)：MCP 封装、初始化和工具发现、严格参数检查、请求 ID 去重、原响应缓存及类型化控制核心映射。状态／停止已复用于真实 WSS 接入并联调通过；动作的命令新鲜度证据源及实际存储仍待接入。16 槽原响应按 FIFO 淘汰，另以 32 KiB 启动期过滤器保留动作 RPC ID／稳定意图及旧版历史位；新只读／停止仅缓存响应，不增加永久占用，旧动作在淘汰／会话恢复后仍拒绝，状态查询和停止持续可用。过滤器可能误拒绝新动作，不能自动清除或换 ID 重试；客户端新意图 ID 需在持久化历史生命周期内保持唯一，兼容性与容量待真实流量验证，跨复位持久化接口与掉电模拟已完成，离线完整迁移已验证，真实后端及持久化分区切换另验收。

| 工具 | 作用与参数 | 本地约束 |
|---|---|---|
| `self.tank.get_status` | 返回已实现的状态、故障及能力 | 不虚构电量、液位或执行成功 |
| `self.tank.stop` | 无参数，取消全部普通动作 | 幂等、优先，不等待播放结束 |
| `self.tank.move` | `direction`: `forward`／`backward`／`left`／`right`；`speed_level`、`duration_ms` 为正十进制整数 | 本地使能；方向白名单；速度／时长有上限，到时停止 |
| `self.tank.water` | 正式契约为 `duration_ms`；当前台架另外要求本机签发的 `permit`，且 `duration_ms=5000` | 30 秒内有效的一次性授权，用后不能重试；5 秒软件期限、BOOT 提前停止，松开不恢复。该台架不替代正式动作核心；不能承诺精确喷水次数 |
| `self.tank.bubbles` | `duration_ms` | 限时供能，结束自动关闭；前置条件由本地状态决定 |

不暴露 GPIO、任意电压、无限运行或高压效果工具。不默认支持厘米／角度目标，待编码器、传动比例及打滑实测后再扩展。

## 错误和恢复

- JSON-RPC 请求按协议正确回复；未知工具、缺参、非法类型、负值／超大时长、未使能状态均拒绝。
- 接入层以会话和请求 ID 处理重复请求，驻留记录的重传返回原结果而不重复启动；淘汰后不恢复原结果，旧动作 ID 拒绝，只读可重算；新会话不接收旧队列。应用层过期判断须有可校验的时间依据或本地接收时限，不能假设平台自带 TTL。
- F1 在首次本地接收时保留连接代次、使能代次与时间，禁止停止前排队的命令在重新使能后执行。设备签发窗口及稳定意图 ID 已有[离线实现](../firmware/FRESHNESS.md)，将 RPC ID 与意图身份分开；真实认证、内容绑定与服务端重试映射尚未接入。不得在接收时制造新窗口或新意图，证据源缺失时动作保持关闭。
- 接收动作后立即在本地建立结束期限，断网不能延长动作。语音“停止”只是补充，物理停止必须独立有效。
- 执行器未结束时只报告“已接受／执行中”；完成、失败和被中止要区分，不让对话模型代替设备确认结果。
- OTA、异常复位及重新绑定期间禁止动作，升级失败保留可恢复状态；实际升级策略待选定固件框架后验证。
- Wi-Fi 密码、设备 token、绑定码不写入代码、日志或仓库；原型阶段默认不保存原始录音。

本次账号已完成设备绑定和状态／停止真实联调，首次额度不足在用户处理资源包后重试通过；计费和隐私仍以账号实际设置为准。音频效果、动作能力及完整故障恢复仍待联调；本次范围不代表整机接入验收完成。

## 0.2.0 单次喷水台架边界

用户授权的受限联调采用本机先创建固定 5000 ms 意图并生成随机一次性 permit，再经已认证 WSS 让灵矽返回对应工具调用。原正式协议核心仍为零动作能力；没有在收到云端消息后补造正式 proof 或清除持久化历史。新台架只接受当前本机意图，停止、到期、断线或复位不保留下一次授权。计时与 BOOT 由独立任务处理，网络不能延长期限。详见[工程说明](../firmware/esp32-linx/README.md)及[实测记录](linx-validation.md)。自动停止和 BOOT 带载观察已通过；自主动作、真实持久化和完整故障矩阵仍开放。
