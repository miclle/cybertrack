# ct78 新角色与 11 个工具：无实物语音回归

2026-11-01 完成 30 个预先固定场景、35 轮语音，全部正常结束。严格工具、参数与顺序匹配 **33/35 轮、28/30 场景**；发现一次明确时长错误和一次漏调停止却声称已停，**当前候选不满足上线条件**。本轮不修改固件或角色内容，不补跑替换失败，不替代原固定 80 条成绩。

输入是 macOS Tingting 合成普通话，经 16 kHz 单声道 Opus 发送到灵矽真实 STT／模型；所有工具回执来自冻结的 ct78 实际 MCP 分发器、回调和控制守卫。时钟、距离与 IO 为主机模拟，没有设备转发、麦克风拾音、扬声器播放、串口操作或执行器动作。点火与狂暴模式只验证参数和逻辑状态。[预先计划](evidence/ct78-voice-regression/plan.json) · [语料](evidence/ct78-voice-regression/cases.json) · [主机来源](evidence/ct78-voice-regression/host-manifest.json)

## 两条必须修复的失败

- **S01：明确时长被默认值覆盖。** 原话及识别均为“先左转一秒，再吹泡泡两秒”，模型提交两步 sequence，但第一步 `move_ms=880`，应为 `1000`；第二步泡泡 `2000` 正确。固件按传入参数执行并完成，因此设备拒绝门不能纠正这类合法但不符合原话的参数。
- **T04：无回执却宣称停止成功。** 原话正确识别为“停止”，没有任何工具调用，回复却为“动作都停下了，我在这儿等你。”该例主机初态为空闲，没有活动动作，也没有模拟输出残留；仍必须算漏调用和虚假确认。T01／T02 的活动序列及 T03 的活动行走均直接一次 stop，取消／关闭状态正确。R04 的第二轮停止也正确；不能用这些成功抵消 T04。

本轮没有原角色的同条件对照，不能断言两条失败由移除剧场引起，也不能用恢复原角色推定问题已经解决。

## 连续恢复的实际路径

| 场景 | 同一连接内的语音和回执 |
|---|---|
| R01 | 空闲“全速” → set_speed 返回 rejected；新语音“左转一秒” → move accepted，只有一次新启动 |
| R02 | 空闲“快一点” → adjust_speed 返回 rejected；新语音“吹泡泡一秒” → bubbles accepted，只有一次新启动 |
| R03 | “前进两秒，先别执行” → 无调用、零启动；新语音“现在前进一秒” → move accepted |
| R04 | 已有序列时“喷水一秒” → RPC 拒绝；新语音“停止” → stop ok、取消整单；再说“喷水一秒” → water accepted，旧序列后续泡泡未启动 |

拒绝后均没有自动重试、拆单补做或额外启动。R03 属于模型不调用后的新指令，不是设备拒绝后的恢复；与另外三组分别解释。每一轮等待实际 TTS stop 后才发送下一轮，未覆盖回复中抢话、多人交叉输入或失序网络。
