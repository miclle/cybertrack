# 模型工具轮播报中继：本地原型

针对[协议观测](tts-protocol-observation.md)没有取得可信最终回复阶段字段的现状，本轮把修复点移到模型返回与 TTS 之间，交付可运行的[本地中继](../../tools/lingxi-relay/README.md)。原型尚未采纳，没有创建灵矽模型、云服务或公网绑定，也没有改变默认设备直连路径。

## 已验证的行为

中继提供 `POST /v1/chat/completions`，客户端可取 JSON 或 SSE。上游先返回完整的非流式结果，工具轮普通文字置空，完整工具调用的 ID、顺序、名称与参数字符串保留；正常无工具回复原样保留。消息、工具定义、工具选择和工具结果历史不改写。单个客户端请求只产生一次上游请求，没有自动重试。

17 项本地测试通过，包含两个真实 HTTP 服务之间的工具／结果两轮闭环，以及 SSE、完成前不发响应头或文字、最终限幅／拒绝／查询／澄清、完整参数字符串、畸形和截断、认证、拒绝重定向与上游失败。所有上游回复是明确标注的测试夹具，未调用真实模型或灵矽，没有传感器、音频或执行器 IO。

## 仍不能采纳的原因

- **工具之后的最终分析文字仍保留。** 它与正常最终回答同为 `content`，此原型没有通用语义判断，不能称 C005／C008 已修复。
- **工具轮的必要限制也可能被删除。** 本地反例中，将“喷水单次最多三十秒”放入工具轮，就会置空。必须在真实工具回执后的最终回复验证限制没有遗漏；设备边界轨迹不足以确定原提示在上游属于哪一轮。
- **整轮缓冲会增加等待。** 首个工具、语音停止、首句和完成时间还未在真实模型链路测量。本地 BOOT 和固件截止不经中继，但这不等于语音停止无延迟。
- **非空结构化推理模式不支持。** 需要推理历史的工具模式必须完整实现历史回送；当前明确报错，避免删除后继续发送工具。
- **真实连接条件尚未配置。** 需要已有模型服务配置与灵矽可访问的正式 HTTPS 托管入口；本地回环地址无法直接给云端使用。没有部署、费用或账号权限变更。

上述反例保留为未采纳依据；不以本地测试通过抵消这些产品门槛。当前固件仍 ct72，最近记录部署仍 ct45，平台仍为前轮保存恢复的原配置。原固定集的工具、播报、实际设备与亲子退出条件保持。

## 接口依据与下一步

[灵矽自定义 LLM 指引](https://linx.qiniu.com/docs/xrobot/guide/third-app)提供模型服务接入位置；[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)区分完整工具轮、普通回复及流格式。本原型按这些接口形态进行本地验证，不能据此归因灵矽内置服务的内部实现。

取得真实配置后，先验证消息／工具／请求参数，再执行原 80／8 回归，分列语义、TTS 文字、音频与时延；必须验证限幅、拒绝、明确停止和断线。最终回复中的过程分析、必要提示只存在于工具轮的情况、思考工具历史及真正的上游流式时延仍需继续实现或验证。
