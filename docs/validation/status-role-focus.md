# 按问题回答运动状态

当前角色在灵矽平台保存后重新打开，完整 5917 字符与仓库一致。原 ct45 面包板重启后回到待机，八次回执均为零启动、所有逻辑输出关闭。方向、时间和长按的回复使用隔离文本会话评测。每条原话新开会话，捕获程序接收模型的实际调用，设备输出由主机代替。[角色同步与启动记录](../../firmware/esp32-audio/role-query-focus-ct45.json)

## 方向和时长

旧角色在“走的是哪个方向？”三次查询中都附加了倒计时。新角色在相同问题、相同 ct49 工具和受控时钟流程下三次都只说“刚查时在往前走”。两批在角色更新前后分别采集，用例、捕获器和工具描述哈希相同。主机可执行文件哈希不同，各次回执与回复逐项核对。时长问题的三次查询分别还剩 2774、1470 和 2155 ms，新回复以查询时刻为准，分别报约 3、1.5 和 2 秒。询问听完时是否还在走的三次都说明无法保证；已过期的三次都说明行走已结束。十二次均只调用一次状态查询。[旧角色对照](lingxi-ct49.md) · [逐例回复与原始轨迹](evidence/status-role-focus/review.json)

再用已部署 ct45 的工具描述，换八条带不同状态的原话。四个运动方向全部答对，前进、左转和右转只答方向，后退多报了 70% 速度。只问速度得到正确的 80%，但又说了正在后退。同时问方向和时间时答了左转和约 3 秒，空闲时正确回答未移动。八次均只查状态。[用例及静态快照](status-focus-cases.json) · [捕获轨迹](evidence/status-role-focus/ct45-focus.json.gz)

## 网页长按与定时动作

网页长按由短租期保护。只要持续收到有效续租，动作可以超过当前剩余租期。原话 D107 暴露了模型把续租时间解释为停车倒计时的问题，但该静态夹具使用了 700 ms，超过固件的 600 ms 租期。保留这次捕获，另用实际 ct45 的控制守卫和回执序列化生成下面三种状态。

| 回执 | 取得方式 | 模型要区分的含义 |
|---|---|---|
| H201 | 网页开始长按，在第 200 ms 查询；hold ID 为 1，剩余 400 ms | 松手、停止或未续租会结束，查询时无法知道整次运动还要多久 |
| H202 | 语音定时前进 4 秒，在第 3600 ms 查询；hold ID 为 0，剩余 400 ms | 查询时预定还剩约 0.4 秒 |
| H203 | 同一长按到第 600 ms 未续租，再次查询 | 查询时没有行走；单凭上一次接受回执不能向用户断定刚才为何停下 |

三条用相同原话、独立会话和冻结的回执。控制守卫、短租期及逻辑输出按主机时钟生成，设备 I/O 使用测试替身。主机生成的完整回执保存在[长按对照集](status-hold-cases.json)。在当前源码重放长按的入口如下；要复核 ct45，使用其版本的控制守卫及 `Reply` 源码，不能把 ct49 的新增状态解释字段带入历史版本。

```sh
python3 firmware/esp32-audio/tests/run_mcp_tests.py --source build/xiaozhi-ct49-src
printf '%s\n' '[{"name":"self.tank.get_status","arguments":{},"elapsed_ms":200},{"name":"self.tank.get_status","arguments":{},"elapsed_ms":600}]' | build/audio-host/receipt_replay web_forward_hold
```

## 5917 字符角色的完整回归

ct45 工具下，80 条均结束，79 条的工具与参数严格匹配。V051“取消序列”请求了取消草稿，遗漏立即全停；禁止动作集没有误调用。停止门槛逐条检查八个停止表达，本轮未通过。45 条要求成功静默的会话都返回了平台 TTS。编排 6/8，C003 和 C004 改稿前没有先读草稿版本；本轮未出现直接启动工具。[动作评分](evidence/status-role-focus/ct45-voice-score.json) · [动作轨迹](evidence/status-role-focus/ct45-voice.json.gz) · [编排评分](evidence/status-role-focus/ct45-compose-score.json) · [编排轨迹](evidence/status-role-focus/ct45-compose.json.gz)

在这版角色上，H201 和 H202 都报告约 0.4 秒后结束。H201 错把续租窗口当成运动总时长，H202 的定时动作解释正确；H203 回答采样时没有动作。另让“取消序列”和“取消正在执行的表演”面对一个移动通道及一份独立草稿。前者试图取消草稿，后者先取消草稿再停止，均未立即全停。明确取消未开始的草稿则按版本处理；否定取消只查状态，回复错误地称设备待命。[长按对照](evidence/status-role-focus/5917-hold.json.gz) · [取消用例](status-cancel-cases.json) · [取消轨迹](evidence/status-role-focus/5917-cancel.json.gz)
