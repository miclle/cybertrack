# ct48 否定、停止与剧场动作顺序

ct46 曾把“不要前进”解释成全停，也曾将“往后走两秒，同时吹泡泡一秒”保存成先后两步。ct48 在灵矽的停止工具说明中区分否定和明确停止，在编排工具中说明同步动作共用一步。手机预览直接从载入的设备草稿计算各步的起止关系，家长可在确认前比对原意。[历史失败](lingxi-ct46.md) · [候选构建与浏览器验证](../../firmware/esp32-audio/verification-ct48.json)

使用相同的 5998 字符角色，从候选构建树导出工具描述。每轮按[八条原话](ct48-intent-cases.json)新建八个灵矽 WSS 会话，连续三轮，共 24 条，均正常结束。只发送原话，设备为空闲、无有效草稿的内存夹具。捕获器使用 ct47 的回执格式，设备固件没有刷写。

| 原话意图 | 三轮结果 |
|---|---|
| 否定前进，两种表达 | 6/6 无工具调用 |
| 明确停止，含“别再往前走了，马上停下” | 6/6 直接调用一次全停 |
| 后退与泡泡、左转与泡泡同时开始 | 6/6 先查版本，再保存一步。两路时长分别匹配 |
| 相同动作按先后进行，含泡泡先开始 | 6/6 先查版本，再保存两步，方向、顺序和时长匹配 |

工具名、顺序及参数按现有评分器的 `canonical` 比较。每个编排案例另与 `draft_saved` 回执中的步骤数组逐项核对，省略的速度按固件默认值 100% 处理。12 份草稿均保存为预期结构，未请求执行。第一轮“不要前进”仍播报了判断意图的内部说明。这里只评价这八条原话；ct48 未重跑固定 80 条，也未采集真人语音或扬声器输出。[逐例评分](evidence/ct48-intent/summary.json) · [原始轨迹](evidence/ct48-intent/)

复现时，按[隔离联调步骤](lingxi-capture.md)从 `build/xiaozhi-ct48-src` 导出 schema，使用 `--ct47 --raw-text --corpus docs/validation/ct48-intent-cases.json`，每轮使用新的输出文件。预览测试在真实 Chromium 中拦截全部设备请求，分别载入同动与分步草稿，检查顺序、预计时长、确认状态及窄屏布局。
