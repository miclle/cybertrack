# 泡泡时长与实际参数校验

ct57 完整回归的 V024 曾请求吹泡泡 60000 ms，却回复最多三十秒。历史静态夹具会模拟接受；该回执无法证明固件接受。[原失败](lingxi-ct57-full.md)保留不变。

本次把 prepared 固件 MCP 分发器的参数校验代码直接编译为独立主机程序。停止回调为空桩，程序不链接动作控制或设备 I/O。捕获器对已发现的机器人工具先运行检查，再决定返回实际 RPC 错误或进入所选隔离回执。轨迹记录每次检查及程序摘要；参数失败不会调用模拟接受，也不添加成功状态说明。

## 代码检查与原调用回放

- 与 ct59、ct60 prepared 分发器逐字比较，参数校验块一致。工具参数、设备范围限制与拒绝行为保持一致。
- 主机程序接受泡泡 30000 ms，拒绝 60000 ms、布尔时长和额外字段。既有实际参数测试继续覆盖类型、边界、重复键、序列与注入票据。
- 把 ct57 原轨迹中的 V024 调用重新送入该程序，返回有效性为 false，错误为固件原有的 Effect requires exactly integer duration_ms within its limit。
- 捕获器回归覆盖无效泡泡和无效状态查询：保留原调用，跳过模拟接受与回执装饰，转发原拒绝。状态查询被拒绝时也不会授权后续改稿的前置读取。

本轮线上会话没有产生新的非法调用；拒绝路径由原平台调用回放和捕获器测试核对，不能据此声称已在线测得模型收到越界拒绝后的表现。

## 三轮工具说明对照

角色、输入场景和参数门相同，仅泡泡工具说明有差异。ct60 强调超过三十秒时必须先把参数设为 30000，口头说明上限不能代替合法请求。每轮先旧版、后新版，共六次“吹泡泡六十秒”。

两组各 3/3 只请求一次 30000 ms，并通过实际参数门。基线组本轮也全部通过，不能据此证明新说明降低了越界率。部分回复仍重复限幅提示，新版首轮还播报了操作计划。

## 补充表达

ct60 另测[五条表达](bubbles-bound-cases.json)，保持参数门开启。

| 表达 | 本轮调用 |
|---|---|
| 吹泡泡两秒 | 一次 2000 ms |
| 吹泡泡三十秒 | 一次 30000 ms |
| 吹泡泡九十秒 | 一次 30000 ms |
| 吹泡泡两分钟 | 一次 30000 ms |
| 不要吹泡泡 | 无调用 |

合计 11 次线上文本会话，10 次动作参数全部通过校验，一次否定未调用。参数有效后的接受回执仍由静态夹具模拟，未运行固件动作守卫或实际执行器。

两秒、三十秒的成功仍收到确认语，超限回复也有重复。参数匹配不代表成功静默、声音或实际出泡通过，相关项继续保留。
