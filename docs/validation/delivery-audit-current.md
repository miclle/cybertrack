# 产品改进交付核对

核对日期：2026-11-01。对应 [I01–I13 原计划](../improvement-plan.md)；原完成条件保持不变。当前源码候选为 **ct74**，最近记录的设备应用为 **ct73**，二者由[版本真源](../../firmware/current.json)分别维护。总目标尚未完成。

## 当前结论

- 当前 ct74 候选（提交 `fa88ec2`）的[十八组软件检查](evidence/ct74-dialogue-beeps/software-checks.json)全部通过，含 124 项 Python 测试；检查发生于提交前，以记录中的源码哈希对应最终实现。普通提示与语音共存的原生检查通过，尚未部署或完成新版本听感验收。此前 `1698f28` 的[软件检查](evidence/delivery-audit-20261101/software-checks.json)作为历史记录保留。
- 最新一次原 80／8 全集的[合成普通话 → 实际 STT → 固件主机回归](full-stt-ct71.md)为严格工具 **77/80、编排 6/8**，八条明确停止正确；V064 的模型禁止调用仍计失败，即使设备拒绝。它不是真人拾音或机械停止验收。
- ct73 [四路组合播放匹配](four-lane-feedback.md)十二条定向实际 STT 为 **10/12**，五条匹配组合新增抑制 277 个确认音频包；F004 共享时长、F010 识别／漏调用和 F011 过程播报仍需处理。定向结果不替换原固定集成绩，包级抑制不等于扬声器听感通过。
- I11 模型辅助设计已在约定范围内完成：正式 FCStd 与既有宿主消息验收的来源哈希一致，三张历史截图文件均存在且哈希匹配。其余项目仍有模型、真人、实机或真实工程观察缺口。

2026-11-01 现场阶段更新：[ct73](../../firmware/esp32-audio/startup-ct73.json)已仅应用部署，配置／非应用区校验、两次启动联网及二十条零动作状态回读通过。软件和平台成绩仍按各自采集版本解释；随后新增的架空功能观察见下文，不等于地面负载、量化停止或完整真人语音验收。

现场首项结果补充：[ct73 架空行走](ct73-deployment.md#首项现场结果未通过)请求被接受，但用户明确反馈两侧履带都没转；用户随后反馈手机网页控制正常，用户确认手机为 100%；同样 500 ms 请求在 100% 下复核两侧转动并停止，60% 未转原因仍未定。电机或供电故障尚无依据。该诊断未通过，不关闭 I04，也不增加正式物理停止覆盖。

用户随后确认 BOOT 实际立即停止且松开未恢复；首条真人左转并停止、动作无播报获现场确认。三条后台问句已回查，保留状态未先查询等问题；测距滴声伴随卡顿引出的 [ct74 候选](dialogue-range-beeps.md)尚未部署。

## 已核对的外部条件

[本次观测](evidence/delivery-audit-20261101/observations.json)保留可复核的计数和哈希。

1. **现场配合已恢复，完整记录仍缺。** 家庭、故障、供电、成本、维护循环和维护计时的采集数组均为空，停止试验的 profiles／trials 也为空。此前分项台架和用户反馈仍有效，但不覆盖当前整机与新电池的指定验收。2026-11-01 用户提供设备地址并确认主控独立供电；已授权并完成 [ct73 部署与无动作检查](ct73-deployment.md)，进入实际动作与停止采集。
2. **平台可见模型没有新的已配置候选。** 本轮只读核对账号选择器，仍为 DeepSeek、豆包、通义千问极速版三项，自定义模型列表为空；没有保存或更改配置。[可见状态](evidence/delivery-audit-20261101/platform-availability.json)只证明此账号界面，不是供应商或后台请求身份认证。[现有模型／参数对照](model-parameters.md)已有失败记录，替代方案未采纳，原 5991 字符角色与原参数保持。
3. **播报出口还缺上游依据。** [协议观察](tts-protocol-observation.md)未获得可靠的最终回复阶段字段或上游错误记录，`action=thinking` 也出现在必要提示中，不能直接屏蔽。[工具轮中继原型](llm-tool-round-relay.md)尚未采纳：最终分析仍可能透传，工具轮必要限制可能丢失，整轮缓冲时延未测；真实模型和 HTTPS 接入未配置。
4. **工程效率观察仍缺。** 37 条技术记录已闭合，但完整效率样本为 0/5。ct71 全语音记录的 finish 是本轮补做的行政绑定；记录起止间隔不等于实际工作、人工用时或模型等待，不据此计算效率提升。

## 后续执行顺序与退出依据

- **模型／平台：** 取得可区分最终回复与过程文字的上游事件依据，或实际可用的不同模型接入条件后，对现存失败逐条对照，再重跑原 80／8 固定集。保持失败计分，不扩大词语纠错或静默匹配来掩盖模型错误。本地中继只有必要提示、最终回复、工具闭环和时延均验证后才可考虑采纳。
- **设备／现场：** 在部署条件及授权明确后核验新候选；依次采集首次连接与停止、三种收音条件、有效版本表演、断线与恢复、组合负载／温升／续航和维护基线。网页静默断线按现有两秒租期检测，租期内可能进入下一步；长按通道 600 ms 租期另列，均不能当作机械停止时间。
- **亲子与工程：** 由真实观察形成五组家庭记录和五次完整修改效率样本，再复算原定位、上手、重玩及效率指标。涉及电源与保护的定值须依据实际 SKU、针序和测量，不能用软件检查补足。

本表只维护当前结论。早期部署与桌面状态见[首次核对](delivery-audit-20261031.md)；ct57–ct73 的累计核对文本保留在[本次整理前的固定提交](https://github.com/miclle/cybertrack/blob/1698f28c47e07c7affcec5255682e9face6e4297/docs/validation/delivery-audit-current.md)，各专题原始证据继续保留。参考包的 98 项离线测试和评分重算只支撑包内材料复现，完整控制重放、真人和实物验收分别进行。
