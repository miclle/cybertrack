# ct46 语音候选隔离联调

固件候选冻结于 `a5fe8f4`，角色沿用 ct45 的 5998 字符版本。每条原话新建灵矽 WSS 会话，模型可以发现设备工具，调用只进入内存夹具。夹具用候选固件的同一状态解释函数生成 `status_facts`，模拟草稿与版本回执。最近部署记录仍是 ct45。这些结果覆盖平台文本、合成状态和主机播放逻辑，真人语音、扬声器及执行器另验。[固件构建](../../firmware/esp32-audio/verification-ct46.json) · [输入与回执协议](lingxi-capture.md)

## 真实远端语音与本地播放

ct45 的四例时序探针显示，平台在工具回执后仍会返回确认语音。ct46 利用设备已识别的原话、匹配参数和成功回执来决定是否将远端音频送入解码队列。用三轮未参与开发的原话重放平台事件，结果如下。

| 原话或场景 | 三轮观察 |
|---|---|
| 前进、全部停止、吹泡泡 | 三轮各三条，9/9 在主机重放时抑制首个远端音频包，平台均生成了回复。此次覆盖默认参数的短指令。 |
| 让水枪喷四十秒 | 3/3 只请求 30000 ms 并保留上限说明的首包；三轮均出现重复说明。 |
| 排练第二幕加喷水 | 3/3 没有写草稿或调用动作，但全部追问要加在哪里、喷多久。用户可能以为此功能可用，拒绝话术 0/3 通过。 |
| 泡泡短一些，还没想好几秒 | 3/3 保留原稿并询问时长；第二轮播报了内部推理。 |
| 拿走障碍后会接着走吗 | 3/3 表达不会自动续走，需要新指令。 |
| 上条指令为什么没接住 | 三轮均查状态；第一轮猜测占用或冷却，第二轮把当前快照概括为“一切正常”，第三轮说明具体原因未细分。 |

主机测试另覆盖参数不匹配、失败回执、早于回执的语音、多工具及跨轮迟到回执。本地测距提示音走独立的优先播放路径。固定 80 条带评测前缀的输入和无前缀的短指令分开统计。[新原话集](ct46-transfer-cases.json) · [播放回归](../../firmware/esp32-audio/tests/voice_feedback_test.cc)

三轮原始输入、工具回执、文本与事件时序分别见[第一轮](evidence/ct46-repeats/1-transfer.json.gz)、[第二轮](evidence/ct46-repeats/2-transfer.json.gz)和[第三轮](evidence/ct46-repeats/3-transfer.json.gz)。压缩文件含文本及音频字节计数，未保存音频内容。

## 同一候选的三轮回归

三轮各 112 条，共 336 条都收到正常完成信号。固定动作和编排集带上下文，状态、旧留出集与新迁移集使用原话。每轮分别计分，未因额外查询无害而放宽旧评分器。ct45 上一轮动作 77/80、编排 5/8，其中只读解释 4/8。服务端没有返回模型签名版本，模型名取自平台可见配置。

| 独立轮次 | 固定动作严格匹配 | 固定编排严格匹配 | 禁止用例中的工具违规 | 45 条应静默动作中的云端静默 |
|---|---:|---:|---|---:|
| 第一轮 | 79/80 | 7/8 | 无 | 0/45 |
| 第二轮 | 77/80 | 8/8 | V061 请求全停 | 0/45 |
| 第三轮 | 79/80 | 5/8 | 无 | 0/45 |

- **动作门槛。** 三轮准确率均超过 95%。第二轮因“不要前进”额外调用全停，未通过包含零违规要求的完整门槛。第一、三轮均是“全速”多一次只读查询。第二轮还出现超限放电只说明上限、未提交限幅调用，以及距离指令多一次查询。全部调用均在夹具内处理。
- **草稿保护。** 第三轮把“不要编排表演”误解成取消，未读版本即提交 `cancel`。候选夹具返回 `draft_changed`，模型承认没有取消成功。第三轮 C007、C008 的额外查询也计作严格匹配失败。三轮共 24 个固定编排会话均无直接执行调用。
- **状态解释。** 24 个状态会话均只查状态。“解除保护仍需新指令”和“表演正在步骤间等待”各 3/3 说对。驱动故障题第一、三轮建议重启；第二轮 D008 还把历史“接受”说成动作“完成”。保留设备事实后仍需核对模型的实际回复。
- **旧留出集。** H002 和 H003 三轮都没有提交不支持的草稿。H001 第一、三轮将后退与泡泡保存在同一步，第二轮错存为先后两步。口头确认未触发执行，含糊时长未写稿，部分回复仍播报英文或内部推理。旧留出集已用于发现问题，本轮只将新增的 P001–P008 作为冻结后的新表达。
- **首包与整轮。** 原话短指令的主机回放结果、固定上下文的云端静默率和人在现场听到的声音是三种不同的观察。本轮没有现场听测。

每次会话的原始调用、回执、回复和时序收录于[压缩轨迹目录](evidence/ct46-repeats/)。[机器汇总](evidence/ct46-repeats/summary.json)列出每轮运行 ID、输入轨迹 SHA-256、错项和首包判定。按[重放说明](lingxi-capture.md)编译主机工具后，可直接对压缩轨迹重算。

```sh
python3 scripts/report_lingxi_repeats.py docs/validation/evidence/ct46-repeats
```
