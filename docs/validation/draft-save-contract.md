# 草稿查询、提交和保存回执

ct57 完整回归的 C001 只调用了状态查询，却回复“草稿已保存”。[原始失败记录](lingxi-ct57-full.md)保持不变。ct58 强化编排工具说明，要求本次实际取得保存／取消回执后才能说明完成。候选仍需按实际调用和最终草稿核验。

两版导出的十二个工具名称和参数一致，仅 compose 说明有差异。线上角色仍为已回读的 5991 字符版本，模型配置为 deepseek-v4-flash。控制守卫沿用已实现的读版本限制，角色提示不能代替它。

## 实际固件主机回执

使用用户原话建立独立文本会话，不添加场景前缀。新建从无草稿、版本 0 开始；修改与取消从两步、版本 7 开始。两组均由同一个固定的 ct58 主机程序按实际调用时间应答，没有连接执行器。

每组每种请求独立运行三次。新建应生成左转 880 ms 再吹泡泡一秒，修改应只把第二步泡泡改成两秒，取消后应无活动草稿。分别检查操作回执、最终版本和步骤，以及启动计数、全部逻辑输出和平台回复。

现场听感、有效版本表演和家庭体验仍待验。这里的新建原话与固定集相同，输入方式、设备回执与固定集不同，应独立解读。

## 三轮结果

24 次会话都正常结束。十八次主机回读均为零启动、全部输出关闭。

| 输入与回执 | ct57 工具说明 | ct58 工具说明 |
|---|---|---|
| 原话文本，真实主机回执；新建／修改／取消各三次 | 8/9 调用及参数严格匹配；一次新建把默认左转写成 1000 ms。实际保存／取消均有回执 | 9/9 严格匹配，最终草稿符合预期，修改保留第一步，取消清空草稿 |
| 完整集相同的 C001 场景前缀，静态夹具；各三次 | 1/3 实际保存，其余两次只查询却声称已保存 | 2/3 实际保存，第二轮仍只查询却声称已保存 |

因此，仅强化工具说明尚未解决虚假完成。新版在原话主机验证中通过，但完整集输入仍重现失败，原 C001 失败项继续开放。旧说明的原话样本同时出现默认时长错误，新版亦有提前说明操作计划与英文旁白，回复语义不因调用正确自动通过。

[全部调用、回复与最终草稿](evidence/draft-save-contract/review.json)保存两类输入的独立记录，同目录保留 24 份原始压缩轨迹。工具说明组的顺序固定为先旧版后新版，本轮样本量和顺序不足以证明长期稳定性。

下一步核对状态回执能否明确表达“当前没有已保存草稿”和“查询不产生本次保存确认”，并继续以原输入复测。只有实际保存回执和原生最终草稿一致，才能通过该完成条件。既有守卫对过期或漏查版本的拒绝已由主机测试覆盖，仍不允许从上下文中的版本代替本轮读取。

后续[ct59 状态回执对照](draft-state-facts.md)已完成 14 次。静态对照两组均 3/3，实际主机编排本轮 8/8；单轮通过仍不足以关闭虚假完成稳定性问题。
