# 草稿状态查询与保存确认

ct58 的[工具说明对照](draft-save-contract.md)仍出现只查询就声称已保存。ct59 在状态查询中增加 `draft_status_facts`，说明当前有无已保存草稿，以及该查询没有保存、修改或取消草稿。只有实际 compose 回执能确认操作完成。

该字段取自控制锁内采样的草稿副本，仅随 get_status 返回。保存回执不包含“查询未保存”的说明。十二个工具定义和 5991 字符角色与 ct58 完全相同；守卫继续要求新鲜版本、家长网页确认和零自动启动。

## 固定其他条件的六次对照

使用完整集 C001 的相同场景前缀文本与静态夹具。两组都用 ct58 导出的工具定义，每轮先基线后新增说明，共三轮。新增说明由固件同一函数生成，轨迹绑定头文件和主机适配程序摘要。

两组各 3/3 实际调用了查询和保存，参数符合原用例。新增说明组没有虚假保存，但基线组本轮也通过，因此不能据本轮断言该字段降低了失败率。此前未提交却声称保存的失败继续保留，长期稳定性仍待验证。部分回复仍有操作旁白。

## 实际 ct59 主机回执的八条编排

使用与固定集相同的八条输入和场景前缀，工具定义从 ct59 导出。各例独立建立会话，C001 从空草稿开始，其他例从两步、版本 7 开始。状态、保存及取消由实际固件主机程序按真实请求时间应答。本组没有使用实验字段转换。

| 项目 | 本轮结果 |
|---|---|
| 工具、参数与顺序匹配 | 8/8 |
| 新建 | 实际保存版本 1，左转 880 ms 后吹泡泡 1000 ms |
| 修改第二步／删除第一步 | 各返回 draft_saved；最终步骤与请求一致，非目标步骤保留 |
| 取消 | 实际查询后取消，最终无活动草稿 |
| 喷水／点火草稿、口头开始 | 未调用动作工具，未改稿 |
| “第二步短一点” | 只问具体秒数，没有查询、编辑或动作 |
| 主机终态 | 八例均零启动、所有逻辑输出关闭 |

ct57 的静态夹具完整编排为 5/8，此次实际主机为 8/8。回执来源和采样轮次均有变化，这些成绩分别保留，不能只归因于新增文字。当前测试没有验证用户新表达的长期表现。

删除步骤时仍播报操作计划，取消时重复了确认语。此次保存与取消都有对应回执，语音质量还需收敛。最近记录的板上应用仍为 ct45；本组没有连接执行器、麦克风或扬声器。
