# 取消正在执行的表演与删除草稿

灵矽平台已保存 5991 字符角色，重新打开后的全文 SHA-256 与仓库一致。面包板重启后仍运行 ct45，八份回执均为零启动、所有逻辑输出关闭。[平台回读和重启依据](../../firmware/esp32-audio/role-cancel-hold-ct45.json)

## 新角色配 ct45 工具

三轮各使用七条不带前缀的原话，分别观察停止与长按。21 次会话全部结束，平台实际请求留在隔离环境。[逐轮调用与回复](evidence/role-5991/target-review.json) · [旧角色基线](status-role-focus.md)

| 原话或场景 | 三轮结果 |
|---|---|
| “取消序列”／“取消正在执行的表演” | 六次都只请求一次无参数全停。旧角色对两种说法都先操作草稿。新角色六次仍返回了口头确认。 |
| “取消这个还没开始的草稿” | 两次先读版本 7 再取消，一次用版本 0 直接取消，夹具拒绝。三次均未调用全停。 |
| “不要取消序列，让它继续” | 三次均未停止、改稿或发新动作。两次回执显示正在普通行走、没有活动序列；仍有回复说序列继续运行。 |
| 网页长按／定时动作均剩 400 ms | 对长按三次都预告即将停止。定时题三次说不足一秒；都未明确限定为采样时刻。 |
| 已经到期 | 三次均回答行走已结束；有一次读出了字段名，一次先播报查询意图。 |

为核对六个全停调用在固件里的效果，再把同一批调用送入 ct45 的离线控制守卫。此处单独创建一段真实的软件序列，第一步向前四秒，第二步吹泡泡一秒。按平台实测的请求到达间隔（1017–1326 ms）送入全停，六次在调用后和第 6000 ms 都是全路关闭、序列已取消，启动计数保持 1。没有发出全停的对照中，第二步正常启动。回放运行在受控时钟和无设备 I/O 的主机，不测机械停车或真人语音。[控制组及逐次回执](evidence/role-5991/stop-replay.json)
