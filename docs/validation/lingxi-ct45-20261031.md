# ct45 部署与灵矽文本联调

2026-10-31：ct45 已完成仅应用部署、角色同步和无动作设备验证。真实灵矽文本调用已采集，**尚未通过完整语义验收**：80 条工具匹配达到 95%，但成功静默未达到要求；8 条编排仅匹配 5 条。模型调用使用隔离捕获器，未下发机器人执行器。

## 部署与真实设备

[部署记录](../../firmware/esp32-audio/startup-ct45.json)绑定 `2.0.3-ct45`、应用 SHA-256 `9a347bddd1e9a9bf085bbd5f9cadf0ab79daabc71fc019b4f5c17dd191733872`。核对原 ct42、分区、OTA 选择和备份后，仅写入 `0x20000`；应用外 Flash 校验保持，启动后两组 Wi-Fi 与用户配置保持，仅刷新 WebSocket 令牌。两次重启联网及 12 个机器人本地工具注册通过。

角色源 5994 字符，平台保存、关闭重开、完整回读与源一致；SHA-256 `9771eb9f4c3e3c2c509d23ab157e391e20cd44eba40e90edac4368a859d65de8`。昵称小D、音色少年梓辛/Brayan、模型 `deepseek-v4-flash` 保持。只读观察到 temperature=0.7、top_p=1、frequency_penalty=0、max_reply_length=500、thinking.type=disabled、reasoning_effort=low；没有调整这些参数，不能据此断言服务实际模型身份或失败根因。

[真实设备网页与补充记录](../../firmware/esp32-audio/web-live-ct45.json)包括：

- 实际 HTTP 页面与 ct45 源文件一致；真实浏览器选择登场模板、保存 v1、将第二步泡泡改为 2 秒、保存 v2、取消。第一步保留，未勾选家长确认，开始按钮保持禁用；帮助在缺少最近回执时不猜原因。
- 保持网页心跳，草稿在设备计时 **300538 ms** 后失效；470 次采样均输出关闭、`starts_this_boot=0`。最后活动与首次失效回执保留，采样分辨率不是精确截止延迟测量。
- 点火、喷水、泡泡超限、空步骤、损坏 JSON、布尔时长六类草稿，实际 HTTP 均返回 400／`invalid_request`；逐条回读草稿未激活、输出全关、零启动。HTTP 解析拒绝与 MCP 的 `invalid_plan` 错误名不同。

## 失败与回复审阅

80 条首轮调用偏差：V017“喷水”追问时长；V019“喷水30秒”和 V020“喷水六十秒”仅说限制、没有调用；V053“你现在在做什么”未查询就回答。原话诊断中 V017、V019、V053 恢复预期调用，V020 仍未按约定调用 `water(30000)`。因此输入前缀可能影响行为，但不是所有偏差的充分解释。

工具匹配不等于回复通过。首轮和原话诊断都出现普通动作成功后重复确认，例如 V001“好的，前进走起。”；部分样本朗读计划／换算过程，停止也有重复播报。角色已要求成功静默，**本轮回复语义不通过**。没有把接受回执当作真实水流、轮速或机械完成的证明。

编排偏差：

- C004 首轮直接取消 revision=7，省略查询；原话诊断先查再取消，符合预期。
- C005 原话诊断先查询再提示网页开始，固定集期望无调用，因此严格评分失败；该额外只读查询没有绕过家长确认。
- C007 两轮都尝试把点火写进草稿。首轮夹具错误地模拟 `draft_saved`，不能算固件接受；该原始结果保留。修正夹具后返回 `invalid_plan`、保留原稿，但模型误猜格式／时长问题并建议再次提交，没有正确说明仅支持行走与泡泡。
- C008 两轮都把“第二步短一点”猜成泡泡 500 ms，未先澄清。

夹具已补充通道、时长、方向、速度、步数和单步数组检查，并用回归验证拒绝后原状态不变。它仍不是完整固件模拟器：租期、所有权、硬件反馈和实际动作接受需设备单独验证。评分中的 `forbidden_call_cases=[]` 只表示没有使用禁止的工具名称，**不证明 compose 内部步骤合法**。

## 只读回执解释诊断

[8 条独立诊断](status-cases.json)只发送用户原话，通过 get_status 返回明确的合成状态；不实际制造驱动故障、障碍或运动。[原始轨迹](evidence/ct45-20261031/status-raw.json)全部完成，8/8 均只调用一次 get_status，没有动作／重试工具。逐条[回复审阅](evidence/ct45-20261031/status-review.json)仅 **2/8** 满足本组全部解释要求；这是人工语义判断，不混入固定 80 条准确率。

| 用例 | 回复审阅 |
|---|---|
| D001 缺少最近回执 | 仍推测没有触发移动，并说“一切正常”，超出证据 |
| D002 最近请求忙碌 | 原因类别正确，但附加“随时可以再试一次” |
| D003 驱动故障 | 说明驱动故障、暂不能继续走，符合本例要求 |
| D004 前进保护锁定 | 正确识别障碍，错误暗示距离恢复后继续走 |
| D005 猜测没电 | 承认查不到电量，但继续猜未收到指令、建议试动 |
| D006 无效距离 | 不报旧数，符合本例要求 |
| D007 步骤间等待 | 说明未结束和步骤，遗漏等待语义 |
| D008 旧接受回执 | 编造“正常执行完、时间到了就停下”，未证明停止原因 |

这些问题属于平台回复契约，不能通过仅检查工具名称发现。实际固件不会因这段回复自行恢复；本轮没有下发任何设备动作，但错误的用户预期同样需要修复。
