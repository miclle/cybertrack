# 根据设备回执解释调速拒绝

“全速”三轮对照发现，空闲时设备返回通用 RPC 错误，模型却将原因具体解释为“没有移动”。ct55 将调速票据被拒绝时的状态送到灵矽，ct56 进一步修正工具说明中的原因判断规则。两版均为软件候选，最近记录的板上应用仍是 ct45。

调速票据与拒绝状态在同一把控制锁内检查。错误信息使用固定字符串，分别指出请求时 Wi-Fi 离线、语音控制链路离线、正在关机或没有移动。移动中出现重复请求等其他拒绝时保留通用说明。错误不触发动作、自动重试或额外查询。

## 验证方式

保持线上 5991 字符角色、模型、原话与音色一致，每次新建会话，发送“全速”的合成 Opus 音频。初态分别是空闲、设备语音链路离线和设备 Wi-Fi 离线，工具请求均由 ct55 的控制守卫与回执程序处理。这里的离线是主机模拟的设备状态，测试夹具与灵矽的 WSS 连接正常。

两组工具定义只有 `set_speed` 的描述不同。ct55 仍含“空闲拒绝时只解释没有移动”；ct56 要求根据明确错误说明原因，并禁止建议试动。每个条件各做三次，全部尝试都保存，失败样本计入结果。

原始轨迹和人工核对的回复见[逐条记录](evidence/speed-rejection/review.json)。回复原因需要对照 RPC 错误逐条阅读，不能由“请求工具正确”推断解释正确。

## 复现入口

在[合成语音采集](lingxi-capture.md#移动中与空闲时说全速)中使用 `--speed-host idle`、`--speed-host voice_offline` 或 `--speed-host wifi_offline`。工具文件从对应候选源码导出，主机回执程序固定到相同版本。每次请求的实际时间均写入轨迹，回执可按调用前缀重新计算。软件检查覆盖三种拒绝、正在移动时有效调速、重复调速请求的通用拒绝及零额外启动。
