# 明确时长的喷水与泡泡反馈

ct60 只匹配“喷水”“吹泡泡”等不带时长的短句。说“吹泡泡两秒”时，成功回执后的确认仍可能进入播放。ct61 扩展这类明确时长短句，并核对本次工具参数和接受回执中的 last_duration_ms。

播放判断不发出动作请求。只有工具、唯一时长参数、操作名、accepted、fault=none 和实际接受时长全部匹配，且回复在回执之后开始，才能抑制语音。超限被缩短、未知语法、否定、问句、多意图、拒绝、缺字段、时长不符或迟到回执均保留播放。

## 支持的短句范围

形式为“喷水＋时长”或“吹泡泡＋时长”，末尾可带句号或感叹号。时长支持阿拉伯数字整数毫秒、整数或至多三位小数秒、常用中文 1–30 秒及小数秒、“半秒”和“一秒半”等明确形式；范围为 1–30000 ms。其他表达保持可播放，模型的工具理解与执行能力仍由原契约规定。

这是播放白名单，未增加动作理解或输出控制入口。单位测试遍历全部 1–30000 整数毫秒和中文 1–30 秒，并覆盖小数、边界、非法输入与线程代际隔离。

## 七条合成普通话与三次修正复测

七条原话只通过二进制 Opus 发往灵矽，使用 ct60 工具说明和当前角色。工具经实际 MCP 参数门检查，再由静态夹具应答。服务器返回的转写、工具、回执和音频包顺序全部保存。将同一轨迹分别重放至 ct60 和 ct61 策略。

| 场景 | 平台结果 | ct61 包级回放 |
|---|---|---|
| 吹泡泡两秒／三十秒／2.5 秒 | 参数分别为 2000／30000／2500 ms | 100 个确认包全部抑制，ct60 原本全部可播放 |
| 喷水零点五秒，ct60 说明 | 错请求 1000 ms，并虚构“最短一秒” | 110 个包全部保留，未将时长不符当成成功 |
| 吹泡泡六十秒 | 请求 30000 ms，返回上限说明 | 34 个提示包全部保留 |
| 否定／词义查询 | 两条均无动作调用 | 204 个回复包全部保留 |

ct61 的水工具说明进一步区分“最短 1 ms”和“未指定时默认 1000 ms”。仅该工具说明改变，其他工具参数与角色保持一致。对“喷水零点五秒”另建三次合成语音会话，三次均请求 500 ms。90 个成功确认包在 ct61 全部抑制，ct60 均可播放。单次旧结果与三次新结果不能证明长期稳定性，错误样本仍计入原七条。

合计十条轨迹，ct61 抑制 190 个确认包，保留 348 个提示包。每次重放均核对音频总字节数。原七条工具参数为 6/7，喷水三次复测为 3/3，不把复测覆盖原失败。

## 实际固件回执检查

另用真实控制守卫和 Reply 序列化器，在无设备 I/O 的主机执行泡泡 2500 ms 与并发喷水 500 ms。回执中的接受时长匹配播放判断，两路逻辑启动计数合计 2。测试还覆盖拒绝、错误／缺失时长、迟到回执和新输入使旧回执失效。

平台轨迹使用静态接受回执，真实控制守卫检查属于独立主机证据。最近记录的板上应用仍为 ct45；本轮不包含麦克风、扬声器听感、机械出泡或喷水持续时间验收。

## 复核与后续

[逐条参数、回复与两版包数](evidence/effect-feedback/review.json)及同目录原始轨迹保持独立。[原话集](effect-feedback-cases.json)和[ct61 构建检查](../../firmware/esp32-audio/verification-ct61.json)提供复现依据。按[逐包回放步骤](lingxi-capture.md#核对整段回复的播放策略)分别链接两版头文件，传入同一条原始轨迹即可重算。
