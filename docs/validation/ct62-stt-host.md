# 真实 STT 事件驱动 ct62 主机

2026-10-31，使用相同的 20 条合成普通话，通过灵矽 ASR 返回的真实 STT 开启 ct62 输入轮次。主机启动时没有模拟识别文本，随后按实际接收顺序处理转写和工具调用。每次 MCP 回执来自实际固件分发、回调和控制守卫，没有向设备转发。

内置浏览器回读模型为 `deepseek-v4-flash`，角色仍为 5991 字符、原 SHA-256；温度 0.7、Top P 1、频率惩罚 0、最长 500、thinking disabled、reasoning_effort low、usage 开启。未保存配置、重启或刷写。[实验与来源摘要](evidence/ct62-stt-host/experiment.json)

## 成功确认的播放检查

将同批真实 STT、工具回执和全部远端音频包事件送入 ct62 的 `VoiceFeedback`，逐包总字节数与采集记录一致。已有短句规则抑制了 248 个确认包，包括前后左右、泡泡、全速及两条停止；613 个包保留可播放。

保留包中，四条组合／序列确认共 176 包，目标速度确认 40 包，尚需扩展可靠的成功匹配；其余 397 包属于状态、否定或澄清等回复，应继续保留。V017 没有音频，不能计为策略抑制。云端仍会生成成功确认，端侧策略回放不等于扬声器听感。[逐条包数与策略来源](evidence/ct62-stt-host/playback-review.json)

## 复核与边界

先按[完整固件主机](firmware-host.md)编译相同来源的程序，核对 `host-manifest.json` 中的二进制摘要后运行：

```sh
python3 scripts/review_stt_host.py --capture docs/validation/evidence/ct62-stt-host/full20.json.gz --executable <本轮固定主机程序>
python3 scripts/review_spoken_cases.py --capture docs/validation/evidence/ct62-stt-host/full20.json.gz
```

复核器会拒绝二进制、事件顺序、转写、时刻、回执或终态不一致。新的等待 STT 协议场景与原八组一起通过；四条历史改稿失败请求仍零启动。[主机来源](evidence/ct62-stt-host/host-manifest.json) · [九组边界及历史请求](evidence/ct62-stt-host/guard-check.json)

本轮证明真实平台转写能够驱动无设备主机，不证明设备麦克风、线程时限、扬声器、实体停止或家庭体验。时间是采集循环处理事件的时刻。每条独立会话只有一次输入，没有验证同一连接内多人抢话或重复转写；缺少原话编号时，迟到网络请求的关联限制仍在。此前 ct61 原话文本成绩与静态夹具合成语音成绩保留，不能混合提升分数。
