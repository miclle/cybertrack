## 设备约束与评测器的后续工作

换模型不能替代设备约束。此次失败显示，同一次输入中，在改稿拒绝后转用直接动作，以及重试／补做，仍可能被另一个合法业务工具接受。下一步按一次识别输入绑定请求代际，把“失败后不自动重试／补做”落实到执行端；停止应始终直达，新输入需能正常恢复，迟到回执不能影响下一条输入。该项尚未实现，不把上述试验记为约束已通过。

评测器原来会因捕获的畸形 `steps_json` 抛错，无法输出整组成绩。现将这类实际请求记录为失败，并在 `invalid_tool_argument_cases` 与逐条错误中保留；语料自身错误、缺少调用名称或非对象 arguments 等记录结构问题继续报错。非法参数、禁止调用、漏停、缺例及未完成会话仍分别统计，评分门槛保持不变。加入对应回归后，完整项目测试 76 项通过。
