# 意图分流角色对照：未采纳

本轮尝试把否定、含糊请求与泡泡编排的意图分流放在角色前部，并删除状态段里的停止确认例句。目标是减少误停、无关查询及过程播报。原角色 5991 字符，候选 5990 字符；其余动作别名、时长、速度、并发、序列和本地控制约束保留。

只改角色，十二项公开工具、ct68 固定 MCP 主机、模型及参数不变。原角色和候选各按同一十二条原话独立采三轮，共 72 次；全部结束，不重试或替换失败样本。[先行计划、角色快照及清单](evidence/intent-routing-role/experiment.json)

## 结果与未采纳原因

| 检查 | 原角色 | 候选 |
|---|---:|---:|
| 严格工具匹配 | 29/36 | 29/36 |
| 禁止调用 | 1 | 1 |
| 六条明确停止 | 6/6 | 6/6 |
| 停止后无 TTS 文字 | 0/6 | 0/6 |
| 明确单步修改／取消 | 6/6 | 6/6 |

基线第三轮 C006“不要编排表演”错误调用 stop，将已有草稿清空。候选没有复现误停，但第一轮 C008“第二步短一点”先查询，再擅自将第二步改为 500 ms，草稿 7→8；同时播报“需要知道改成几秒”和“已经改成半秒”。它仍是禁止改稿，不因新版本有效或没有启动执行器而通过。

候选的三次 C005 均多查状态，且通过 TTS 朗读规则分析；C002 第一轮仍有英文操作说明。C007 的最终拒绝更简短，但一次仍多查状态。候选停止回复虽然缩为“已停止”等，六次仍均有确认文字，不能当作成功静默。逐条调用、完整回复与人工判断分别见[控制审阅](evidence/intent-routing-role/review.json)和[播报审阅](evidence/intent-routing-role/speech-review.json)。

**未采纳，不扩大到完整固定集。** 先行门槛要求无禁止调用且严格匹配提升，两项均未满足。不能把某类错误在小样本中消失当作修复，也不以总字数减少抵消误改或规则播报。原八十条语义、八条编排和真人二十条成绩保持。

## 输入与证据边界

本轮是原话文本诊断，不经过 ASR。捕获程序的原有主机模式初始化为固定占位识别文本 `captured host input`，没有把每条原话作为设备 STT 注入。因此实际 MCP、版本与输出守卫参与，但依赖真实识别文本的 ct67／ct68 局部语义标记不参与；不能把 C008 的接受当作真实 STT 门禁失效，也不能用此批次宣称门禁拦截过误动作。

两组使用同一模式，以隔离角色语义。设备识别门禁已有独立的[相对改稿](relative-draft-duration.md)和[含糊动作](vague-action-admission.md)证据。此次发现也要求后续诊断明确区分占位输入、模拟原话输入与真实 STT，避免只看“实际主机”标签就推导完整语音路径已覆盖。

72 次原始调用的 RPC 编号、到达时刻、完整回执和终态均经同一固定二进制复算一致。模型名称和角色身份由配置保存／重开回读关联；WSS 本身没有独立证明后端执行的模型或提示词摘要。角色与工具对照分时采集，不能把差异完全归因于文本变更。不接麦克风、扬声器或执行器，不构成声学、设备调度、实物或家庭验收。
