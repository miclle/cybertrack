# 状态话术限定对照：不采纳

本轮只在角色的状态段前加上六个字“状态查询时，”，将 5991 字符临时变为 5997 字符。目的是排查“停止成功静默”与“主动停止后可说……”的示例是否冲突。平台保存后从智能体列表重新打开，逐字回读一致；工具、ct66 主机、模型和参数保持不变，没有重启或刷写机器人。[先行计划与完整结果](evidence/stop-role-qualifier/experiment.json)

## 十四次定向结果

原角色和候选各七次独立原话文本会话，三条停止、两条状态查询、一条取消草稿、一条含糊改稿。两组均正常结束，完整实际 MCP 回执和终态已按原 RPC 编号／时间逐次复算一致。

| 项目 | 原角色 | 候选 |
|---|---|---|
| 严格工具匹配 | 6/7 | 6/7 |
| 三条停止 | 三次均直接 stop，随后有 TTS 确认文字 | 三次均直接 stop，随后仍有 TTS 确认文字 |
| 停止确认总字数 | 42 | 39 |
| 无 TTS 文字的停止 | 0/3 | 0/3 |
| 两条状态查询 | 查询后正常回答 | 查询后正常回答 |
| 取消草稿 | 查询后取消、版本清零、无启动 | 同左 |
| C008“第二步短一点” | 查询并擅自改为 500 ms，草稿 7→8，含英文与规则分析 | 多查询一次后追问秒数、草稿保持 7，仍含英文与规则分析 |

原角色的 C008 本应追问，实际 MCP 却接受改稿，随后模型道歉。候选未误改不等于稳定修复：每条只采一次，分时运行，没有因失败重试。两条 C008 都不符合严格无工具预期；英文及过程文字均直接出现在平台 `tts/sentence_start` 事件中，不是从固件日志推测出来。[逐条复核](evidence/stop-role-qualifier/review.json)

**不采纳。** 先行计划中的数值检查均满足，包括停止字数减少、含糊改稿不变，但它们只能作为继续研究的信号。42→39 是措辞变化，没有增加一次静默停止，过程播报也仍存在，不能将较短文字当作产品问题已解决。因此没有扩大到完整八十条语义与八条编排，也没有修改其历史成绩。
