# ct76：含糊改稿的时长不能借用其他分句

ct75 的相对改稿门禁先在整句话搜索量化值，因此“第一步保持两秒，第二步短一点”会因第一步的“两秒”放行第二步的猜测修改。“第二步短一点，第一步保持两秒”和“速度保持80%，第二步短一点”也有同样问题。

已用 ct75 实际 MCP 主机复现三条反例：注入模拟识别文本，再请求把第二步改成 500 ms，三次均返回 `draft_saved`，草稿版本 7→8、第二步 1000→500 ms。[原始反例](evidence/ct76-draft-clause/baseline.json)保留完整请求、回执与终态。这些是人为构造的错误模型调用，不是本轮线上模型真的发出了调用。

ct76 改为按相对修改词所在分句检查量化值，其他分句的时间或速度不再解除澄清门禁。紧接着的明确赋值仍可补齐同一步，例如“第二步长一点，改为两秒”；遇到另一步或隔着其他分句则不能继承。多处相对修改分别检查，不能用已量化的第二步掩盖含糊的第三步。

拒绝沿用 `draft_duration_unspecified` 和既有澄清说明，保持原稿，查询／统一停止及新输入恢复不变。十二项工具、正式角色源、模型设置和网页路径不改；固件只是阻止错误写入，不能替代模型准确选择工具或消除过程播报。

## 验证与范围

- 分类器 ASan／UBSan 检查覆盖中文／英文分隔符、速度／其他步骤数字、紧邻量化补充、多步混合及说话长短对照。
- 实际 MCP 的 19 组原生检查通过，包含四条新拒绝和两条合法改稿，以及原有失败后隔离、新输入恢复、取消、方向替换、长时长、迟到回调和直接全停。[回执与终态](evidence/ct76-draft-clause/host-checks.json)
- 完整 ESP-IDF 构建通过；十八组软件检查中保留十七组已有通过，补齐参考包清单后重跑失败的 Python 组，135 项全部通过且无跳过。初次失败保留，未伪装成首轮全通过。[检查汇总](evidence/ct76-draft-clause/software-checks.json) · [ct76 构建记录](../../firmware/esp32-audio/verification-ct76.json)

这是有限的标点分句检查，**不证明数字与步骤的完整自然语言归属**。无分隔符的多主题表达、同一分句中的旧时长与新要求、未覆盖的省略和歧义仍可能需要澄清；实际 STT 是否保留标点须独立验证。新补充表达应继续加入线上回归，不把模拟输入成绩当作 ASR 或模型成绩。

用户暂缓实机，本轮没有设备请求、重启或刷写。最近记录部署仍为 ct75；ct76 仅为软件候选。普通提示音的三个跳过项保持跳过，原 80／8 模型失败及物理／家庭验收不因此关闭。
