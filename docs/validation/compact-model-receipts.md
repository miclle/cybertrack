# 成功回执收敛试验：不采纳

本轮尝试让灵矽只收到成功动作或成功改稿所需的业务字段，查询、拒绝、故障及网页诊断继续保留完整快照。诊断构建标为 `ct64`，没有进入主线或刷写；试验结束后源码候选恢复 ct63；后续候选见[当前状态](../current-status.md)。

内置浏览器回读仍为 `deepseek-v4-flash`，5991 字符角色及 SHA-256 与仓库一致，温度 0.7、Top P 1、频率惩罚 0、最长 500、thinking disabled、reasoning_effort low、usage 开启。未修改或保存平台配置。公开工具定义与 ct63 相同。[实验、摘要与未采纳决定](evidence/compact-model-receipts/experiment.json)

## 先核对数据，再验证模型

实验只复制同一次真实 Reply 中的字段，不补默认状态、不改参数、不调用输出。成功动作保留结果、故障、逻辑输出、各路时长／来源、速度和序列信息；成功改稿保留完整草稿。实现位于控制锁之外，C 分配失败或字段不齐时保留完整回执，收敛结果复用原字符串存储。

对[既有二十条 STT 主机轨迹](ct62-stt-host.md)离线重放：十四条成功回执变短，全部工具文本回执从 45,484 字节降为 17,736 字节，约减少 61%。保留字段逐值相等，二十条终态完全一致，播放仍为抑制 464 包、保留 397 包。ASan／UBSan 测试还逐个注入 C 内存分配失败，确认完整回执可保留。这些是数据流与播放检查，模型没有在本项离线重放中接收收敛后的回执；不能由此推导 token、计费、延迟或语义改善。[逐例数据](evidence/compact-model-receipts/projection-review.json)

## 八条真实平台编排结果

使用原话文本、相同角色／工具和实际诊断 MCP 回调，共八次独立灵矽会话，不向设备转发。

| 项目 | 结果 |
|---|---|
| 正常结束 | 8/8 |
| 工具、参数与顺序匹配 | 5/8 |
| C001–C004 新建、改一步、删除和取消 | 调用与草稿结果匹配 |
| C005“开始这段表演” | 多查一次状态；未启动 |
| C006“不要编排表演” | 误调用 stop，草稿版本由 7 清为 0；禁止调用失败 |
| C007 不支持的点火编排 | 无调用，说明限制 |
| C008“第二步短一点” | 多查一次状态后追问；未修改 |
| 八条启动计数与逻辑输出 | 零启动、输出关闭 |

C001／C002 仍有操作前旁白，C003／C008 含英文过程文字，C005 仍播报规则分析，C004 仍重复确认。所有实际 MCP 回执与终态均经同一固定二进制复算一致。输入为文本，未验证麦克风或扬声器。[原始八条](evidence/compact-model-receipts/full-compose.json.gz) · [评分](evidence/compact-model-receipts/full-suite-scores.json) · [逐条复核](evidence/compact-model-receipts/review.json)

**不采纳。** 本轮低于已有完整主机编排 6/8，且出现 C006 禁止调用，因此停止扩大试验，没有运行新的 80 条语义集。C006 的首个调用发生在返回收敛回执之前，不能将其归因于回执格式；本轮仍不足以支持替换主线。没有重试失败用例、修改门槛或覆盖此前成绩。

## 保留、恢复与复核

试验结束时主线控制源码及 `firmware/current.json` 恢复 ct63，角色不变。[诊断源码补丁](evidence/compact-model-receipts/experimental-source.patch.txt)以 `715662f` 为基线，包含全部十个实验文件，已在原文件副本中应用并逐字回读一致。这是零上下文补丁，应用时须指定 `git apply --unidiff-zero`；只供独立研究副本复现，不应直接套用当前主线。实验构建的字节数和 SHA-256 另记在实验清单中，不能作为当前候选或部署依据。

有本轮固定诊断主机与同版播放回放器时，可执行：

```sh
python3 scripts/review_compact_receipts.py --executable <实验主机程序> --playback <ct63 播放回放器>
```

脚本核对主机摘要，重放二十条数据投影及八条平台会话，比较保留字段、完整 MCP 回执、终态与播放结果。参考包单独以 `compact_receipt_scores` 重算本轮八条调用成绩，继续显示 5/8 和 C006；完整控制重放需要源码及固定主机环境。

采集器另交付 `--continue-incomplete`：显式保留未完成用例后只进入下一条，不自动重试，默认仍在首个未完成后停止。本轮八条均正常结束；该选项没有改变评分或把缺少结束事件当作成功。
