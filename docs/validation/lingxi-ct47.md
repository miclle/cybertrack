# ct47 草稿能力与驱动故障回复

在 ct46 的三轮联调中，“排练第二幕想加一点喷水，先别演”三次得到错误追问。驱动故障题两次得到重启建议。ct47 让状态回执直接给出草稿允许的通道、网页确认入口，以及驱动故障时保持停止、交给家长排查的说明。设备仍使用原有动作和草稿校验。[ct46 完整基线](lingxi-ct46.md) · [ct47 主机与固件构建](../../firmware/esp32-audio/verification-ct47.json)

首先用额外的合成字段探索这两条原话，每条三次。一次回答喷水问题时没有查询设备，因此这组对照无法单独证明回复变化由字段导致。[探索轨迹](evidence/ct47-regression/prototype.json.gz)

随后从候选固件导出工具、复用固件字段生成器，独立完成三轮，每轮 8 条只读状态题和 8 条原话迁移题，共 48 次正常结束。角色与 ct46 相同。P005 与 D003 在这三轮中均实际调用了 `get_status` 并收到对应字段。

| 场景 | ct46 三轮观察 | ct47 三轮观察 |
|---|---|---|
| P005 在表演草稿加喷水 | 0/3 明确拒绝，全部追问参数 | 3/3 说明草稿只支持行走和泡泡，未写稿或请求动作 |
| D003 驱动故障 | 2/3 建议重启 | 3/3 要求保持停止、由家长检查，查明前勿重启试跑 |
| D007 当前步骤间等待 | 3/3 解释表演仍在进行 | 3/3 解释等待，未误报表演结束 |
| P001–P003 默认成功短指令 | 主机重放抑制 9/9 首包 | 主机重放抑制 9/9 首包 |
| P004 超限喷水 | 3/3 保留语音说明 | 3/3 只请求 30000 ms，保留说明首包；第二、三轮仍重复提示 |

本轮覆盖回执契约变更涉及的两组用例。固定 80 条动作和 8 条编排的三轮分数归于 ct46。普通自然语言中的否定、同时／先后、回复冗长和真人识别仍需独立验证。全程由隔离夹具回应工具，没有向设备转发，也没有刷新实机固件。
