## 语音工具选择

已提供[灵矽隔离捕获入口](lingxi-capture.md)：从实际固件导出工具描述，运行真实 WSS 文本会话，仅返回模拟回执、不下发设备动作。线上成绩与回复审阅见[ct45 联调记录](lingxi-ct45-20261031.md)：首轮 80 条工具匹配 95%，编排 5/8，回复语义未通过；后续[角色复测](lingxi-ct45-role-feedback-20261031.md)为 77/80（96.25%），编排仍 5/8。

`voice-cases.json` 固定 80 条文本用例，包含前置状态、预期工具与回复要求。`spoken-cases.json` 选取 20 条真人表达。先在无执行器的工具捕获环境运行文本集；测试不得接入真实动作工具。普通动作的既有语义不因产品规划改变。点火类仅为文本参数回归，不属于亲子试用或高压测试。

记录格式如下，完整测试要逐条包含所有 80 个 ID；模型名称、角色哈希、运行 ID 必填。前置状态必须真实提供给受测模型，捕获工具调用顺序；回复语义由人工核对。不要把 expected_calls 复制成实际记录，下面仅演示格式。

```json
{"kind":"captured_tool_calls","run_id":"actual-run-id","model":"actual-model-version","role_sha256":"actual-sha256","results":[{"id":"V001","calls":[{"name":"self.tank.move","arguments":{"direction":"forward","duration_ms":1000}}]}]}
```

评分命令：`python3 scripts/evaluate_voice.py output/voice/actual.json --output output/voice/score.json`。缺例、重复 ID、未知 ID 或禁止动作样本出现控制调用不能通过；序列 JSON 键顺序、工具名称规范化及默认速度不影响语义等价。未执行线上模型时只能报告评分器测试通过，不能报告识别率。

真人表达分别在安静、设备播放语音和批准的低压运动噪声条件测试；记录识别文本、工具、回执及现场观察，先断开功率核对，再逐项实物验证。不把录音、设备凭据或参与者身份提交 Git。

## 五组亲子体验

家长知情并全程负责启动、停止和设备管理。儿童可拒绝或退出。使用匿名家庭编号，不采集姓名、联系方式、面部或录音；年龄段可选且只用于理解交互。未完成适用性检查前，仅使用无动作的界面／故事原型；现场互动范围由家长与设备负责人确认。

每组 15 分钟：2 分钟说明与停止方式 → 3 分钟独立首次使用 → 5 分钟体验语音／泡泡／编排原型 → 3 分钟自由重复 → 2 分钟反馈。观察者不提示隐藏步骤，需要帮助时如实计数。记录哪个玩法是主动重玩，不能把主持人的邀请算作主动选择。

填写 `templates.json` 的 family_sessions。目标：至少 4/5 独立上手，至少 3/5 主动重复同一玩法。记录家长愿意使用的场合、主要顾虑及对装配维护的接受程度；不将“觉得有趣”直接等同购买意愿。

## 低压故障矩阵

已提供[17 案例采集契约与分析说明](stop-trials.md)、[空记录入口](stop-trials.json)及 `scripts/analyze_stop_trials.py`。具体记录格式以该契约为准；旧 `templates.json` 的 fault 字段只作采集概览。分析器拒绝混来源、重复计数及无效数值，并按配置分别给出缺项、违例和输出／机械停止统计。命令成功不代表实物验收。

每种条件至少 5 次：松手、BOOT、网页后台、网页网络中断、Wi-Fi 断开、语音连接关闭、序列执行／等待时取消、重连。分别记录 web／voice 来源以及活动通道。网页失效只停网页动作、语音失效只停语音动作，BOOT／统一停止／Wi-Fi 断开全停；序列后续步骤不得恢复。

先断执行器功率核对逻辑，再按批准范围逐项带载。测量事件发生、输出归零、机械停止三个时间，停止距离另测。记录固件哈希、电源、负载、地面、速度、工具和方法；600 ms 租约不是机械停止承诺。出现失控、复位或超出已定额定限制时结束该轮并记录原因。

固定语义集还有一道独立的停止门槛。V045–V052 均须以一次无参数 `stop` 结束，先查询、改草稿、遗漏或未完成均记入 `failed_stop_cases`。即使 79/80 匹配，一条停止不符合约定也不能通过工具调用验收。历史评分文件保留原样，可用当前评分器对同一轨迹复算。

## 电源、续航与成本

先从实际型号资料填写各支路允许电压／电流／温度和测量方法，未知保持 null，不用模块宣传功率代替。分别记录待机、语音、行走、喷水、泡泡和获准的低压组合负载。当前电池为辰克 5 V；不使用旧电源数据，不安排点火高压测试。

先完成短时基线与异常检查，再确定连续运行时长；相同典型使用流程实际重复 3 次。万用表读数不能冒充瞬态峰值。成本关联 `hardware/BOM.md` 的物料 ID，分别记录实际单价、数量、来源、打印克重与料价、装配工时；样机成本和未来批量估算分列。

当前 Lean 27 件的估算为 920.28 g PLA，逐盘数据可用于整套预算或按盘补打。用实际每公斤购料价换算预计用料费用，实打称重、重打及修整另记。[切片口径与复核方法](../../hardware/model/lean-print/README.md#打印一套需要多少耗材)

用 `python3 scripts/summarize_parts_cost.py docs/validation/templates.json` 汇总采购记录。将模板复制到本地填写，每行关联一个 H 编号。`source` 填脱敏凭据代号和行号，同一来源行只入账一次。样机行填用在这一台的数量、实付单价、购买日期及 `estimate_only: false`。报价行填 `estimate_only: true`、`estimated_unit_cny` 和 `scenario`，用场景名区分采购数量和报价版本；同一场景统一按一台或整批计量。没有可核对的单价就留空。工具分列已知采购小计、各报价场景小计、缺凭据的 BOM 项和不完整记录。BOM 含待选部件，缺凭据清单供逐项核对；样机总成本还需计入实际打印消耗、报废和装配工时，同一笔料费只计一次。

在模板副本的 `power_runs` 里，每次独立开跑分配一个 `run_id`。在本地事先写下典型流程（动作次序、占空比及循环方式）、电池起始状态、负载、地面、速度、环境和允许的停止条件，以 `procedure` 和 `condition_id` 引用。固件、电池编号、流程或条件不同就分组。到事先规定的终点写 `planned_endpoint`，人工中断、保护动作或异常提前结束写实际原因。同一趟各支路共用整趟时长、复位次数和结束原因；至少一条 `battery_output` 记录要有仪器、额定依据、电压、电流和温度，注明采样时刻及测温位置。

```sh
python3 scripts/analyze_power_runs.py docs/validation/templates.json
```

同条件至少三趟到达预定终点且全程无复位，才给出这些完成样本的时长中位数；报告同时列出异常、中断、缺数据和未归类样本。若预定终点仅是一次固定时长演示，结果只表示该流程的运行时长。当前真实样本为零，整机续航和电气额定符合性仍待实测。

## 维护与修改效率

维护记录补液、清洁、取瓶、换电池、线束检修的步骤／耗时／工具／异常。先测基线，再选择最慢两项修改，比较相同条件下至少 3 次中位数；目标降低 ≥30%。10 次拆装检查紧固、磨线、管路与渗漏；未经观察不得写“无故障”。

在本地记录副本中填写 `maintenance_trials`。每次观察有独立 `sample_id`，`condition_id` 对应一份可追溯的工况说明，固定装配方向、液量、起止状态、计时口径及操作人员安排。两个版本共用该工况编号。记录实用工具、观察者代号、是否完整完成及异常，未检查的异常填 null，检查过且无异常填空数组。按顺序将实际操作写入非空的 `steps` 数组。计时与循环均填写 `evidence_kind: physical_observation` 和能定位该次原始观察的 `evidence_ref`（如台架记录页及行号）。CAD 演练、模拟和来源未标明的旧记录单列，不进入中位数或十次循环。每个任务分别按 `before` 或 `after` 从 1 编号。旧记录缺工况时只计为未归类。

```sh
python3 scripts/analyze_maintenance.py docs/validation/templates.json \
  --condition 台架A --before 基线版 --after 修改版
```

首次采基线可省略 `--after`。五项任务各有至少三次完整计时后，工具选择中位数最高的两项。并列按模板任务顺序取前；应记录并列情况，两项分别按未舍入的比例判断是否降低至少 30%。已完成但遇到异常的计时仍计入；未完成或缺字段的次数单列。重复编号会拒绝汇总。

在 `maintenance_cycles` 单独记录修改版完整拆装循环，每次分别填写紧固、磨线、管路、渗漏四项 `checks`（值为 `ok` 或 `issue`）；发现问题应写入 `faults`。十次记录齐全只代表检查覆盖，遗留故障仍需处理。当前模板的真实记录为空。


[实际工程记录工具](engineering-log.md)提供开始／结束／汇总命令，绑定新提交与验证产物，未知值不填零。每次软件改动记录开始／结束、人工时间、模型等待、修正轮数、失败检查、提交与回归缺陷。至少积累 5 个真实样本；不能以代码行数或单次成功声称效率提升百分比。

## 编排候选增量

[compose-cases.json](compose-cases.json)固定 8 条编排用例，用模拟状态上下文定义预期工具；与原 80 条直接动作集分开评分。通过 `--corpus` 选择增量集，完整编号校验和禁止直接动作门槛保留。评分器单元测试不是灵矽模型成绩；ct45 角色已保存回读并部署，模型调用及其偏差已在上述联调记录保留。

## 泡泡剧场体验任务

ct45 候选的[模板与操作流程](../show-composer.md)先在无动作原型中测试理解，再在具备条件后验证设备。每组安排：选“登场”但不保存 → 说明此时是否会动 → 将第二步泡泡改为 2 秒并应用／保存 → 核对设备版本 → 家长确认启动或选择取消 → 自由选择是否修改或重玩。不要预先告诉孩子哪个模板更有趣；“庆祝”“谢幕”留作自由选择。

分别记录是否误以为选模板即执行、是否理解未应用／未保存状态、能否找到停止、是否主动修改／重玩及具体模板。I07 的门槛按家庭去重：至少 3/5 主动重玩或修改，同一家庭多次不重复计数。无动作原型结果与实体表演结果分列，不能相互替代。

后续角色修正、独立同步记录及复测见[联调反馈修正](lingxi-ct45-role-feedback-20261031.md)；首轮轨迹和评分保持不变。

### 从五份原始观察复核三项指标

预先为同一场次留出 F01–F05 五个家庭编号，固定使用原型或设备、版本、网络条件和上手卡。主持人只记录实际发生的行为。按上述任务要求的改第二步属于引导环节；只有随后的自由选择才进入重玩与修改统计。记录同一玩法时须具体到口令、模板或完全相同的自编剧本编号。不能将不同家庭各自编的故事合并成一个热门玩法。

在仓库根目录运行 `python3 scripts/analyze_family_sessions.py 记录目录/*.json`。每个文件用 `family_sessions` 数组保存匿名记录。报告分别给出五组家庭中三分钟内独立完成首次动作且停止的组数、各个玩法被几组主动重复，以及主动重玩或修改泡泡剧场的组数。180 秒计入，主持人提供操作帮助、动作未完成或未独立停止均不能计入独立成功。已熟悉界面的家庭不能作为首次上手样本。暂停或未观察的环节保留未知。

原型和实机按场次、载体、版本及网络条件分别汇总。原型结果标为 `prototype_only`。每项收齐五组可判定观察后才显示达到或未达到门槛。来源不明的历史记录单列，模拟数据不得充当家庭观察。定性判断另需结合家长的使用场合、顾虑和维护接受度。
