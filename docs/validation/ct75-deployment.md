# ct75 部署与无动作 HTTP 检查

2026-11-01 用户确认执行器仍断电、主控保留供电，并授权仅更新 ct75 应用。完整[启动与部署记录](../../firmware/esp32-audio/startup-ct75.json)关联本次检查；没有请求真人听感或实际动作。

## 写入与启动

- [预检](evidence/ct75-deployment/preflight.json)确认设备身份、分区表和 OTA 选择；芯片中的旧应用与 ct74 回退文件一致。新鲜的 128 KiB 配置备份及回退应用仅保存在本地忽略目录，没有尝试全片备份。
- 仅写 `0x20000` 应用，2,721,488 字节、SHA-256 `6e6cf11e9ae1fd59e4280ec249495a8dc1602950a57e08b130ea44883714a8c8`。写后应用摘要、启动前配置逐字节及 `0x410000` 以上非应用区摘要核对通过。
- 两次启动均读到 ct75、OLED 初始化、控制输出初始化关闭、联网和 idle。各十条[HTTP 回读](evidence/ct75-deployment/http-readback.json)为零启动、逻辑输出全关、无活动序列或草稿；网页与源码一致，采集后释放会话。
- 角色源未改，仍与 ct74 部署时的平台回读摘要一致。本次沿用该观察的原时间，不将它记成新平台回读或保存。

## 配置比较的首次失败与复核

首启后的“只允许连接令牌变化”检查[失败](evidence/ct75-deployment/nvs-initial-failure.json)，没有忽略失败或重新取样替换它。按 ESP-IDF NVS blob 索引的大小、块数及起始编号重组同一份前后快照后，[复核](evidence/ct75-deployment/nvs-review.json)确认：

- 前后各 59 个逻辑配置项，两个已存 Wi-Fi 和用户设置保持，记录及数据 CRC 均通过；非 NVS 的前应用区域仍逐字节一致。
- 值变化仅有 `websocket/token` 与 `phy/cal_data`。PHY 校准数据前后均为 1904 字节，但内容确实改变，不能仅解释为分块布局变化。
- 本地 ESP-IDF 5.5.1 的 `components/esp_phy/src/phy_init.c` 将 `phy/cal_data` 用于运行时无线校准存储；本次未捕获具体更新原因，未据此推断电源故障或无线性能通过。

因此本次结论是“Wi-Fi／用户设置保持，系统运行时数据变化已记录”，不是“首启后所有配置字节不变”。语义比较只对应首启快照，第二次启动另验联网与零输出，不冒充第二次 NVS 比较。

## 实际 HTTP 拒绝检查

[22 次请求](evidence/ct75-deployment/http-zero.json)覆盖五类非法输入：操作名零转义、键名零转义、原始零字节、草稿取消值零转义和 revision 键零转义。全部返回 HTTP 400／`invalid_request`；草稿内容与 revision 在拒绝后保持，合法 Unicode 操作名、状态查询、取消及空闲全停正常，最后释放会话。

其中 16 条包含控制状态的响应均为零启动、逻辑输出全关。合法调速请求只重设原有网页速度偏好；一份草稿仅保存并取消，未确认表演。没有发送畸形行走／效果请求；这些分支继续以[原生回归](http-zero-admission.md)为依据，不冒充设备分支覆盖。

本轮完成应用部署及上述无动作检查，不验证物理电平、制动时延、扬声器、模型语义或家庭使用；用户已跳过的三个听感项目保持跳过。构建时的 `verification-ct75.json` 保留当时“未部署”的历史状态，当前版本以 [firmware/current.json](../../firmware/current.json)为准。

本次私有快照另由[通用离线配置核对工具](nvs-config-review.md)复算，默认策略继续报告两项变化；显式例外不隐藏差异，也不替代原首次失败记录。
