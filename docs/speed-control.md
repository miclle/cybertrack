## 速度与时长

2026-10-30 ct39 已部署：未说时长时，100% 速度（含省略速度）的左右转默认 880 ms；60–99% 转向、前进／后退及其他普通动作仍默认 1000 ms。单项、组合及序列每步均适用，明确指定或同一步明确共享的时长优先；组合中的喷水默认仍为 1000 ms。平台保存回读一致、设备仅应用更新并重启联网；用户确认 880 ms 测试效果符合预期，完整语音回归仍待逐项验证，见[角色维护](agent-role.md)及[部署记录](../firmware/esp32-audio/startup-ct39.json)。

`speed_percent` 为 60–100 的整数，省略为 100。`以 80% 的速度前进五秒` 对应 forward、5000 ms、80；`以 60 的速度左转三秒` 对应 left、3000 ms、60。最快为 100，不能把百分比当作实测轮速、距离或转角。超范围、非整数或无明确数值的绝对速度先澄清，不擅自截断。0 不作为移动速度；停止仍走统一停止或网页松开。

电机频率仍为 1 kHz，8 bit duty 使用 `(speed × 255 + 50) / 100` 整数换算：60 → 153、70 → 179、80 → 204、100 → 255。默认由 ct25 的 230 提至 255。同方向调速只更新 LEDC 占空比，不拉低使能、不改方向或脉冲其他通道；换向仍先关闭两路使能。任何输出 API 失败仍锁定全停。GPIO18 诊断保留。60% 下限来自用户动力不足的现场反馈，并非定量轮速或负载校准。

## 语音工具

| 工具 | 速度参数 | 行为 |
|---|---|---|
| `self.tank.move` | 可选 `speed_percent`，默认 100 | 指定速度执行原定时长 |
| `self.tank.move_and_water` | 可选 `speed_percent`，默认 100 | 仅影响行走，喷水保持原定时长 |
| `self.tank.sequence` | `steps_json` 每步可选 `speed_percent` | 五个动作字段仍必填；各步速度独立，省略为 100；全句指定速度由提示词填入各行走步骤 |
| `self.tank.set_speed` | 唯一字段 `speed_percent`，60–100 整数 | 直接设置当前移动目标速度；不启动、不改方向、不续时、不影响其他通道 |
| `self.tank.adjust_speed` | 唯一字段 `delta_percent`，仅允许 10 或 −10 | 对当前移动增减 10 个百分点，结果限制在 60–100；不启动、不改方向、不续时、不影响其他通道 |

“加速、加快速度、快一点”调用一次 `adjust_speed`／10；“减速、减慢速度、慢一点”调用一次／−10。例如 70 → 80，不是乘 1.1；100 加速仍为 100，60 减速仍为 60。接受后静默，拒绝不重试。停止或序列等待间隔中拒绝，不能用 `move` 补启动。票据绑定当前行走的启动计数及语音会话，重复 RPC、停止后迟到、跨步骤迟到均不能再次调速。

调速适用于当前语音、网页和狂暴模式的移动；序列只改变当前步骤，后续步骤保持原定速度。网页正在行走时，语音加减速同步更新网页速度偏好和显示，但不更新长按租期，仍由原网页续租或松开停止。语音启动新移动仍遵循网页同路优先；当前移动的绝对及相对调速均允许此交互。

“减速到 60%”“加速到 80”“速度调到 70”调用一次 `set_speed` 设置目标，不连续调用相对调速，不重新启动行走。单独“全速／最快／最大速度／调到全速”均调用 `set_speed` 设置当前速度 100%，不追问方向或时长；空闲时不启动。“全速前进／后退／左转／右转”先查询状态：空闲调用 `move` 启动对应方向，左右转默认 880 ms、前进／后退默认 1000 ms，显式时长优先；正在同方向移动只调到 100%，原截止不变；不同方向不自动停止换向。仅明确移动语境的“全速后台”按后退纠错；软件后台等语境不触发动作。

## 网页滑块

方向键上方新增“网页速度”滑块，范围 60–100%，新网页控制会话默认 100；重新连接恢复默认，不写入 NVS。闲置时设置仅影响后续网页动作，不启动电机；网页行走或狂暴模式中设置立即修改其电机输出，不改变到期时间、长按 ID／续租序号、动作启动计数或效果输出。语音自己的指定速度与序列步骤不会被闲置网页的偏好覆盖。

滑块每次以新鲜状态窗口提交 `POST /api/action`：

```json
{"operation":"set_speed","sequence":1,"window":1,"speed_percent":80}
```

须使用现有会话令牌及 Host／Origin 校验；整数、字段数、窗口与请求序号校验不变。此操作返回 `ok`，不是启动动作的 `accepted`。不增加单独端点。快速拖动只保留最新待提交值，串行提交；停止、隐藏、断线使过时请求失效，不重试或回放。持续行走的续租不等待滑块请求。

状态提供 `speed_min_percent=60`、`speed_max_percent=100`、`capabilities.speed_control=true`、`web_speed_percent` 和 `move_speed_percent`。后者为当前行走设置百分比，未移动为 0；`logical_outputs.left/right` 为带方向的 −100…100 设置值。滑块依据设备回执同步，移动状态额外显示当前百分比。旧固件缺少能力时滑块禁用。

主机 sanitizer 覆盖四方向 60／70／80／100%、独立截止、低于 60% 拒绝、绝对目标和 10 点加减与限幅、重复／停止／跨步骤票据、网页动态变化不延长租期／重启动作、语音调节网页移动及源隔离。输出测试检查 duty 映射、同向变化不触发停机或效果写入、更新失败锁定全停。实际导出的 MCP 校验、HTTP 参数／处理器、网页合并请求及停止竞态通过；ESP-IDF v5.5.1 构建通过。

ct27 初次部署时角色为 5974 字符；后续单独“全速”修正为 5998 字符，已保存回读并重启，见[提示词更新记录](../firmware/esp32-audio/role-full-speed-ct27.json)。ct27 仅应用部署、保持配置、启动联网，设备网页与源码一致；闲置 80／60／100% 设置成功，59% 返回 HTTP 400，默认恢复 100%，执行器启动计数为 0。测试中没有启动执行器。用户已确认速度测试符合预期，单独“全速”修正也已实测并有下述串口佐证；以下其他细项未逐项记录验收：

- “以百分之八十的速度前进十秒”，移动时说“减速到百分之六十”，确认一次设置到 60% 且原截止不变；随后“加速”应到 70%。
- “全速前进／后退／左转／右转三秒”，分别核对方向与 100% 设置；单纯“调到全速”只调当前移动。
- 网页滑块最低 60%；在 60% 继续说“减速”，应保持 60%。松开或统一停止后，“加速／减速到 60%”不能启动。
- 序列当前步骤调速后，后续步骤仍按原指定速度，其他通道的截止不变。

软件与用户观察不等于定量轮速、100% PWM 下电流、母线与温升验收；此前喷水启动轻微滞后和脱离 USB 回归另行记录。

## 单独“全速”反馈与修正（2026-10-29）

用户确认此前速度测试符合预期，但移动中单独说“全速”未生效。原角色只有“调到全速”与带方向的全速表达，没有显式覆盖这个短句；本次补齐明确映射，固件 ct27 不变。已有串口记录在 08:31:38 断开，包含此前效果动作但没有本轮调速回执；无法据此确认失败发生在语音识别、模型选工具还是参数校验。记录用户结果，不将提示词缺口视为已通过复现确认的唯一根因。

保存后重启联网，部署检查未发送执行器启动请求。用户随后确认移动中单独“全速”正常生效。08:54:28 的 `move` 回执接受前进十秒、60%；08:54:37 的 `set_speed` 回执接受 100%，方向仍为 forward，启动计数仍为 1，剩余 1393 ms。两份回执的 `uptime_ms + move_remaining_ms` 均为 986418，证明未延长原截止；随后 `ACTION_OFF` 因 deadline 结束，实际软件运行 10003 ms，无故障、无日志丢弃。证据见[更新记录](../firmware/esp32-audio/role-full-speed-ct27.json)。

此轮未覆盖：停止后单独“全速”不启动、“不要全速”不调速、“现在是全速吗”只查询，以及其他方向的全速表达。
