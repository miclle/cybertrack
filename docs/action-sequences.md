## 序列工具与执行契约

`self.tank.sequence` 仅接收字符串 `steps_json`，内容为 1–16 个步骤组成的 JSON 数组。上游工具属性仅支持标量，因此使用 JSON 字符串；调用时应正规 JSON 编码，不直接传数组。每步必须正好包含以下五字段，不接受缺失、重复或额外字段：

| 字段 | 范围／语义 |
|---|---|
| `direction` | forward/backward/left/right；本步不行走时为 none |
| `move_ms` | 0 或 1–2147483647；none 时必须为 0，否则必须大于 0 |
| `water_ms` | 0–30000 |
| `bubbles_ms` | 0–30000 |
| `ignition_ms` | 0–5000 |

0 表示本步不用该通道，各时长必须为整数；每步至少一个通道。字符串最多 4096 字节，拒绝尾随内容。先校验整单再签发会话内一次性票据；执行前复验，并要求四路均空闲、冷却结束且没有网页活动通道或狂暴模式。单次接受保留四路，期间新的独立语音动作拒绝；网页正常连接、心跳和释放不会取消语音序列，有效网页动作请求优先取消整单并返回 `voice_preempted`，不会立即启动网页动作，需间隔结束后新指令。

同一步所有通道在同一互斥区更新、同一轮应用输出，逻辑上原子接受或拒绝；GPIO 写入仍是顺序 API 调用，不承诺物理边沿严格同步。各通道独立截止；全部停止并满足冷却后才开始下一步。行走／喷水／泡泡停止后至少间隔 200 ms；点火关闭间隔至少等于实际软件 ON 时长。步骤间隔由设备控制，不需要模型等待或再发工具调用。控制循环只访问固定 16 步存储，无 JSON 解析或堆分配。延迟 tick 不补赶遗漏动作或缩短间隔。

统一停止、BOOT、语音连接关闭、Wi-Fi 丢失、关机／升级入口、输出故障、时钟倒退及网页抢占均取消当前和全部后续步骤；松开／恢复连接不恢复。票据过期、重复、取消及忙碌不自动重试。不能借序列分割一个超限效果或擅自循环。

## 回执与验证边界

`result=accepted` 仅表示序列开始。状态含 `sequence_active`、`sequence_step`（从 1 开始）、`sequence_steps`、`sequence_result`（idle/running/waiting/completed/cancelled）及 `sequence_max_steps=16`。间隔中仍为 ACTIVE；最后一步结束即 completed，不要求等待最终冷却结束。历史进度保留供查询，新序列开始时重置。`remaining_ms` 只代表当前通道的最大剩余时长，不能作为整条序列倒计时。网页显示序列执行、等待或取消状态，未新增编排界面。

主机 ASan／UBSan 用例覆盖长时行走、并发及串行时序、效果上限、整单拒绝、重放／过期、运行和间隔中的停止／故障／断线／抢占，以及恢复连接不补做；MCP 实际校验块、HTTP 解析及处理函数、网页脚本和 ESP-IDF 构建分别验证。软件结果不等于真实语音识别、设备时延或带载动作通过。平台同步与真人回归按[角色维护](agent-role.md)执行；90% PWM 下的速度、停止距离、电流、母线电压和温升仍待验证。
