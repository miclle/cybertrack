# CyberTrack 智能体角色与提示词

角色介绍决定小D如何理解指令、选择工具和报告结果，是机器人的行为配置，需要与固件一起维护、审阅和验证。

## 维护源与名称

完整角色介绍的唯一维护源为 [role-prompt.txt](../firmware/esp32-audio/role-prompt.txt)，已纳入 Git 跟踪。该文件是可直接粘贴到灵矽“角色介绍”字段的 UTF-8 纯文本，不添加版本标题、维护说明或测试记录。版本和差异由 Git 管理；本页记录维护流程，其他文档只链接原文，不复制正文。

| 项目 | 当前约定 |
|---|---|
| 灵矽智能体管理名称 | CyberTrack，原名“彩菊”，沿用现有面包板绑定 |
| 助手昵称 | 小D，角色中的 `{{assistant_name}}` 对应平台昵称 |
| 固件唤醒词 | “你好小智”；更改管理名称或昵称不会更改唤醒词 |
| 角色 | 机灵、友好、利落的双履带机器人小助手，主要响应指令、报告状态 |
| 当前能力 | ct10 支持网页与语音同时操作，按通道判断来源与网页优先；同步与现场回归状态见文末 ct10 记录 |

历史联调中的“彩菊”指当时的智能体名称，不批量改写历史证据。音色名称“彩菊姐姐”与智能体名称是不同配置，不因智能体重命名而修改。

## 修改与平台同步

1. 先编辑 `role-prompt.txt`，说明要改善的行为，并检查工具名称、参数、单位和回执字段是否与[面包板实现](../firmware/esp32-audio/README.md)一致。语气优化不能无意改变执行条件、时长或停止语义。
2. 审阅原文差异。保留真实回执优先、失败不自动重试、默认一次 1 秒、行走最多 3 秒、喷水最多 30 秒、两路独立计时、同路忙碌拒绝、本地停止优先和未接入能力不假装执行等约束。实际能力发生变化时，连同相关实现、说明和验证项一起更新。
3. 在用户授权的配置同步范围内，将原文完整复制到现有 CyberTrack 智能体的“角色介绍”，保存后重新打开，逐字核对（仅忽略末尾换行）。不要覆盖昵称、音色、模型或设备绑定等无关配置。平台操作与 Git 提交、推送分别遵循用户授权。
4. 平台直接修改也必须回存同一文件，并先比较差异；有两边并行修改时合并语义，不盲目覆盖任一侧。禁止只在控制台维护正式版本。
5. 按平台提示重启设备加载配置，再做相关语音回归。记录提示词 Git 提交或 SHA-256、固件版本、验证日期、受测表达、工具回执和用户现场观察；区分“仓库已修改”“平台已核对”“设备已验证”。

纯角色调整通常无需烧录；提示词不会自动随固件构建部署到灵矽。固件工具描述也是模型输入，变更时应检查与角色规则的冲突。ct6 工具描述与角色统一为明确动作未说时长时传入 `duration_ms=1000`；本轮已记录指定时长、四方向、状态／停止、否定及单向互斥；默认时长、上限等完整语音回归仍待补齐。提示词不能取代固件参数校验、截止计时、BOOT 提前停止和断线停止。

## 语音回归清单

下表是预期，不是已通过记录。动作相关测试先保持 L298N 12 V 和 MOS 5 V 功率供电均断开，结合工具回执和设备日志核验；仅查看聊天回复不足以证明工具执行。带载测试另按[喷水验证记录](audio-water-validation.md)准备和记录。

| 用户表达／场景 | 预期行为 |
|---|---|
| “你叫什么名字？”／“小D” | 自称小D或简短回应，不调用动作工具 |
| 单纯唤醒／呼唤连续数次 | 每次只用一句自然回应，适当变化，不连读多条例句，不调用状态或动作工具，不声称已自检 |
| 唤醒并说“发射”／“检查状态” | 直接处理请求，不先加问候；动作仍只作一次简短确认，状态先查询再回答 |
| 待命／主动停止后／多路活动／持续动作／狂暴模式的状态查询 | 按最新回执自然组织一到两句；待命不等于硬件全部正常，活动通道分别报时，持续动作不编造截止时间，狂暴模式按模式字段报告 |
| 状态查询失败／冷却／故障／缺少电量或液位数据 | 如实说明，不用“准备好了”等话术掩盖异常或编造数据，不主动重复查询 |
| “查询状态” | 调用状态工具，依据最新回执简短回答，无喷水调用 |
| “喷水”／“喷一下”／“再喷水” | 一次水工具调用，明确传入 1000 ms，不追问、不沿用上次时长 |
| “喷水七秒”／“喷水半秒” | 分别传入 7000／500 ms，按实际接受的时长回应 |
| “喷水四十秒” | 只请求 30000 ms，说明单次最多三十秒，不分段续喷 |
| “停止”／“停止所有动作” | 立即调用停止，不先查询；再查状态应与停止回执一致 |
| “不要喷水”／“现在有没有喷水？”／明显背景谈话 | 不触发喷水；状态问句只查状态 |
| “停止说话” | 结束回复，不误作喷水请求 |
| “前进”／“后退半秒”／“左转”／“右转五秒” | 一次 move，分别 forward/1000、backward/500、left/1000、right/3000；最后一个说明三秒上限 |
| “向前一米”／“左转九十度” | 说明只能按时间控制，请用户给出时长，不擅自换算 |
| “边走边喷” | 一次 move_and_water，默认 forward、两路各 1000 ms；成功后确认各自时长 |
| 行走中请求喷水／喷水中请求行走 | 只请求另一通道，已有动作的时长和输出不变 |
| 同路仍活动时重复请求／组合请求遇一路忙碌 | 拒绝，不续时、不换向、不部分执行或补做 |
| “不要前进”／“现在在转吗？” | 不触发行走，后者只查状态 |
| “吹泡泡”／“点火” | 分别调用 bubbles／ignition，默认 1000 ms；明确请求才动作，不能把工具接受当成实测出泡或火花 |
| “发射”／“开炮”／“放电”（含“一下”） | 分别按喷水／吹泡泡／点火理解，调用 water／bubbles／ignition，各一次 1000 ms |
| “发射三秒”／“开炮十秒”／“放电两秒” | 分别请求 water/3000、bubbles/10000、ignition/2000 |
| “发射四十秒”／“开炮四十秒”／“放电八秒” | 分别限为 30000／30000／5000 ms，说明上限，不分段或续时 |
| “停止发射”／“停止开炮”／“停止放电” | 立即调用统一 stop，不先查询或启动动作 |
| “不要发射”／“不要开炮”／“不要放电” | 不启动任何动作 |
| “还在发射吗”／“开炮结束了吗”／“现在在放电吗” | 仅调用状态工具，按对应通道实际回执回答 |
| “发射是什么意思”／引用或背景谈话中的“开炮”“放电” | 不触发动作；不把别名理解为其他能力或狂暴模式 |
| “前进并发射” | 一次 move_and_water，forward、两路各 1000 ms；不得额外启动点火 |
| “吹泡泡八秒”／“点火八秒” | 泡泡请求 8000 ms；点火仅请求 5000 ms 并说明上限、不分段，停止后等实际通电时长的间隔内拒绝新点火 |
| “不要吹泡泡”／“现在在点火吗？” | 不启动；状态问句只查询 |
| “发射”／“开炮”／“放电”成功回执 | 分别只说一次“好，发射一秒。”／“好，开炮一秒。”／“好，放电一秒。”；使用原名时按原名回复，调用前不预先确认，结束后不重复播报 |
| 一次请求多种动作／同一请求出现重复回执 | 汇总为一句；不逐工具重复确认，不因重复回执再次执行或播报 |
| “发射四十秒”成功／“停止”成功 | 分别只说“最多三十秒，发射三十秒。”／“已停止。”，不再另加普通确认 |
| 网页在线但没有动作时发出语音指令 | 不因网页在线自行拒绝，按正常规则调用工具并检查回执 |
| 网页持续行走／喷水／泡泡期间语音查询状态 | 根据非零 hold_id 说明对应动作持续运行，不把短租期读作总剩余时间或承诺即将结束 |
| 网页占用同路时语音请求／持续动作期间语音停止 | 依据实际回执简短说明占用，不自动补做；停止始终直接调用统一 stop |
| 工具拒绝、超时或结果不确定 | 不声称成功，不自动重试；不把指令接受说成实测出水 |
| 行走或喷水中按 BOOT，随后松开 | 本地提前停止且不恢复，以设备和现场结果为准 |

所有回答保持简短、与机器人角色相关；不出现“已开启输出”“已关闭输出”等面向用户的工程话术。无需每次修改都重跑全表，按改动选择相关用例；改变动作理解或参数映射时，至少覆盖状态、默认时长、指定时长、上限、停止和否定表达。
