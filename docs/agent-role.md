## 维护源与名称

完整角色介绍的唯一维护源为 [role-prompt.txt](../firmware/esp32-audio/role-prompt.txt)，已纳入 Git 跟踪。该文件是可直接粘贴到灵矽“角色介绍”字段的 UTF-8 纯文本，不添加版本标题、维护说明或测试记录。版本和差异由 Git 管理；本页记录维护流程，其他文档只链接原文，不复制正文。

| 项目 | 当前约定 |
|---|---|
| 灵矽智能体管理名称 | CyberTrack，原名“彩菊”，沿用现有面包板绑定 |
| 助手昵称 | 小D，角色中的 `{{assistant_name}}` 对应平台昵称 |

历史联调中的“彩菊”指当时的智能体名称，不批量改写历史证据。ct2 阶段的音色名称“彩菊姐姐”与智能体名称是不同配置，当时未随重命名修改；后续音色变更见版本沿革，最新平台回读为“少年梓辛/Brayan”。

ct55 在调速票据被拒绝时提供请求时刻的未移动、Wi-Fi 离线、语音链路离线或关机状态。选择错误信息与请求票据共用控制锁，其他拒绝保留通用说明。角色按明确回执回答，模糊错误不能推断具体原因。[构建检查](../firmware/esp32-audio/verification-ct55.json)

ct62 候选在设备端按识别输入隔离失败：本轮失败后拒绝后续动作、调速与改稿，查询和停止可用，新输入恢复。角色仍须解释拒绝、不自动重试；新增防护不能代替首个工具的意图判断或抑制虚假回复。角色源与公开工具参数保持不变，未新增平台保存或设备部署。[验证与限制](validation/voice-input-guard.md)

ct61 播放策略扩展明确时长的喷水／泡泡短句，要求本次唯一工具参数、成功回执的操作与时长均匹配。支持的时长书写范围见验证记录，未知或多意图原话保留语音；超限和时长不符不会静默。喷水说明同时区分 1 ms 下限和未指定时的 1000 ms 默认值。[构建检查](../firmware/esp32-audio/verification-ct61.json)

ct60 的泡泡工具说明强调先将超三十秒请求的参数设为 30000，不能以口头说明上限代替合法参数。设备端范围校验继续拒绝越界，捕获工具可用同段 MCP 校验代码核对参数。[构建检查](../firmware/esp32-audio/verification-ct60.json)

ct59 的状态查询增加 `draft_status_facts`，按当前草稿状态说明已有或没有已保存草稿，并指出该查询没有产生保存、修改或取消回执。字段仅随状态查询返回，保存回执仍以操作结果与新版本为准。[构建检查](../firmware/esp32-audio/verification-ct59.json)

ct58 的编排工具说明明确区分查询、提交和保存回执。只有本次实际收到 `draft_saved` 与新版本才可说已保存，取消必须取得 `draft_cancelled`；未提交不能声称完成。平台行为按独立回归记录核对。[构建与主机检查](../firmware/esp32-audio/verification-ct58.json)

ct57 将绝对与相对调速的票据拒绝作为明确的工具结果返回。传输 `isError=false`，内部 `result=rejected`，不能判断为动作成功。未分配票据时直接返回，不进入动作回调。原有角色源和接受条件继续适用。[构建检查](../firmware/esp32-audio/verification-ct57.json)

ct56 的调速工具说明要求按明确错误中的状态解释，通用错误只说明未确认，拒绝后不建议试动。线上回复另见[原因解释对照](validation/speed-rejection.md)。

ct54 的调速工具说明区分单独“全速”和“全速前进”。单说“全速”等四种明确短句时，设备核对本轮调速请求、100% 目标、成功回执中的实际设置和故障字段，再抑制随后的语音确认。多工具调用、提前开始的回复及拒绝继续交给播放通道。[候选构建与检查](../firmware/esp32-audio/verification-ct54.json)

ct51 候选在设备播放端识别明确的全停短句，包括“停止行走”“取消序列”和“取消正在执行的表演”。只有当前调用、回执操作和成功结果匹配，且无异常时，才抑制后续确认音频。“不要取消序列”、取消未开始的草稿、故障或尚未收到成功回执的回复继续交给播放通道。[候选构建与检查](../firmware/esp32-audio/verification-ct51.json)

## 修改与平台同步

1. 先编辑 `role-prompt.txt`，说明要改善的行为，并检查工具名称、参数、单位和回执字段是否与[面包板实现](../firmware/esp32-audio/README.md)一致。语气优化不能无意改变执行条件、时长或停止语义。
2. 审阅原文差异。保留真实回执优先、失败不自动重试、普通动作默认一次 1 秒（100% 速度的左右转默认 880 ms）、狂暴模式默认 5 秒；行走按指定时长（协议整数毫秒范围 1–2147483647）、喷水／泡泡及狂暴模式最多 30 秒、点火最多 5 秒、四路独立计时、同路忙碌拒绝、本地停止优先和未接入能力不假装执行等约束。实际能力发生变化时，连同相关实现、说明和验证项一起更新。
3. 在用户授权的配置同步范围内，将原文完整复制到现有 CyberTrack 智能体的“角色介绍”，保存后重新打开，逐字核对（仅忽略末尾换行）。不要覆盖昵称、音色、模型或设备绑定等无关配置。平台操作与 Git 提交、推送分别遵循用户授权。
4. 平台直接修改也必须回存同一文件，并先比较差异；有两边并行修改时合并语义，不盲目覆盖任一侧。禁止只在控制台维护正式版本。
5. 按平台提示重启设备加载配置，再做相关语音回归。记录提示词 Git 提交或 SHA-256、固件版本、验证日期、受测表达、工具回执和用户现场观察；区分“仓库已修改”“平台已核对”“设备已验证”。

纯角色调整通常无需烧录；提示词不会自动随固件构建部署到灵矽。固件工具描述也是模型输入，变更时应检查与角色规则的冲突。ct6 历史变更曾将工具描述与角色统一为明确动作未说时长时传入 `duration_ms=1000`；该阶段已记录指定时长、四方向、状态／停止、否定及单向互斥；跨动作互斥已被 ct7 并发取代；默认时长、上限等完整语音回归仍待补齐。提示词不能取代固件参数校验、截止计时、BOOT 提前停止和断线停止。

### ct28 测距语音待测

- “前面有多远／测一下距离”：仅 `get_status({})`；有效毫米值换算厘米并报“大约”，不触发动作。
- 无回波、未接模块、信号异常、数据超过 500 ms、旧固件缺字段：答暂时没有有效距离，不沿用上一轮数字，不说前方畅通。
- “前面有障碍就停”：说明在网页开启自动避障；不声称已切换。“自动绕开”：说明无自动绕行，不建立动作循环；明确“停止”仍直接调用 stop。
- 网页开关关闭／开启后分别语音请求前进、边走边喷和含前进的序列：按同一设备状态执行；开启时近距离拒绝／停止前进，独立效果保留。关闭及距离恢复不补做旧动作。
- 待机、后退、转向或前进锁定时，分别开启／关闭自动避障并靠近物体：设备只按有效距离滴声，云端不重复提醒；仅开启时停车，关闭后旧动作不恢复。
- “自动避障开了吗”：只查 get_status，按 proximity.auto_avoidance_enabled 回答；缺字段不猜。
- 行走中询问距离不续时、不换向；否定、引用、背景谈话不启动动作。原停止、全速和组合规则保留；平台保存回读及设备重启完成，口述回归待做。
