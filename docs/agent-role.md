# CyberTrack 智能体角色与提示词

仓库角色配套 ct79，最近部署和平台回读见[当前状态](current-status.md)。ct78 合成语音完整集留下的调速漏调用与否定尾句丢失，仍需在候选角色上复验。[失败样例](validation/ct78-stop-duration.md)

## 维护源与名称

完整角色介绍的唯一维护源为 [role-prompt.txt](../firmware/esp32-audio/role-prompt.txt)，已纳入 Git 跟踪。该文件是可直接粘贴到灵矽“角色介绍”字段的 UTF-8 纯文本，不添加版本标题、维护说明或测试记录。版本和差异由 Git 管理；本页记录维护流程，其他文档只链接原文，不复制正文。

| 项目 | 当前约定 |
|---|---|
| 灵矽智能体管理名称 | CyberTrack，原名“彩菊”，沿用现有面包板绑定 |
| 助手昵称 | 小D，角色中的 `{{assistant_name}}` 对应平台昵称 |
| 固件唤醒词 | “你好小智”；更改管理名称或昵称不会更改唤醒词 |
| 角色 | 机灵、友好、利落的双履带机器人小助手，主要响应指令、报告状态 |
| 当前能力 | ct79 源码为九个工具，含三路独立控制和序列，支持网页与语音并用；见[当前接口](../firmware/CAPABILITIES.md#当前面包板接口)，分项证据不等于完整现场回归 |

## 修改与平台同步

1. 先编辑 `role-prompt.txt`，说明要改善的行为，并检查工具名称、参数、单位和回执字段是否与[面包板实现](../firmware/esp32-audio/README.md)一致。语气优化不能无意改变执行条件、时长或停止语义。
2. 审阅原文差异。保留真实回执优先、失败不自动重试、普通动作默认一次 1 秒（100% 速度的左右转默认 880 ms）；行走按指定时长（协议整数毫秒范围 1–2147483647）、喷水／泡泡最多 30 秒、三路独立计时、同路忙碌拒绝、本地停止优先和未接入能力不假装执行等约束。实际能力发生变化时，连同相关实现、说明和验证项一起更新。
3. 在用户授权的配置同步范围内，将原文完整复制到现有 CyberTrack 智能体的“角色介绍”，保存后重新打开，逐字核对（仅忽略末尾换行）。不要覆盖昵称、音色、模型或设备绑定等无关配置。平台操作与 Git 提交、推送分别遵循用户授权。
4. 平台直接修改也必须回存同一文件，并先比较差异；有两边并行修改时合并语义，不盲目覆盖任一侧。禁止只在控制台维护正式版本。
5. 按平台提示重启设备加载配置，再做相关语音回归。记录提示词 Git 提交或 SHA-256、固件版本、验证日期、受测表达、工具回执和用户现场观察；区分“仓库已修改”“平台已核对”“设备已验证”。

纯角色调整通常无需烧录。设备端参数校验、超时与本地停止由固件实施。

## 语音回归清单

先断开执行器功率，用本轮识别、工具参数、回执和播放记录核对下列预期。真人拾音和实物动作另记。[观察单与评分方法](validation/README.md#语音工具选择)

| 场景 | 核对重点 |
|---|---|
| 唤醒、呼唤、普通对话 | 自称小D，简短回应。普通对话不触发动作。 |
| 明确、共享和默认时长 | “左转一秒”为 1000 ms，“右转，同时喷水两秒”两路均为 2000 ms。省略时长的全速转向为 880 ms。 |
| 调速与序列 | 运动中“快一点”调整当前速度，保留截止时间。核对同一步并发、多步先后、冷却与取消。 |
| 否定、引用、预览与含糊表达 | “先别执行”应保持静止。核对转写是否保留否定尾句。明确停止动作须直接全停，单纯“停止说话”只结束回复。 |
| 效果别名和退役请求 | “发射”对应喷水，“开炮”对应泡泡。遇到退役效果整单拒绝。单次喷水或泡泡超过 30 秒须说明限幅。 |
| 状态、测距与网页长按 | 按当前回执作答。距离过期时说明缺少有效读数。分别核对动作剩余时间、长按租期和真实执行反馈。 |
| 成功、拒绝与恢复 | 成功动作按角色约定静默，拒绝或异常要说明。同一轮失败不重试，新输入可恢复，本地停止优先。 |

## 回滚

通过 `git log -- firmware/esp32-audio/role-prompt.txt` 查看历史，提取需要的旧版本并与当前原文比较。确认仍兼容当前固件工具和动作限制后，按上述同步流程恢复平台配置并验证；不要为回滚提示词重置整个工作区或设备配置。已保存的旧提示词不代表与新固件自动兼容。
