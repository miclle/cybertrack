# 泡泡枪与双点火线圈控制

核对日期：2026-10-27。当前源码与最新有记录的部署为 `2.0.3-ct21`。面包板已实现并部署四路独立控制、喷水／泡泡长按，以及网页／语音狂暴模式；泡泡定时上限为 30 秒，点火单次最多 5 秒、停止后至少间隔本次实际软件 ON 时长。下文先列当前规则，再保留历史验证记录。

2026-10-25 用户要求泡泡枪和点火线圈接入现有面包板 ESP32-S3，使用水枪同款 P01／JZ-MOS；两只点火线圈共用一块 MOS、5 V 供电，单次最多五秒，四路功能不互斥。这是低压控制实现边界，高压接线、绝缘、液体共存、EMC 与安全验收仍未完成。最新部署与四方向现场反馈见[ct21 记录](../firmware/esp32-audio/startup-ct21.json)。

## 通道与引脚

| 动作 | 源码控制引脚 | 语音默认／最大单次 | 停止后操作间隔 | 功率侧证据与缺口 |
|---|---|---|---|---|
| 行走 | GPIO8–13；B／左、A／右，约 80% PWM | 1 秒／3 秒；网页长按另有短租期 | 200 ms | ct21 四方向获用户正常反馈；定量速度、停止距离、电流／温升未验收 |
| 水枪 | GPIO18 | 1 秒／30 秒；网页支持长按 | 200 ms | MOS→降压至 3.7 V 支路已有短时喷水及 ct7 并发分项记录；当前电源与完整负载仍待验证 |
| 泡泡枪 | GPIO17，独立一块 P01 | 1 秒／30 秒；网页支持长按 | 200 ms | 用户确认工作电压 3.7 V，已有样机出泡影像；逐线核对、降压／MOS 适配及完整电气验收仍待完成 |
| 两只点火线圈 | GPIO21，共用一块 P01、同时启停 | 1 秒／5 秒；无长按持续接口 | 至少等本次实际软件 ON 时长 | 用户指定 5 V；两只总电流、启动瞬态、开关适配与高压验收尚未完成 |

GPIO17／21 在固定版本 `bread-compact-wifi/config.h` 的音频、显示、按钮分配及原电机／水枪驱动中未占用，低压控制源码已部署。实际引出脚、排针和完整布线尚未独立逐线核对，不能从其他型号开发板推定针位。软件初始化先写低再配置输出；启动之前、复位期间真实电平和 MOS 悬空关断仍须独立验证。影像中的出泡不证明 GPIO、电源或版本配置全部核实。

三块 P01 分别用于水枪、泡泡和两只点火线圈；“双 MOS”是一路并联开关，并非两个独立通道。原水枪短时成功不证明新负载适配。等长点火间隔不是热保护或厂家允许占空比；软件时长包含调度误差，无电气通电时长反馈。泡泡三十秒及长按能力也不代表持续运行验收。

## 四路独立与统一停止

- 普通定时动作四路可同时运行，每一路有独立截止、间隔和来源；启动／结束泡泡或点火不重启其他输出。
- 普通同路定时请求不续时、不叠加、不排队；到期不自动循环。网页行走／喷水／泡泡长按通过有效租约维持，松开只停本路；语音不提供长按续租，点火不提供持续接口。
- 狂暴模式须四路均就绪，总时长 1–30000 ms：左转、喷水、泡泡持续，点火每次最多 1000 ms，关闭后至少等实际软件 ON 时长再启动下一脉冲。末尾脉冲不越过模式总截止，重复请求不续期；该明确模式是有界循环，普通动作不自动升级为模式。
- BOOT、语音停止、网页全部停止、Wi-Fi 断开、重启／OTA 入口、输出故障及时钟异常关闭全部通道并取消待执行请求；释放按键和恢复网络不恢复旧动作。GPIO API 失败锁定故障并尽力关断，不保证故障器件的物理断开。
- 网页可抢占同路普通语音动作，但先停止并等待本路间隔，需再次手动发起；语音不能覆盖同路网页动作。网页普通动作抢占语音狂暴模式时取消整个模式并返回 `voice_preempted`，不部分保留或自动启动；网页狂暴请求须四路就绪。
- 网页离开／心跳失效只停止网页来源动作；语音会话断开只停止语音来源动作，模式按来源取消。行走长按失租撤销所有网页来源动作；喷水／泡泡失租只停本路。全局停止覆盖所有来源。

## 接口与角色

MCP `self.tank.bubbles({"duration_ms":1000})` 接受整数 1–30000，`self.tank.ignition({"duration_ms":1000})` 接受整数 1–5000；仅允许 `duration_ms`，拒绝缺参、多参、重复键、注入票据、非整数及越界。角色在明确普通动作但缺少时长时填 1000 ms，超限只请求对应上限并说明，不分段；固件不自行补参或截断。

`self.tank.frenzy({"duration_ms":5000})` 接受整数 1–30000，角色默认 5000 ms；与网页使用同一有界模式。`move_and_water` 仍是行走／喷水两路原子组合；其他分别发出的普通动作不保证全部接受，狂暴模式须四路就绪后整体启动。

HTTP `/api/action` 的 `bubbles/ignition/frenzy` 使用 `operation/sequence/window/duration_ms`，范围同上；喷水／泡泡另有 `start/renew/stop` 长按接口。网页喷水／泡泡各有 1／3／5／10／30 秒及按住持续，点火有 1／3／5 秒，狂暴模式有 5／10／30 秒。租约、来源与全部请求字段见[局域网控制](lan-control.md#http-契约)。

状态包括 `logical_outputs.water/bubbles/ignition` 及各路计时、间隔和来源；能力包含 `bubbles/ignition/water_hold/bubbles_hold/frenzy`。`remaining_ms` 为四路最大剩余值，模式另读 `frenzy_remaining_ms/frenzy_last_duration_ms/frenzy_source`，不按点火 ON/OFF 判断模式结束。`starts_this_boot` 是软件启动计数，后端为 `concurrent_motor_effects_bench`，`physical_feedback=false`；回执不代表出泡、火花或实体停止反馈。完整字段见[当前接口手册](../firmware/CAPABILITIES.md#当前面包板-ct21-接口)。

[角色源](../firmware/esp32-audio/role-prompt.txt)按[角色同步流程](agent-role.md)维护；2026-10-27 别名、纠错与成功静默规则已保存并回读，真人语音回归仍待完成。仅明确点火／火花或明确狂暴模式请求可选择相应工具，不从其他普通动作或含糊效果请求推断点火；状态、否定句和背景谈话不启动动作。角色默认值和话术不能代替固件限制。

## ct13 历史部署与验证（2026-10-25）

ct13 在用户确认四路功率断开、仅 USB 供电后完成实机逻辑测试，未进行新模块接线或通电验收。以下五秒泡泡与固定三秒点火间隔仅属当时配置，已分别被 ct14 与 ct17 替代；原始测试结果保留。

软件证据见 [ct13 验证记录](../firmware/esp32-audio/verification-ct13.json)。覆盖四路并行与独立截止、1／5000 ms 边界、重复／超时请求、间隔、全部停止及来源隔离、输出 API 失败注入、真实 MCP／HTTP 参数校验及实际网页脚本竞态。构建使用固定 ESP-IDF v5.5.1、导出目录 `build/xiaozhi-ct13-src` 和输出目录 `build/firmware-ct13`。

已核对设备、备份并仅写应用分区，前 128 KiB 配置区逐字节保持。实机 HTTP／串口确认四路并行、独立截止、重复点火不续时、停止后 3 秒间隔、全部停止、网页释放及心跳失效关闭、重连不恢复；未测量 GPIO 波形。5 秒点火请求记录的 `software_on_ms=5002`，存在调度延迟，不能认定严格不超过 5 秒的硬件截止。ct13 当时尚缺泡泡单支路实物证据；目前已有出泡影像，但未绑定完整版本／电源配置，定量参数、提前停止、复位及故障关断仍需对应记录。点火的正式模块参数、两只模块并接的开关适配、绝缘／液体共存／EMC、独立切断及四路电源预算仍未验收；该阶段未提供高压电极或高压接线方案，未安排点火通电测试。用户指定 5 V 和 ≤5 秒不构成高压输出安全证据，也不能沿用旧电源验收。

## ct14 更新：泡泡与喷水统一操作

历史 ct14 变更：用户要求增加长按持续并统一时长，泡泡定时上限改为 30 秒，默认 1 秒、停止间隔 200 ms；五秒泡泡规则只属于 ct13 历史。两路各提供五个定时按钮和一个持续按钮，长按通过独立短租期连续运行，松开只停本路。点火不增加持续入口，当时保持 5 秒／3000 ms 规则，固定间隔随后由 ct17 替代。协议与失联处理见[局域网控制](lan-control.md#ct14-喷水泡泡六按钮与长按)。

## ct17 等长间隔与狂暴模式

用户后续将点火间隔改为本次实际通电时长，替代历史固定 3000 ms；软件从点火接受至关闭 tick 计算时长，提前停止同样计算，重复停止不改变已建立的截止。普通单次点火最多 5000 ms。狂暴模式以 1000 ms 点火／至少等长间隔配合持续左转、喷水和泡泡，整体最多 30000 ms。该循环是明确网页模式的有界行为，语音单项调用仍不自动循环。

ct17 已完成低压 MOS 控制软件的构建与部署，见[部署记录](../firmware/esp32-audio/startup-ct17.json)；该次未启动执行器。等长间隔不是厂家占空比、电流或热保护证据。软件时长含调度误差，没有电气通电时长反馈；不新增高压接线、带载或通电火花验收。

## ct18 语音入口

历史 ct18 变更：同一有界模式新增语音启动，默认五秒、最长三十秒；点火脉冲与等长关闭间隔不变。模式来源隔离、语音断连和票据取消由固件处理，不用提示词取代控制限制。此扩展不新增带载或高压验收。

ct18 已仅应用烧录并保存平台角色，启动／联网和模式字段已核对，检查时动作启动次数为零；真人口述狂暴及完整带载仍待验证，见[部署记录](../firmware/esp32-audio/startup-ct18.json)。后续 ct20 提高电机 PWM、ct21 修正桥映射，当前模式沿用上文约 80% PWM 与 B／左、A／右，不沿用旧版本的完整验收结论。
