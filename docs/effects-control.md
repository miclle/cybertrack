# ct13 泡泡枪与双点火线圈控制候选

2026-10-25 用户要求泡泡枪和点火线圈接入现有面包板 ESP32-S3，均使用水枪同款 P01／JZ-MOS。用户进一步确认两只点火线圈共用一块 MOS、直接使用 5 V 电源、单次最多 5 秒，并明确所有功能之间不互斥。本次范围为固件候选、网页／语音接口和软件验证；未刷写、未同步平台角色、未接线或通电。当前已部署记录仍为 ct12。

## 通道与引脚

| 动作 | 候选控制引脚 | 语音默认／最大单次 | 停止后操作间隔 | 功率侧证据 |
|---|---|---|---|---|
| 行走 | GPIO8–13，保持原分配 | 1 秒／3 秒；网页维持长按短租期 | 200 ms | 原 L298N 台架证据不扩展为新电源或四路同时负载验收 |
| 水枪 | GPIO18，保持原分配 | 1 秒／30 秒 | 200 ms | 原 MOS→降压至 3.7 V 支路保持 |
| 泡泡枪 | GPIO17，独立一块 P01 | 1 秒／5 秒 | 200 ms | 用户确认工作电压 3.7 V；独立 MOS、降压及真实负载待验证 |
| 两只点火线圈 | GPIO21，共用一块 P01、同时启停 | 1 秒／5 秒 | 3000 ms | 用户指定 5 V；两只总电流、启动瞬态及开关适配尚未验证 |

GPIO17／21 在本机已固定版本 `bread-compact-wifi/config.h` 的音频、显示、按钮分配以及现有电机／水枪驱动中未占用；这里只完成源码分配，实际引出脚、排针和布线须先核对。不接线、不从其他型号开发板推定针位。软件按现有 P01 高电平启用方式实现，初始化先写低再配置输出；启动之前、复位期间的真实电平和 MOS 悬空关断仍须独立验证。

三块 P01 分别用于水枪、泡泡和两只点火线圈；“双 MOS”是一路并联开关，并非两个独立通道。原水枪短时成功不能证明新负载适配。3000 ms 点火操作间隔为用户指定的停止后最短间隔，不是热保护或厂家允许占空比；泡泡的 5 秒上限也是联调限制，不代表连续运行验收。

## 四路独立与统一停止

- 四路可同时运行，互不排斥；每一路有独立截止、间隔和来源。启动／结束泡泡或点火，不脉冲或重启其他输出。
- 同一路活动时拒绝再次启动，不延长、不叠加、不排队；到期不会自动循环。间隔结束后仍需新的明确指令。
- BOOT、语音停止、网页全部停止、Wi-Fi 断开、重启／OTA 入口、输出故障及时钟异常关闭全部通道并取消待执行请求；释放按键和恢复网络不恢复旧动作。GPIO API 失败锁定故障并尽力关断，不能保证故障器件的物理断开。
- 网页和语音保留 ct12 的按通道来源规则：网页可抢占同路语音，但先停止并等待本路间隔，必须再次手动发起；语音不能覆盖活动中的同路网页动作，其他路不受影响。
- 网页离开／心跳失效只停止网页来源的动作；语音会话断开只停止语音来源动作；全局停止覆盖所有来源。网页松开方向键只停行走，原行走租期失效仍撤销网页来源动作。

## 接口与角色

新增 MCP：`self.tank.bubbles({"duration_ms":1000})`、`self.tank.ignition({"duration_ms":1000})`。两者均要求唯一的整数参数 `duration_ms`，范围 1–5000，拒绝缺参、多参、重复键、注入票据、非整数及越界。默认值由角色在明确动作但缺少时长时填写，固件不补缺参。超过五秒由角色限为五秒并说明，不分段。

HTTP `/api/action` 新增 `operation=bubbles/ignition`，字段为 `operation/sequence/window/duration_ms`，沿用单次窗口和序号规则。网页新增各自 1／3／5 秒选择、动作按钮及状态。多路分别启动可以重叠，但没有包含新效果的原子组合工具；保留原 `move_and_water`，不承诺分别调用全部成功。

状态新增 `logical_outputs.ignition`，启用 `capabilities.bubbles/ignition`；两种效果各新增 `*_last_duration_ms`、`*_remaining_ms`、`*_cooldown_ms`、`*_source`、`*_max_duration_ms`。`remaining_ms` 为四路最大剩余值；`starts_this_boot` 累加每路接受次数。后端标识为 `concurrent_motor_effects_bench`。回执和日志都不代表实际出泡、火花、停止延迟或安全验收。

[角色源](../firmware/esp32-audio/role-prompt.txt)已更新；按[角色同步流程](agent-role.md)部署后才能记为平台生效。仅明确点火／火花请求才调用点火工具，不从其他动作或含糊的“来个效果”推断。状态、否定句和背景谈话不启动任何动作。

## 验证与后续

软件证据见 [ct13 验证记录](../firmware/esp32-audio/verification-ct13.json)。覆盖四路并行与独立截止、1／5000 ms 边界、重复／超时请求、间隔、全部停止及来源隔离、输出 API 失败注入、真实 MCP／HTTP 参数校验及实际网页脚本竞态。构建使用固定 ESP-IDF v5.5.1、导出目录 `build/xiaozhi-ct13-src` 和输出目录 `build/firmware-ct13`。

部署前核对设备和引脚，保持功率负载断开验证控制信号；新固件和平台角色需同步，保留原配置备份。之后泡泡单支路出泡、提前停止、复位及故障关断需要实物证据。点火的正式模块参数、两只模块并接的开关适配、绝缘／液体共存／EMC、独立切断及四路电源预算仍未验收；本次不提供高压电极或高压接线方案，不安排点火通电测试。用户指定 5 V 和 ≤5 秒不构成高压输出安全证据，也不能沿用旧电源验收。
