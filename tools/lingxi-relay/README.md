# 模型工具轮播报中继原型

针对工具调用前的操作旁白，CyberTrack 提供一个可独立运行的本地 Chat Completions 中继原型：先取得上游完整回复，带工具调用的一轮仅返回原工具调用，普通最终回复继续返回文字。代码位于 [lingxi_llm_relay.py](../../scripts/lingxi_llm_relay.py)。

这是开发验证入口，尚未绑定灵矽或部署到云端。当前设备仍按既有链路直连灵矽，固件、十二项工具与角色均未改。

## 完整一轮后再放行

| 上游结果 | 中继行为 |
|---|---|
| 完整 `tool_calls` 轮，含普通过程文字 | `content=null`，工具 ID、顺序、名称及参数字符串原样保留 |
| 无工具的正常最终回复 | 原文字保留，包括查询、限制、拒绝和澄清 |
| 截断、矛盾的结束标志、非法参数编码 | 返回明确错误，不发送部分工具调用，不重试 |
| 非空结构化推理字段 | 拒绝该模式，不删除推理后继续工具，避免损坏模型所需历史 |
| 上游 HTTP 错误、超时或重定向 | 返回通用错误，不转发敏感错误正文、不重试或跟随跳转 |

请求中的消息、工具定义、工具选择与工具结果历史不改写。仅映射配置中的模型名，将上游调用设为非流式并移除流式选项；客户端需要 SSE 时，从完成验证的结果生成流及 `[DONE]`，可带 usage。原型一次只支持一个生成结果和文本／函数工具调用。

带工具轮的过程文字与工具之后最终回复里的规则分析必须分开验收。后者仍作为普通 `content` 放行；本原型没有语义分类器，不能声称已经解决 C005／C008，也不按英文、关键词或设备表情过滤回复。

带工具轮中的必要限制文字也会被移除；如果模型没有在工具回执后的最终回复重述限制，就会丢失提示。已有设备边界记录没有上游完整消息，不能判断原 V020 的限制来自哪一轮。此项与最终回复规则分析均是采纳前必须解决／验证的门槛，当前原型尚不能替换线上链路。

整轮缓冲会增加首个工具或首句的等待，具体增量尚未实测。线上采纳前必须测工具到达、明确停止、首句和完成时间，不能只凭静音效果采纳。本地 BOOT 和设备截止仍由原固件独立处理。

## 先做完全本地的验收

```sh
python3 -m unittest discover -s tests/improvements -p test_llm_relay.py -v
```

测试启动随机本地端口的上游夹具与中继，结束时关闭。包括两轮真实 HTTP 工具／回执闭环、SSE、完成前无输出、拒绝／限幅保留、截断、认证、重定向和单次错误不重试。夹具不是模型结果，也不调用灵矽、真实模型、麦克风或执行器。

## 在本机连接已有模型服务

复制 [配置样例](config.example.json)到 Git 忽略的本地目录，填写固定 HTTPS `/chat/completions` 地址、真实上游模型名及客户端使用的别名。密钥从样例指定的两个环境变量读取；配置文件中不放密钥。环境变量应在本机私下设置，不粘贴到对话或公开记录。

`disable_thinking=true` 专用于已确认支持 `thinking.type=disabled` 的上游，此时同时移除 `reasoning_effort`；其他供应商先使用其自己的非思考服务配置。不能仅根据灵矽页面上的模型标签断定其原始接口兼容。

```sh
python3 scripts/lingxi_llm_relay.py --config build/private-relay/config.json
```

仅监听 `127.0.0.1:9474`；入口为 `POST /v1/chat/completions`，需使用配置的中继密钥认证。它不建立隧道、不开公网端口、不创建模型绑定、不执行 MCP，也不记录请求、角色、对话或凭据。运行日志只显示本地监听端口。上游固定为配置地址，使用独立密钥、系统 HTTPS 验证，不受客户端请求或环境代理改址。

## 灵矽真实接入前的剩余条件

[灵矽自定义 LLM 指引](https://linx.qiniu.com/docs/xrobot/guide/third-app)支持 OpenAI 接口的模型地址、模型名和密钥。真实联调需用户已有的模型配置，以及灵矽可访问的正式 HTTPS 托管入口；当前脚本的回环地址不能直接给云端使用。本仓库没有自动购买、发布或绑定这一服务。

取得环境后，先验证角色／工具／请求参数是否原样到达上游，再以原 80／8 语料分列工具语义、TTS 文字、音频与时延，覆盖拒绝、超限、停止和断线。思考工具模式的历史保留、真正流式上游、最终回复中的分析、服务可用性与设备听感仍待完成。

协议实现参考 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)的完整消息、工具结束标志与流格式；并不据此证明灵矽内置模型的供应商请求或 TTS 内部实现。
