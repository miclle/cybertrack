## ct2 历史工具语义

- `self.tank.get_status`：读取本板 CyberTrack 控制核心的逻辑状态。初始 `DISARMED`；能力全部关闭，`physical_feedback=false`、`actuator_backend=not_installed`。
- `self.tank.stop`：在同一个序列化主任务内调用 `ct_stop`，进入 `FAULT/stopped` 并清除逻辑输出；重复调用仍保持锁定。不终止 TTS、不禁用屏幕，不声称实体停止或已控制另一台设备。
- 两项工具只接受空参数；额外参数在执行前拒绝，schema 标明 `additionalProperties=false`。不提供 GPIO、喷水、行走、泡泡或重新使能工具。
- 回执带本板 MAC、随机启动标识、单调递增请求序号及运行时间，便于对照平台真实工具调用。状态不会在重新开始对话时自动解除停止；重启后仍为不可动作的 DISARMED。
- 复用 `firmware/src/control.c`，通过 `apply_overlay.py` 复制到临时构建目录，不另写一套动作状态机。

## ct5 历史工具语义

- `self.tank.water` 只接受整数 `duration_ms`，范围 1–30000 ms；不再暴露 permit，不要求长按 BOOT。必须是明确的喷水指令；状态查询不会喷水。角色将秒数转换为毫秒，超过 30 秒按 30 秒执行并说明；明确要求喷水但未说明时长时由角色填写 1000 ms，不追问、不沿用历史请求。工具参数仍必须显式提供 duration_ms，固件不自行补默认值。固件拒绝零、负数、非整数和超出 30000 的参数，不自动分段。
- `get_status` 与 `stop` 只接受空参数。状态报告本板水枪逻辑输出，`local_authorization_required=false`、`physical_feedback=false`。主动停止为 `STOPPED/fault=stopped`，不是硬件损坏；故障仍为 FAULT。
- 复用 `esp32-linx/main/water_policy.c` 的截止与冷却策略，新增 `water_request_timed` 接口允许 1–30000 ms；原 `water_request` 的固定 5000 ms 行为不变，授权函数仅在本地请求执行时原子调用，不作为用户操作门槛。`water_guard.h` 校验网络接收时的就绪状态，并为队列创建内部票据；停止、BOOT、断线取消所有待执行票据，超过 5 秒未执行的请求拒绝。
- 同一音频会话最多记住 128 个喷水 RPC ID，重复 ID 拒绝，不逐出旧 ID；表满拒绝进一步喷水，新会话重新开始。内部票据跨会话不复用；不宣称跨重启持久化防重放。
- 独立优先级 10 控制任务每 5 ms 检查 BOOT、连接与期限。截止由本次 duration_ms 决定，上限 30000 ms，活动时不续时，结束后冷却 1 秒。BOOT 释放需稳定 30 ms；松开或恢复网络本身都不启动动作。
- 停止在网络接收时立即关断，再通过主任务返回回执。已检测的 Wi-Fi／WebSocket 断线、复位与升级均关闭输出。活动输出期间控制任务不进行显示、日志、网络或堆分配。

ct3 的逐次物理授权流程和 ct4 的固定五秒要求已被用户明确取消，历史结果保留在[喷水验证记录](../../docs/validation/bench.md)。用户已确认控制线纠正后喷水测试正常，带载 BOOT 提前停止及松开不恢复也已确认。上述结果属于 ct4 五秒配置；ct5 已通过功率断开的 1／7 秒及 40 秒请求限为 30 秒的语音核验，用户确认音频／屏幕正常，不能推导 30 秒带载已通过。真实断网故障矩阵、独立硬件切断和完整供电验收仍未完成，软件输出回执本身不证明有水流。

## ct6 历史工具与统一控制

- 新增 `self.tank.move({"direction":"forward","duration_ms":1000})`。方向仅接受 `forward/backward/left/right`，整数时长 1–3000 ms，固定 1 kHz／8 bit duty=154（约 60%）。角色默认一秒，超三秒请求三秒并说明；不把距离或角度换算成时间。A 候选左、B 候选右，正负极须按车体前进方向核对，当时不是实车标定；ct21 已修正为 B／左、A／右并取得四方向正常反馈。
- `self.tank.water` 保留 1–30000 ms，未说时长填 1000；工具描述与角色统一。两类动作互斥，共用 128 项会话 RPC 记录、内部票据与截止时间；接受一个动作即取消其他已排队票据，忙碌请求不延迟补做。
- `self.tank.stop`、BOOT、已检测的 Wi-Fi／会话断开、重启／升级入口同时撤销两类动作和待执行票据。BOOT 松开稳定 30 ms 后也不恢复；ct6 原电机停止后冷却 3000 ms、喷水停止后 1000 ms；ct12 将面包板两路统一为 200 ms，必须另有新指令。
- GPIO8–13 为 ct6 的面包板分配，后续部署沿用，与独立台架 GPIO4–9 不同。LEDC timer 2／channel 2、3 避开上游 LED／背光的 timer 0、1／channel 0；原 I2S、OLED 与 GPIO18 不变。
- 切换方向前先关闭两路使能及水枪；任何 GPIO／PWM API 错误锁定 `output_fault`，尝试关闭全部输出并将使能重置为普通 GPIO 低，不自动重试动作。
- 控制任务维持优先级 10、5 ms 周期，活动循环没有显示、网络、日志或堆分配。LEDC API 使用带优先级继承的互斥锁串行化，避免在自旋临界区调用可能取 RTOS 锁的驱动。
- 四工具共用状态：`logical_outputs.left/right` 为 -60/0/60 的逻辑方向与标称占空比，`water` 独立布尔值；`move_direction` 为当前方向或 `none`。`remaining_ms` 和 `last_duration_ms` 对应共享动作，`starts_this_boot` 计两类动作；`max_duration_ms=30000` 保留水枪上限，`move_max_duration_ms=3000` 为电机上限。无编码器、水流或物理停止反馈。
- 网络参数严格拒绝缺参、额外参数、非法方向、非整数值与越界时长。动作只有内部 `result=accepted` 才算接受；硬件 API 失败返回 `output_fault`，接受后尚未应用就被本地条件取消返回 `cancelled_before_output`。上游 MCP 外层成功不足以判定动作成功。

## 平台角色配置

灵矽智能体管理名称为“CyberTrack”（原名“彩菊”），助手昵称为“小D”；设备绑定沿用。角色介绍以仓库中的 [role-prompt.txt](role-prompt.txt) 为唯一维护源，用于灵矽角色配置的“角色介绍”字段，昵称使用 `{{assistant_name}}`。角色为机灵、友好、利落的 CyberTrack 机器人小助手，聚焦动作与状态，通常一句话回答；去掉“开启／关闭输出”等工程话术，不接明显的背景谈话，不展开无关话题。动作和停止成功后静默执行；仅超限调整、失败、拒绝或结果不确定时简短说明，唤醒与状态查询正常回应。动作别名与受限的“饭店→放电”纠错以角色源为准；均检查真实工具回执，未知能力不假装执行。音色和模型保持现有选择。平台提示保存后需重启设备生效；修改昵称不会更改固件唤醒词“你好小智”。提示词不是固件动作限制的替代品。

维护、平台同步、回滚和语音回归要求见[智能体角色与提示词](../../docs/agent-role.md)。不要在其他文档复制整份角色介绍；此处仅概述行为。

平台意图识别已由分离模式调整为统一模式，用于让聊天模型直接选择工具；原分离模式下泛称“查询状态”曾误选通用设备信息工具。统一模式下相同说法已正确调用 CyberTrack 工具，停止和停止后查询也已实测通过；详见验证记录。这是 ct2 阶段的有限样本结果，不保证所有表达方式。

## 历史网页与模式验证

ct8 当时的测试另覆盖网页租约／控制权、来源切换与语音防重放、短时动作窗口、HTTP Host／Origin／鉴权／限流／读取边界与发送失败释放，以及页面模拟设备交互。测试使用实际会话类、JSON 解析器和 HTTP 处理函数；HTTP 传输／显示由桩替代，不能证明真实 Wi-Fi、手机后台或声音连续性。见[当前记录](../../docs/lan-control.md)。

ct9 新增长按 15 秒的软件连续性、600 ms 截止、续租／松开乱序与重放、BOOT 期间不可签发动作窗口、滑出／指针取消／后台及在途请求取消。语音仍限三秒；长按持续带载与真实松开停止时延尚未验收。

## ct17 狂暴模式

历史版本 `2.0.3-ct17`。网页提供 5／10／30 秒模式，持续左转、喷水、泡泡和 1 秒点火／至少等长间隔，整体截止最多 30 秒；四路均就绪后整体启动，全部停止、BOOT、会话失效、断网及故障取消，不自动恢复。普通点火停止后也至少等待本次实际软件 ON 时长，替代历史固定三秒。ct17 当时未增加语音狂暴入口；ct18 随后增加 `self.tank.frenzy`。协议见[网页说明](https://github.com/miclle/cybertrack/blob/c25b0af729bd216b69779db2bba75f32f9475cdd/docs/lan-control.md#ct17-狂暴模式)，源码哈希、构建和主机证据见 [verification-ct17.json](verification-ct17.json)。

ct17 已仅应用刷写并保留配置；启动／联网、实际页面全文一致、能力字段、手机视口及最终全关／释放均已核对。该次部署检查的实机 `starts_this_boot=0`，未触发狂暴或点火，动作时序证据来自主机测试。见[部署记录](startup-ct17.json)。

## ct18 语音狂暴模式

历史版本 `2.0.3-ct18`，新增 `self.tank.frenzy`，默认五秒、单次最多三十秒，参数仅整数 `duration_ms`。与网页共用调度，语音连接关闭取消；网页心跳／释放不控制语音模式。票据重复、过期、取消或同路忙碌不补做，全部停止仍全关。验证与部署分别见 [verification-ct18.json](verification-ct18.json) 和 [startup-ct18.json](startup-ct18.json)。

ct18 已仅应用烧录、保留配置，并在角色保存后重启联网。启动日志含 frenzy 工具，实机状态包含模式来源／时长字段，页面与源码一致，最终全关并释放，动作启动次数为 0。该模式尚未完成真人口述或完整带载验证。见[部署记录](startup-ct18.json)。

## ct19 网页提示修复

历史版本 `2.0.3-ct19`。底部动作成功提示跟随设备最新状态更新，全部结束后显示“动作已结束。”，并行时显示仍在运行的动作；错误／停止提示不被普通轮询覆盖。该次变更的动作后端及角色源与 ct18 一致；后续 ct20／ct21 和角色更新见当前状态。
