# 恢复日志冗余与损坏容错

状态：2026-10-24，板型无关实现与主机故障模拟。此契约扩展[独立恢复日志](RECOVERY-LOG.md)，不改变主快照、锚点四字段或 CTLG v1 单条记录字节；默认输出关闭，本地维护必须退役全部协议所有者。

## 显式配置与资源

`ct_replay_log_init_redundant(log, io, workspace)` 配置四个独立擦除槽，每槽 32816 字节，合计 **131264 字节**。槽 `{0,1}` 与 `{2,3}` 分别组成一组，两组交替使用；同组两槽保存相同的完整记录。回调必须支持索引 0–3，并兑现逐槽擦除、完整传输、跨断电同步和串行所有权契约。不同槽号不能证明真实硬件隔离。

调用方提供独占、全启动期有效的 `ct_replay_log_redundancy` 比较缓冲，大小 **32768 字节**，不能与存储位图或日志 scratch 重叠。模块没有动态分配。macOS arm64 日志对象增加一个指针至 **32872 字节**，启用冗余时连同比较缓冲共 **65640 字节**；存储／协议对象大小不变。初始化只配置，不擦除、登记或维修。

原 `ct_replay_log_init` 继续提供旧双槽模式，单槽损坏容错只属于显式四槽模式。不能在四槽读取或配置失败后自动退回双槽。扩展已有介质必须由本地适配器确认四槽映射及独立性，保留完整主历史和当前锚点，再通过 attach 核验／补齐；不能直接把旧双槽驱动当成四槽驱动。旧固件不具备此保证，实际升级／防降级仍待验证。

## 精确证据与读取

扫描四槽，仅接受与当前锚点的 epoch、后端 ID、数据版本、会话全部匹配且格式、CRC、提交标记有效的记录：

- 一份当前副本完整时，可以容忍另一份被截断、单比特损坏、擦空或不可读。恢复使用完整副本，不拼接残片、不清位、不降低版本。
- 同组两份都有效时，逐字节比较整个防重放位图；相同键对应不同历史即锁定，不投票、不取并集。相同键跨两组出现也拒绝，不能按最大 epoch 或槽位置猜测。
- 无当前完整副本时锁定，即使另一组仍有完整旧历史或未选中候选。读取失败的槽不提供证据；没有任何匹配且存在不可读槽时，也禁止靠补种覆盖未知证据。
- CRC 只检测意外损坏，不认证历史。有效 CRC 的伪造、整体介质／锚点回滚、固件绕过及共同故障域损坏需要平台保护。

容错读取不等于可以在永久坏槽上继续动作：所有新记录仍须两份写入／同步／完整回读成功。目标组不可写或不可读时锁定，保留源组证据供后续本地维护。

## 写入、轮换与补齐

首次登记先将完整初始历史写入两份，再 CAS／回读锚点。已有锚点 attach 核验完整主历史；若同组仅存一份匹配记录，只重写缺失／损坏副本，保留完整副本。已有两份完整相同记录时不写入。补齐中断不会推进锚点；当前对象锁定，重启后重新核验证据。

正常 save 的顺序仍为：准备原历史过渡记录 → 领取尝试 epoch → 准备新候选 → 预留数据版本 → 主快照落盘 → 最终核对锚点。每个日志准备阶段均在另一组依次写入两份：每份擦除、正文、sync、DONE、sync、完整回读，全部成功后才允许推进锚点。准备期间不改写选中组，所以轮换中断再损坏选中组任一槽，仍有另一份精确历史。锚点返回失败可能已经提交；重启始终按实际锚点取源组或目标组。

后端 switch 和 recover_log 同样在目标两个主快照完成后，先持久化两份目标日志，再选择目标。主快照缺失时可使用剩余完整日志恢复到独立空白后端，并在选择新目标前重新建立两份证据。恢复不打开会话、不恢复动作，也不恢复本地使能。

每次改变历史的 save 写 **4 份日志、8 次日志 sync、2 次锚点 CAS**，另有主快照写入与同步；首次登记／目标选择写 **2 份日志、4 次日志 sync**。补齐一份副本写一个槽、两次 sync，不改变锚点；无变化 save 不轮换。容量与时延是接口成本，不是目标 Flash 寿命或停止延迟验收。

## 验证边界

存储测试使用完整位图、部分落盘／未落盘两种故障模式，覆盖单槽损坏、读取失败、过渡与候选轮换、补齐中断、登记／切换／恢复选择、锚点不确定结果，以及损坏叠加主快照丢失。6 组存储测试已通过：352 次单比特损坏、1056 次轮换中断叠加单副本损坏、20 次容错读失败、264 次补齐中断、264 次首次登记中断、528 次目标日志中断叠加损坏、34 次锚点故障叠加损坏和 100 次连续恢复，历史位丢失为 0。4 组协议联测通过：动作／会话各 288 次轮换故障、144 次目标日志故障、24 次锚点故障、36 次主快照故障、8 种损坏场景，以及 100 次连续双重恢复；7524 次拒绝断言未重放旧动作。完整 23/23 ASan／UBSan 回归与 Release 四库构建、测试符号排除检查通过。最终计数和执行结果见[验证记录](tests/README.md)。

真实 Flash／NVS、四槽及锚点的物理隔离、磨损均衡、同步最坏时延、共同失效、真实维护授权与实物断电尚未验收。
