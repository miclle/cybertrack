# 固件

固件可与机械设计并行推进。当前已实现可在电脑上编译的 C11 控制核心、F1 离线 MCP 协议适配，以及 F2a 与板型无关的启动／运行层、输入处理、有界接收队列、分片／连接流程模拟和假板卡测试，已新增可烧录的[ESP32-S3 无负载检查工程](esp32/README.md)，复用控制核心验证启动与 PSRAM；仍未控制执行器。独立路线和退出条件见[实施计划](PLAN.md)，消息边界见[协议契约](PROTOCOL.md)，F2b 所需输入见[开发板资料清单](BOARD-INFO.md)。

无负载检查工程固定 ESP-IDF v5.5.1，主控已指定 ESP32-S3 N16R8，见[采购记录 P07](../hardware/procurement.md)。[COREBOARD 原理图、排针和尺寸](../hardware/components/ESP32-S3-N16R8/README.md)已整理；实物修订版、焊装、音频器件及项目 GPIO 分配待确定，Flash／PSRAM 已识别为 16 MB／8 MB，无负载配置为 Flash DIO 40 MHz、PSRAM Octal 40 MHz；具体实测结果见[实物核对](../hardware/components/ESP32-S3-N16R8/physical-verification.md)。

## 本地编译与验证

要求 C11 编译器、CMake ≥3.16，运行测试另需 Python ≥3.9。JSON 解析器已随源码固定版本保存，构建无需联网或硬件。在仓库根目录执行：

```sh
cmake -S firmware -B build/firmware-host -DCMAKE_BUILD_TYPE=Debug
cmake --build build/firmware-host
ctest --test-dir build/firmware-host --output-on-failure
```

Clang／GCC 可在首次配置时加 `-DCMAKE_C_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer'`。构建输出位于已忽略的 `build/`；测试使用虚拟时间，不等待真实动作时长。测试记录见[主机验证](tests/README.md)。仅编译 C 库时使用 `-DBUILD_TESTING=OFF`，无需 Python。

## 已实现的边界

- `include/cybertrack/control.h` 与 `src/control.c`：`BOOT → DISARMED → READY → ACTIVE`，停止／故障进入锁定状态；上电无输出，本地使能后才能提交动作。
- 行走、水枪、泡泡共用一个活动槽位，不排队、不组合；本地期限到达时撤销逻辑输出。停止幂等；松开停止或故障消失都不会自行恢复动作。
- 会话断开／替换撤销使能；活动中断线锁定故障。校验动作类型、方向、速度档、时长、会话、序号、开始执行期限及计时溢出；时钟回退撤销输出。
- 限制值为零即能力不可用。测试数值仅为合成用例，不是台架建议值，也不构成可用的硬件配置。
- `include/cybertrack/protocol.h` 与 `src/protocol.c`：MCP 封装、初始化／发现／调用、严格 JSON 参数校验、有界原响应缓存、模拟传输会话与新鲜度门槛。停止优先于缓存及动作时效检查；远程接口不能使能。新解析与缓存重读内存失败会撤销逻辑输出、保留原缓存并要求本地重新使能，已通过逐次分配失败注入。
- `include/cybertrack/runtime.h` 与 `src/runtime.c`：启动先关断、单轮本地事件优先、周期时限与输出应用、条件喂狗、运行层错误锁定及响应抑制。板级回调契约与尚未验证项见[运行层](RUNTIME.md)；没有默认板型实现。

- `inputs.h`／`inputs.c`：逻辑输入去抖、停止／故障立即断言与已观察脉冲锁存；`inbox.h`／`inbox.c`：4 槽消息副本、原始元数据保持、断线优先及溢出关闭。详见[运行层契约](RUNTIME.md)。

- `link.h`／`link.c`：两层分片、连接与握手完成门槛、接收／发送超时、退避重连、发送失败关闭。通过假传输连接实际运行层，契约见[接收边界与连接流程](TRANSPORT.md)。

核心产生逻辑目标，独立协议层负责 JSON 解析，运行层通过板级回调应用目标；无负载检查工程已使用 ESP-IDF 时钟和 FreeRTOS 调度运行控制核心；完整运行层、真实 GPIO、PWM、网络鉴权尚未移植。左右轨道正值均表示车体向前，左转暂定左右反向原地转向；这是待台架验证的控制策略。速度档与实际 PWM、速度没有预设换算。

## 适配层必须遵守的接口契约

1. 控制器由单一任务串行拥有；API 要求有效控制器指针，`ct_submit` 对空请求返回错误。中断和网络回调只投递事件；本地停止／故障事件先于正常动作处理，不能积压在音频或请求队列后面。硬件切断独立有效。
2. 使用本地单调毫秒时钟调用 `ct_tick`，每轮处理事件后应用当前输出；正常完成必须有周期调度，核心本身不创建定时器。最大调度间隔、输出写入耗时、任务卡死及看门狗行为在板级阶段验证，主机测试不能证明 ≤100 ms 停止延迟。
3. 自检成功后调用 `ct_boot_complete`。`ct_local_enable` 仅来自本地明确事件；物理停止持续按下或故障仍存在时禁止恢复。网络禁止调用使能 API。驱动输出失败应调用 `ct_set_fault` 并执行板级关断。
4. `session=0` 表示无连接。使用 `ct_protocol_open` 分配连接代次，`ct_protocol_close` 处理断线；切换时丢弃旧队列，不得把旧请求重新标记为新会话。离线测试可使用合成会话，不能因此放开真实设备。
5. `sequence` 为适配层分配的会话内严格递增序号，不等同于 JSON-RPC ID。F1 已按会话／ID 缓存原响应，重传不会再次提交核心；16 槽响应按 FIFO 淘汰，启动期过滤器跨重连保留，已淘汰／已记录的动作 ID 拒绝，停止仍有效。过滤器可能误拒绝新动作，不能通过清空记录恢复旧命令。跨复位接入必须在首个 CONNECT 前绑定[持久化存储](PERSISTENCE.md)，通过 guarded 入口核验独立锚点，先保存 ID／会话和锚点再使用；失败锁定动作，复位不恢复使能或输出。核心独立保留 `CT_REPLAY` 防线。只读／停止不再增加永久位；纯只读 ID 淘汰后可用于新意图。已有历史不可清位，离线迁移只向空白目标完整复制，见[容量策略](CAPACITY.md)；独立锚点控制后端原子切换并拒绝旧版本，见[切换契约](ATOMIC-SWITCH.md)。
6. `expires_at_ms` 来自设备预先签发的窗口时间加 `max_queue_ms`；等于当前时间即过期，首次接收、出队或重试不得刷新。窗口同时绑定原始会话和使能代次，稳定意图 ID 独立于 JSON-RPC ID 并在动作前持久化，换 RPC ID 不能重放。`ct_action_proof` 默认全零；认证证据源尚未接入，真实动作不得开放。动作结束期限独立为接受时间加 `duration_ms`。见[新鲜度与意图契约](FRESHNESS.md)。
7. JSON 类型和数值已在协议层先校验后转换，额外字段拒绝。通用接收队列已实现，认证、凭据保护与真实网络交接尚未实现；未来接入必须遵守[协议契约](PROTOCOL.md)，不能从 JSON 接收可信元数据。
8. 使用运行层时，通过 `ct_runtime_step` 串行传递连接、断线、消息或空闲事件，不绕过运行层直接改动控制器／协议。只有该轮返回 true 后才能发送响应；返回 false 表示运行层已锁定，需处理故障并重新启动。看门狗和物理切断不能由本轮回调成功替代验收。
