# 主机控制、离线协议与通用运行层验证

日期：2026-10-24。范围：F0 C11 控制核心、F1 离线 MCP 适配及 F2a 通用运行层、逻辑输入处理及有界接收队列、接收边界与连接流程模拟，无 ESP-IDF、真实 GPIO／看门狗、网络、音频或物理负载。

```sh
cmake -S firmware -B build/firmware-host -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_C_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer'
cmake --build build/firmware-host

```

另以 `cmake -S firmware -B build/firmware-library -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=Release` 配置并构建通过，确认仅编译 C 库不依赖 Python 或测试传输。

## 解析器内存故障注入

`protocol_memory_test.c` 连接实际协议库，使用测试专用 `fault_allocator.c` 注入失败。分配器逐块核对所有权、大小及释放，每次 handle 返回后要求存活块数和请求字节数均为零；失败的 realloc 保留旧块，由解析器释放。未拦截进程其他 malloc，也未修改 yyjson。

先对每类请求跑无故障基线，测得实际分配次数，再分别使第 1 至 N 次 allocate／resize 失败。每个位置运行一次单次失败和一次从该点开始持续失败，合计 **138 次注入**，其中缓存重读失败 36 次、resize 失败 50 次（两项可重叠）。17 类涵盖初始化、行走／水枪／泡泡、活动中状态和停止、停止／动作通知、重复／冲突动作、缓存停止、坏 JSON、无效封装、2048 字节紧凑／带缩进初始化及其缓存重读。

每次失败均验证 `-32603`、ID 是否可用、逻辑目标为零、需本地重新使能、原缓存／过滤器逐字节不变、FIFO 游标及序号／会话／初始化状态不变、无临时分配遗留。错误格式化没有后续分配。堆恢复后逐条重放旧缓存，要求原响应一致、无新动作。另有 3 组契约／恢复测试：启动期完整分配器配置与换会话保持；解析前门槛不申请内存及恢复后旧 ID 不重启；20 次连续耗尽后初始化恢复也不自动使能。

主机 ABI 下测得的请求字节统计：

| 样本 | allocate＋resize 调用数 | resize 次数 | 同时存活的 JSON 请求字节峰值 |
|---|---:|---:|---:|
| 普通行走 | 2 | 0 | 772 |
| 缓存行走重试 | 4 | 0 | 1544 |
| 2048 字节紧凑初始化 | 5 | 3 | 20868 |
| 上述请求缓存重读 | 10 | 6 | 41736 |
| 2048 字节带缩进初始化 | 7 | 5 | 18564 |
| 上述请求缓存重读 | 14 | 10 | 37128 |

这些数值只覆盖列明样本，排除 malloc 元数据／对齐开销、栈、输入／输出缓冲和静态缓存，不是所有输入的理论上限或 MCU 内存预算。当前 `ct_protocol` 对象为 137448 字节，包含 32 KiB 启动期过滤器及 FIFO 元数据，比加入窗口状态与接受序号前增加 56 字节；完整样本统计与源码哈希保存于 `verification.json`。AddressSanitizer／UndefinedBehaviorSanitizer 未报错；逐块台账用于明确检查注入路径释放，不把 macOS ASan 当成独立 LeakSanitizer 验证。

单独复跑：`ctest --test-dir build/firmware-host -R protocol_memory --output-on-failure`。Release 纯库构建不包含故障注入器。板上堆碎片、实际内存耗尽、任务栈和关断耗时仍待 F2b。

## 接收边界与连接流程

`link_test.c` 将实际 link、inbox、runtime、protocol 和 control 串联，使用假时钟、假板卡输出及模拟网络事件；没有真实 socket 或 SDK。14 组测试覆盖：

| 场景 | 验证结果 |
|---|---|
| 配置与握手门槛 | 非零预算、CONNECTING／HANDSHAKE 隔离、ready 后由 service 打开协议、提前数据无动作 |
| 分片／UTF-8 | 对含中文 ID 的消息穷举 376 个两段切分用例，分别模拟同帧回调和跨帧 CONT；另测逐字节和两层混合分片及穿插 Ping |
| 消息边界／通知 | 精确 2048 字节、空文本、NUL、空首帧、通知不产生响应 |
| 非法分片 | 孤立 CONT、重复／缺口／重叠、total／FIN／opcode 改写、空指针、零进度、SIZE_MAX、未知／二进制类型、控制帧违规和累计超长均关闭 |
| 分片期限 | 首片起固定期限，进度／Ping 不刷新；文本截断、CONT 未结束和控制帧未收齐在截止点失败 |
| 连接／握手期限 | 截止点到达即失败；迟到 connected／ready 不开放协议，周期控制继续运行 |
| 首片元数据 | 首片使能代次跨停止／重新使能后仍拒绝；首片空 proof 不能被末片新 proof 升级，接收时间保持不变 |
| 重连／迟到事件 | 新 attempt／session、半包丢弃、旧数据／关闭／发送确认不影响新连接，重复阶段回调不能回退时钟 |
| 断线清理 | 队列、待发响应及半包清除；必须应用断线、确认关闭并等待退避；跨重连按住使能不恢复 |
| 发送故障 | 显式失败、短写、超长报告、未取走即确认、无人取走／无确认／迟到确认均失败；不重发原响应 |
| 背压／本地停止 | 待发送时队列不消费，但本地停止仍关断；队列满导致断线；旧发送 ID 不能确认新响应 |
| 回调耗时／关断失败 | 运行层回调跨分片期限，本轮再关断并抑制响应；关断失败保留假输出事实、锁定并禁止重连 |
| 时钟／计数边界 | 回退锁定、UINT64_MAX 附近无期限加法溢出、attempt／发送 ID 耗尽不复用；已接受动作在 ID 耗尽后撤销 |

本测试连接／握手／分片／发送／退避预算为 30／30／15／12／5 ms，队列预算为 40 ms，控制周期预算为 20 ms，仅为合成用例。link 主机对象 21144 字节、发送副本 4120 字节，不含协议对象；没有新堆分配。单独复跑：`ctest --test-dir build/firmware-host -R '^link$' --output-on-failure`。

分片入口按规范化事件测试，不代表原始网络帧解析、真实 hello、TLS、二进制音频、跨任务同步、实际网络关闭延迟或端到端平台验收通过。尚无在线空闲心跳检测；未知断线仍由本地动作期限兜底。

## 长时会话与缓存压力

`protocol_stress_test.c` 用实际协议／控制库和所有权台账运行 5 组场景。累计 **163522 次协议调用**，虚拟时间推进 **120520500 ms**（约 33.48 小时）；实际测试在数秒内完成，不是实机连续运行或真实时间 soak。每次调用后核对缓存不超过 16 槽、游标合法、位数有界和所有临时分配释放。

| 场景 | 实测与断言 |
|---|---|
| 连续动作与淘汰 | 20000 个唯一 ID，轮流行走／水枪／泡泡，1 ms 合成时长；19593 个接受，407 个被过滤器保守拒绝。每个请求在完成后立即重试原响应，再从最早 ID 扫描全部旧请求，共 40000 次检查无新序号／输出 |
| 连续只读 | 同一启动期继续处理 100000 个状态 ID，包含 100 个 2048 字节帧；全部可读，输出为零；占用达到 120161／262144，且这 100000 次查询新增永久位为零 位。随后最早动作仍拒绝 |
| 会话恢复 | 500 次恢复，交替 close＋open 与直接 open；旧元数据丢弃。初始化和本地重新使能后，重新标记为当前元数据的旧 ID 仍拒绝；500 个新意图中接受 466 个、误拒绝 34 个 |
| 满缓存内存失败 | 注入首次分配持续失败，整个协议对象逐字节不变；输出撤销，堆恢复和本地使能后旧动作仍拒绝 |
| 过滤器饱和 | 测试专用注入全 1 位图，跨 close／open 保留；1000 个未缓存动作全部拒绝，1000 次状态查询及停止可用，无自动清空或恢复 |

累计 **40502 次重放检查**无动作再次执行。压力样本的临时 JSON 请求字节峰值为 7636；这是本组样本而非上限，解析内存故障测试的大帧缓存重读峰值仍为 41736。所有返回后的存活分配为零；固定协议对象 137448 字节，空间不随请求数增长。误拒绝次数是确定性测试语料的观测，不是任意输入的概率保证；过滤器高占用会损害动作可用性，实际容量仍须按板上预算和服务端流量评估。

Python 黑盒测试另验证 FIFO 命中不延寿、淘汰后只读快照重算、旧拒绝不恢复、驻留只读 ID 改动作冲突并退役，纯只读 ID 淘汰后不永久占用，以及跨重连的等价转义、UTF-8、空字符串与数字 `-0` 归一化。假传输测试新增四条丢响应恢复路径：显式失败、短写、无人取走、无确认；完成握手、本地重新使能后旧动作仍拒绝，新意图可执行。

`replay_redundancy_test.c` 使用显式四槽模式，覆盖两组交替副本的读取、写入和修复。6 组存储场景合计 **352 次单比特损坏、1056 次轮换中断叠加当前副本损坏、20 次容错读取失败、264 次补齐中断、264 次登记中断、528 次目标日志中断叠加损坏、34 次锚点故障叠加损坏，以及 100 次连续恢复**，历史位丢失为 0。单比特损坏覆盖四槽的头部、完整位图内部、CRC 与 DONE；轮换故障分别发生在过渡记录和新候选的两个副本中，随后再损坏实际选中组的任一副本并移除主快照。字节切点与原日志测试一致，部分落盘和未落盘两种模式分别验证。相同键有效 CRC 却不同历史、跨组重复键、两份当前记录失效、整体日志回滚均拒绝，不能回退另一组旧版本。

`redundancy_integration_test.c` 的 4 组场景覆盖 **动作／会话各 288 次轮换中断、144 次目标日志故障、24 次锚点故障、36 次主快照故障、8 种损坏场景及 100 次连续双重恢复**；7524 次拒绝断言未重放旧动作，历史位丢失为 0。包含后端切换与维护恢复目标日志中断、锚点不确定提交和主快照写入故障，再叠加单份日志损坏及当前主快照缺失。恢复后检查完整历史、新会话、本地重新使能、旧 RPC ID、换 ID 旧意图及延迟证明。循环测试在首次恢复后再次丢失一份日志和主快照，未打开会话就继续恢复，最后仅允许新意图执行。永久不可读槽可由剩余副本恢复到健康组，但随后轮换仍须双份写入；测试先确认动作锁定，再模拟本地修复介质后重新接入，不能静默接受单份提交。

既有 21 项回归继续保留，其中双槽模式仍严格拒绝重复记录／读取失败，四槽模式不替换这一兼容契约。冗余模式日志对象 32872 字节、比较缓冲 32768 字节、四槽介质 131264 字节；每次改变历史写四份日志、八次日志 sync、两次锚点 CAS。测试中的空白替换介质由夹具显式提供，不代表固件会自动擦除失败目标。这里的 CRC 与读故障模型用于意外损坏，不代表认证、真实磨损或共同故障域已验证。
