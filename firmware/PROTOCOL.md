# F1 离线协议契约

状态：2026-10-23 已实现并通过主机测试。入口为 `ct_protocol_handle`，接收一条完整 JSON 消息，返回协议响应或“无响应”；该库本身不负责网络连接、账号绑定、音频、GPIO 或实际执行器输出。2026-10-24 状态／停止已由[独立联网工程](esp32-linx/README.md)接入真实平台，见[实测记录](../docs/linx-validation.md)。

## 依据与兼容范围

本次复核[灵矽端侧 MCP](https://linx.qiniu.com/docs/xrobot/mcp/hardware-mcp)的 `type: mcp`／`payload` 封装、初始化、工具发现、调用及文本结果格式。传输建立和 `hello` 由独立联网工程按[WebSocket 接入](https://linx.qiniu.com/docs/xrobot/platform/websocket)负责。

消息 ID 和通知响应遵循 [JSON-RPC 2.0](https://www.jsonrpc.org/specification)，工具结果区分协议错误与 `isError`，参照 [MCP 2024-11-05 tools](https://modelcontextprotocol.io/specification/2024-11-05/server/tools)。这是项目的有界端侧实现，不是完整通用 JSON-RPC 服务：不支持批请求、位置参数、任意扩展字段或其他 MCP 能力。真实平台的初始化、发现及状态／停止兼容性已完成 F4 子项联调，动作兼容性与完整故障矩阵仍待验证。

- 外层仅允许 `type` 和 `payload`；`payload` 仅允许 `jsonrpc`、`id`、`method`、`params`。连接会话由可信传输元数据绑定，不接受 JSON 自报的会话或使能状态。
- 支持 `initialize`、`ping`、`tools/list`、`tools/call`。初始化要求 `protocolVersion: "2024-11-05"`、对象型 `capabilities`、含字符串 `name`／`version` 的 `clientInfo`；其他版本拒绝。`serverInfo.version: "0.1.0"` 仅标识本离线适配器，不锁定板级固件。
- 初始化成功后可直接发现工具，符合灵矽文档展示的流程；可接收并忽略 `notifications/initialized`。同 ID 初始化重试返回缓存；新的 ID 再次初始化拒绝，必须换会话。
- 工具列表一次返回，无 `nextCursor`；分页参数拒绝。仅发布有非零配置的动作能力；`max_queue_ms=0` 时仅发布状态与停止。
- ID 为最长 64 个 UTF-8 字节的字符串，或绝对值不超过 `9007199254740991` 的十进制整数；数字 ID 与字符串 ID 区分。拒绝 `null`、布尔、浮点、指数或复合 ID。字符串转义正确回写；数字 `-0` 回写为 `0`。
- 无 ID 的合法通知不回复。动作通知不会执行；合法停止通知会撤销输出。格式无效的消息不是合法通知，返回错误及 `id: null`。解析前发生内存失败时无法确认通知身份，返回内部错误及 `id: null`，同时撤销逻辑输出。

## 工具与参数

以下名称为正式控制核心的项目自定义工具；状态／停止已被真实平台发现并调用，正式核心的动作工具未开放。`esp32-linx` 0.2.0 另以独立台架适配层开放本机单次授权喷水，额外要求 `permit` 且固定 `duration_ms=5000`；见[联网工程说明](esp32-linx/README.md)，不属于下述正式动作契约的验收。所有参数对象拒绝额外字段；无参工具可省略 `arguments` 或传 `{}`，`null` 不代表空对象。

| 工具 | 参数 | 结果 |
|---|---|---|
| `self.tank.get_status` | 无 | 文本内容为 JSON 状态快照：状态、故障、逻辑输出、已配置能力；`physical_feedback=false` |
| `self.tank.stop` | 无 | 撤销全部逻辑输出，锁定至本地重新使能；不声称机械停止完成 |
| `self.tank.move` | `direction`: `forward`／`backward`／`left`／`right`；`speed_level`；`duration_ms` | 通过全部门槛后返回 `accepted`，表示逻辑目标已接受 |
| `self.tank.water` | `duration_ms` | 同上，仅控制供能窗口的逻辑目标 |
| `self.tank.bubbles` | `duration_ms` | 同上，禁止与其他动作并行 |

`duration_ms` 为 1–4294967295，`speed_level` 为 1–255；这只是类型范围，执行时还必须小于等于当前控制配置上限。要求直接十进制整数 token；`100.0`、`1e2`、`true`、`"100"`、负数、零、超大数均拒绝。JSON 数字保留原文，避免浮点舍入后误接受 `100.0000000000000000001`。额外字段不能传入 GPIO、使能、会话、新鲜度或高压控制。

前进时左右逻辑目标为正，后退为负；左转为左负右正，右转相反。实际驱动极性、PWM 和物理速度仍需 F3 实测。

示例请求（仅离线语义，不是实际运行参数批准）：

```json
{"type":"mcp","payload":{"jsonrpc":"2.0","id":"move-1","method":"tools/call","params":{"name":"self.tank.move","arguments":{"direction":"forward","speed_level":2,"duration_ms":100}}}}
```

成功响应仅报告接受，完成状态必须另用新 ID 查询；缓存的原响应不是当前状态：

```json
{"type":"mcp","payload":{"jsonrpc":"2.0","id":"move-1","result":{"isError":false,"content":[{"type":"text","text":"accepted"}]}}}
```

## 会话、去重与停止

`ct_protocol_open` 每次分配递增的本地会话代次，撤销先前使能并清空协议缓存；`ct_protocol_close` 取消动作，旧会话消息无响应且不执行。控制器和适配器在一次启动期间不能随意重新初始化以复用代次。重连后须重新初始化协议并在本地使能；防重放过滤器保留，不随连接清空；已绑定存储时会话代次也先持久化，见[持久化契约](PERSISTENCE.md)。

同一会话采用 16 槽 FIFO 缓存，保存最近 16 个缓存未命中的合法封装／ID 请求及原响应，包含语义／运行错误。新记录覆盖最早插入的记录；命中不刷新位置。匹配 ID 后，对解析后的完整 payload 比较：对象字段顺序、空白和字符串转义差异不影响匹配；数字 token 按原文比较。同 ID、相同内容返回原响应，不分配新动作序号；同 ID、不同内容返回冲突，原记录保持不变。缺省 `arguments` 与显式 `{}` 属于不同 payload，重试应保留原内容。

响应淘汰不等于允许重用动作 ID。另有 **32 KiB、4 个位置的只增 Bloom 过滤器**，在成功解析、确认合法封装／ID 且缓存未命中后，先记录规范化 ID，再分派请求；仅包括可能产生动作的请求及被拒绝的动作；合法只读／初始化／停止只进入响应缓存。位只从 0 变 1，不设置 TTL、不删除、不轮换，close／open、发送失败和本地重新使能都不清除。缓存命中重读失败不会改变过滤器。字符串转义和数字 `-0` 的归一化与缓存一致；数字和字符串仍区分。

缓存未命中时，过滤器判定 ID 可能出现过，则拒绝动作／其他非白名单调用，返回 `-32002`，不增加动作序号、不启动或延长动作。这包括已完成、曾拒绝或改写内容的旧动作，以及曾尝试作为动作的 ID；纯只读 ID 在响应淘汰后可用于真正的新意图。无需重新解析已淘汰的内容，也不承诺恢复原响应。`initialize`、`ping`、`tools/list` 和参数合法的 `get_status` 可继续正常分派，合法停止始终先执行；未知方法默认不在安全重试白名单。已淘汰的只读响应会重新计算，可能不同于旧快照；再次初始化仍受会话初始化门槛限制。同 ID 的内容冲突 `-32001` 只在原记录仍驻留时可精确判断。

该过滤器在内存未损坏且生命周期契约正确时不会漏掉已记录 ID，但哈希碰撞会误拒绝新动作；填充越多，可用性越低，全部位为 1 时所有未缓存动作都拒绝，只读和停止仍可用。它使用非密码学哈希，不负责鉴权或抵御恶意资源耗尽。状态结果新增 `replay_guard.scope`（`boot`／`persistent`）、`storage`（`volatile`／`ready`／`fault`）、`bits_set` 和 `bits_total=262144`，用于观察占用；缓存状态仍是原快照，应使用新 ID 查询当前值。**禁止为了消除拒绝而自动清空过滤器、重启、换 ID 重发原动作或自动重新使能**。客户端应在整个防重放历史生命周期内为每个新意图使用独立 ID；会话重连后计数归零会使动作保守拒绝，真实服务端兼容性待联调。

固定内存无法为无限、无序 ID 保留全部精确结果。本轮选择有界响应和保守拒绝，尚不是无限期在线可用性承诺。当前双身份策略压力测试中 20000 个新动作有 407 个误拒绝；再输入 100000 个只读 ID 后，500 次恢复中的新动作有 34 个误拒绝。只读流量新增永久位为零，策略与旧数据边界见 [CAPACITY.md](CAPACITY.md)。容量、服务器 ID 策略及可接受拒绝率须在目标内存和实际流量明确后评估，不能把这些观测当作通用概率保证。

未绑定存储的离线模式仍只保护同次启动。成功绑定[双槽持久化接口](PERSISTENCE.md)后，在存储后端契约成立、历史未被整体回滚／清除的范围内，相同规范化 ID 的已接受动作跨复位也不会重放；残缺记录锁定动作，禁止回退旧快照。恢复不恢复原响应、动作或使能，只恢复过滤器和会话代次。真实 Flash／NVS、网络认证及 OTA 迁移仍未验证；换 RPC ID 的旧意图由独立稳定意图 ID 拒绝，首次到达即延迟的消息由预先签发窗口拒绝，详见[新鲜度契约](FRESHNESS.md)。新增 `ct_protocol_attach_guarded_store` 要求独立锚点绑定，进一步拒绝旧后端和同后端旧版本，见[原子切换契约](ATOMIC-SWITCH.md)。锚点原子持久化、防回滚和设备身份是实际后端必须兑现的契约；整体锚点回滚或旧固件绕过不在软件保障内。`ct_protocol_init`／`ct_runtime_init` 只用于真正启动；每次启动都必须重新加载并绑定持久化历史，不能利用 RAM 模式绕过。不能宣称跨掉电恰好执行一次。显式[维护恢复](RECOVERY.md)成功后也必须新建协议、重新握手并等待本地使能；缺失锚点对应完整快照且没有匹配独立日志时保持存储故障，查询／停止继续可用，不提供远程恢复或格式化工具。新增 `ct_protocol_attach_logged_store` 同时要求已绑定锚点和 ready 的独立日志，缺项即锁定，不降级到 guarded／RAM；真实动作接入使用此入口。原历史过渡日志先于尝试 epoch 领取持久化，新候选先于数据版本预留持久化，首次登记使用 `ct_replay_store_enroll_logged`，带日志切换与日志恢复均先持久化目标完整日志再选择；旧存储 attach 会核验或补写当前证据，成功后才允许协议接入。需要单槽损坏容错时显式配置[四槽日志](REDUNDANCY.md)，其两份目标记录均完成后才提交锚点；读取可使用同组剩余精确副本，冲突或无当前证据仍锁定，不因容错恢复动作。覆盖首次选中、日志准备和新快照未完成的窗口，详见[日志恢复契约](RECOVERY-LOG.md)。

动作的 JSON-RPC ID 和 `proof.intent` 分别记录。意图使用 `intent:` 加 16 位十六进制数的独立哈希命名空间，与规范化 RPC ID 不重叠；二者共用只增位图并在同一次持久化提交中预留。包括过期、未就绪和参数错误的可识别请求，预留成功后也不能更换 RPC ID 重试。驻留响应命中不执行动作；若调用者附带另一个意图 ID，也先预留该身份再返回原响应，防止随后换 RPC ID 执行。缓存解析 OOM 仍先退出，保留原缓存和位图。读取与停止不要求意图或窗口。

合法的当前会话停止在初始化、缓存、新鲜度及期限检查之前执行。缓存中的停止重试也重新撤销当前逻辑输出；同 ID 被改写为停止时，先停止，再返回冲突；缓存满仍执行停止，并按 FIFO 写入新响应；过滤器饱和也不能阻止停止。停止不等待动作完成或语音播放。无效 JSON／非法 ID／错误参数不构成有效停止；物理停止始终独立。

## 接收层的可信元数据

单一控制任务串行拥有 `ct_controller` 与 `ct_protocol`。在命令首次进入本地队列时，记录以下 `ct_rpc_delivery`，出队、重试及本地重新使能时不得刷新旧消息的元数据：

| 字段 | 来源／用途 |
|---|---|
| `session` | 当前 `ct_protocol_open` 返回的连接代次；丢弃旧连接排队数据 |
| `received_at_ms` | 首次本地接收的单调时钟；必须在窗口签发后且不晚于当前时间，不能延长窗口期限 |
| `enable_generation` | 首次接收时控制器的使能代次；每次本地使能递增，禁止使能前或停止前排队的命令跨代次执行 |
| `proof` | 经认证并绑定完整内容的原始 `session`、`enable_generation`、`window` 和稳定 `intent`；默认全零拒绝动作，禁止在收到消息时制造证据 |

未来接收任务与控制任务必须同步读取代次，或者在同一串行入口完成标记；本地停止与故障先于普通消息处理。F1 测试生产者使用合成证据；窗口策略不需要墙上时钟同步，认证和服务端意图生命周期仍未对接。因此，正式控制核心的真实网络动作保持关闭；待认证证据源与板级验收完成后再开放。0.2.0 单次喷水台架使用独立的本机授权策略，未放宽此处门槛。

每次调用会先推进本地时钟，超时撤销逻辑目标；无消息期间仍必须周期调用 `ct_tick`。时钟回退进入故障，结束期限和接收期限加法溢出均拒绝。适配器不提供定时线程、优先队列或硬件关断，调度延迟仍需 F2 验证。

## 错误映射与资源边界

| 返回 | 含义 |
|---|---|
| `-32700` | JSON 语法或 UTF-8 无法解析 |
| `-32600` | 外层／请求结构、ID 无效，重复键、嵌入 NUL、过深／过大消息 |
| `-32601` | 未知方法或工具；未知工具码沿用灵矽示例 |
| `-32602` | 参数缺失、类型／整数词法无效、未知方向、额外字段或不支持的初始化参数 |
| `-32603` | 解析器分配失败、缓存解析或响应序列化内部错误 |
| `-32000` | 尚未初始化，或试图重新初始化同一会话 |
| `-32001` | 相同 ID 改写内容 |
| `-32002` | RPC ID 或稳定意图 ID 已记录，或过滤器碰撞；无新动作执行 |
| `-32004` | 控制时钟故障 |
| `-32005` | 已绑定存储不可用／持久化失败，动作锁定；只读与停止仍可用 |
| `result.isError=true` | 已识别工具但不能执行，例如 `not_ready`、`busy`、`unavailable`、`invalid`、`expired`、`freshness_unverified`、`stale_local_enable`、`invalid_receive_time` |

单帧最多 2048 字节、JSON 深度最多 16、响应缓冲至少 4096 字节。低于最低输出容量的 API 调用返回 `CT_RPC_BAD_ARGUMENT`，不执行动作。解析器分配失败、缓存重读失败或响应序列化异常时撤销逻辑输出，锁定至本地重新使能。非活动会话返回 `CT_RPC_STALE_SESSION`；通知返回 `CT_RPC_NO_RESPONSE`。

使用 vendored [yyjson 0.13.0](third_party/yyjson/README.md)严格解析，不开启 JSON5、注释、尾逗号、NaN 或宽松 Unicode。输入长度限制同时约束解析规模；本实现仍使用解析器堆分配。macOS arm64 上适配器对象实测 `sizeof=137448` 字节，含 32 KiB 防重放过滤器和完整响应记录；不能放在小任务栈上。主机分配失败注入已完成；F2 仍须核对板级堆／栈、实际分配器及处理耗时，本次不宣称嵌入式内存验收通过。

完整消息前的分片与连接生命周期现由可选 [ct_link 层](TRANSPORT.md)实现。接收时间与使能代次从首片保持到协议调用；实际网络握手、消息路由和新鲜度证据仍不属于 MCP 解析器。

## 解析器内存故障

可在 `ct_protocol_init` 之后、第一次 `ct_protocol_open` 之前调用 `ct_protocol_set_allocator`，提供 `ct_rpc_allocator` 的 allocate／resize／release 和 context。使用运行层时，对应窗口为 `ct_runtime_init` 成功后、第一次 CONNECT 前。三个回调必须完整，配置会按值复制；回调及 context 在适配器存活期间保持有效。开启过会话后，即使已经断开，也不能更换分配器。回调需遵守 malloc 的对齐和所有权语义，resize 失败必须保留旧块。默认仍使用 libc 堆；没有全局 malloc 劫持，也没有修改第三方解析器源码。

新请求和缓存重读共用此分配器，每次处理返回前释放所有临时 JSON 内存。错误响应写入调用方预分配的缓冲，不再次申请内存。故障注入器仅链接测试目标，不进入 `BUILD_TESTING=OFF` 的库。

| 失败位置 | 响应与控制行为 |
|---|---|
| 新消息解析分配／扩容失败 | `-32603`、`id: null`；尚未确认 ID、方法或通知身份，撤销逻辑输出并要求本地重新使能 |
| 匹配 ID 后缓存重读分配／扩容失败 | `-32603`、当前请求 ID；撤销逻辑输出，不将比较失败当成新请求或内容冲突 |
| 缓存重读发生其他内部解析失败 | `-32603`、当前请求 ID，同样撤销逻辑输出 |

上述内存失败不写入新缓存、不增加动作序号，也不删除原缓存或改变 FIFO 游标／防重放过滤器；初始化状态和会话保留。内存恢复本身不会使能或重启动作。旧的 accepted 响应仍按原样回放，只代表原请求曾被接受；即使重新本地使能，重试旧 ID 也不能重新执行。合法停止已经成功解析时，会先撤销目标再尝试缓存比较。内存失败触发的锁定沿用 `CT_STOPPED`，具体资源原因见本次 `-32603`，不是物理停止反馈。

运行层在处理返回后应用关断；只有关断及本轮基础检查成功才发送内部错误响应。若关断回调也失败，运行层另行锁定 `CT_RUNTIME_OFF_FAILED`、关闭会话并清响应缓存、保留防重放过滤器、抑制响应；此时不能声称实际输出已关断。旧会话、超长帧和无效 API 缓冲等解析前门槛不调用分配器，沿用原先行为。
