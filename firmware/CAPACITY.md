# 防重放记录的容量策略

## 保留动作历史，限制只读开销

32 KiB 只增过滤器继续保留所有已记录的动作 RPC ID 和稳定意图 ID；参数错误、未就绪、过期及未知方法的动作尝试同样退役。合法初始化、ping、工具发现、状态读取和停止不再新增永久位，只占 16 槽原响应缓存。缓存内同 ID 改内容仍返回冲突；若改成动作尝试，会在返回冲突前记录该动作 ID／意图。

纯只读／停止的 ID 在响应淘汰或会话关闭后，可以由一个真正的新意图使用。这不恢复旧动作：已经接受或拒绝的动作身份始终保留，换 RPC ID 仍受稳定意图约束。生产者必须继续保持稳定意图的生命周期，新鲜度与认证要求不变。

清理只释放原响应，不删除防重放位。不采用 TTL、LRU 位删除、分轮清零或饱和后自动重启。旧版本曾写入的只读位不能从位图中可靠区分，升级时全部保留；优化减少后续增长，不会降低已有占用。旧存储布局、哈希及完整历史仍兼容，已饱和介质不会被自动“修复”。

## 压力结果

相同主机语料：20000 个新动作、100000 次状态查询、500 次恢复、40502 次旧请求重放检查。新动作阶段仍为 407 次保守拒绝；只读流量新增永久位为零，查询后占用从旧策略的 230561 位降至新建历史的 120161 位。恢复阶段误拒绝从 413/500 降至 34/500（减少约 91.8%），无旧动作重新执行。

这是两种策略各自从空历史运行的对照，不是在线清理旧位图后的结果。它不是任意流量的误拒绝率保证，也不承诺无限期可用。动作数量继续增长时仍会趋于饱和；应依据实际流量和板上内存预算选择后续容量方案。状态已有 `bits_set`／`bits_total` 可观察占用。

## 迁移阶段

容量优化及完整迁移均已完成离线验证。`ct_replay_store_migrate` 仅在输出关闭、源停止写入期间向空白目标复制，已验证掉电、已有目标、历史位缺失、过时快照及连续迁移。迁移不压缩／重建过滤器，不清除源介质。新增独立锚点与原子切换接口已完成主机模拟，真实分区、不可回滚锚点及设备身份仍需板级实现。

## 离线迁移流程与禁止的清理

1. 关闭输出并停止源协议所有者，完成已有持久化操作。加载源双槽和目标双槽，源必须 READY，目标必须 EMPTY；目标与源应是物理独立的介质／区域，使用不同的回调 context。API 不负责让正在运行的控制任务停机。
2. `ct_replay_store_migrate` 重读源两槽，与加载时的版本、会话和位图核对；源已推进、历史减少、损坏或读取失败均拒绝，尚未开始写目标。再检查目标仍全空白；禁止覆盖现有记录、修复坏槽或合并未知设备历史。
3. 将源完整过滤器及会话代次写入目标两个槽，版本分别为源版本加 1、加 2，各自同步并回读。返回 true 仅说明复制完整，目标仍需独立锚点选择。未完整完成时不选择单槽，失败不擦源；返回失败但实际已经写完也不能据此跳过锚点，重启按锚点身份和版本核验。
4. 带回滚保护的接入从第一步即使用 `ct_replay_store_switch`，由该包装接口完成以上复制，再原子提交独立锚点选择；不能先 migrate 再 switch 已非空目标。只有锚点与目标一致时才绑定独立日志并通过 logged 入口启动新的协议所有者。正常 open 预留下一会话，恢复仍不恢复使能、缓存或输出。旧源和旧版本均不能重新绑定，见[原子切换契约](ATOMIC-SWITCH.md)。

迁移可以搬运历史，不释放位图容量，也不增大固定过滤器。[维护恢复](RECOVERY.md)同样只复制由当前锚点确认的完整历史；另一槽损坏可转移，当前快照缺失时只允许从精确匹配锚点的[独立日志](RECOVERY-LOG.md)恢复，无证据则拒绝，不能借维修清位。尝试把位图“清理”为子集会在写介质前锁定存储；重启加载仍保留原历史。响应淘汰／断线只清理缓存；不会清除动作身份。格式、哈希和只增规则未变。

实测：168 次目标回调中断（14 个位置 × 6 个字节边界 × 两种落盘模式）、50 次连续迁移，以及 441 次迁移相关重放断言通过；源无擦写，成功目标历史逐字节一致。源读取失败、目标被占用、源快照过时和版本溢出均拒绝。正常目标使用前重新加载，两槽残缺或空白时动作保持锁定。

上述底层复制测试不包含锚点选择；[原子切换联测](ATOMIC-SWITCH.md)另覆盖旧后端／旧镜像拒绝。真实分区原子性、跨介质别名检测、介质身份和防回滚锚点尚未验收。重用旧后端、静默回退、在线迁移和自动格式化不在接口契约内；不把复制成功等同于真实设备的迁移验收。
