# 接收边界与连接流程模拟

更新：2026-10-23。`include/cybertrack/link.h`／`src/link.c` 已实现不依赖开发板的 MCP 文本接收和连接生命周期，连接真实运行层、协议层及有界队列；测试只使用假传输与假板卡。没有建立网络连接、发送真实 hello、调用 ESP-IDF 或注册设备。

## 接口依据与实现范围

已复核 [ESP WebSocket Client 事件契约](https://docs.espressif.com/projects/esp-protocols/esp_websocket_client/docs/latest/index.html)及其[事件实现](https://github.com/espressif/esp-protocols/blob/master/components/esp_websocket_client/esp_websocket_client.c)：接收回调提供 opcode、FIN、payload 长度与 offset，一个帧的内容可能分多次回调交付；控制帧也会产生事件。因此本模块分别处理“同帧多次回调”和“TEXT／CONT 多帧消息”，不将 data_len 当成整条 JSON 长度。未锁定 SDK 或组件版本；选型后须核对实际版本的事件映射。

[灵矽连接流程](https://linx.qiniu.com/docs/xrobot/platform/websocket)在 WebSocket 连接后还有 hello 协商，文本与音频二进制分开。本模块使用可信本地 `connected`／`ready` 事件模拟两道门槛；**不解析或验证真实 hello**，不提供凭据、TLS 或音频参数。真实适配器必须完成证书／主机名、鉴权和 hello 参数验证后才调用 `ct_link_ready`，不能以收到任意文本或 JSON 自报字段替代。

这里是离线 MCP 文本路径，文本直接交给现有 MCP 解析器。真实平台的 hello、TTS／STT 等文本需由未来消息路由器分流；音频二进制需单独路由，当前误送二进制至该路径会关闭连接。WebSocket 帧头、掩码、协议级控制帧校验及 Ping 的实际应答由未来传输库负责，此模块不解析原始 TCP 字节，也不是完整 WebSocket 实现。

## 所有权与调用顺序

`ct_link`、运行层和内部 inbox 由一个控制任务串行拥有；无内部锁或网络回调。网络任务／ISR 只能通过板级可靠交接提交事件，不能并发调用这些 API。所有 now_ms 使用与运行层相同的单调时钟；过期连接事件在时间校验前忽略。

1. 先初始化运行层，再调用一次 `ct_link_init`，要求尚无协议会话、运行层健康、五个时间预算均非零。使用 link 后，不再从外部直接修改其运行层、协议或 inbox。
2. `ct_link_begin` 返回新 attempt；网络适配器据此启动一次连接。所有回调和发送副本绑定该 attempt。`ct_link_connected` 进入 hello 等待，`ct_link_ready` 只登记已完成可信握手。下次 service 才打开协议会话、绑定 inbox 并进入 ONLINE。
3. 调用 `ct_link_receive` 交付规范化分片。首片保留协议会话、使能代次、接收时间和可信新鲜度标记；后续分片不能刷新或升级它们。完成消息复制入 inbox，来源缓冲可复用。
4. 周期调用 `ct_link_service`，即使正在连接、等半包、等发送完成或退避，也必须持续服务本地输入、动作期限和看门狗。每轮最多处理一条普通消息；断线先于队列。函数 true 表示基础服务未锁死，不等同于已联网或动作成功。
5. 响应经运行层成功返回后，`ct_link_take_tx` 只交付一次副本给工作线程，含 attempt、递增发送 ID、精确长度和内容。工作线程只对绑定的旧／新句柄发送一次，通过 `ct_link_sent` 报告结果；不能跨连接转发副本或自动重发接受响应。
6. `close_required` 表示网络适配器需要关闭／中止当前 attempt 的句柄。完成后回报 `ct_link_closed`。重试必须同时满足：断线已由 service 应用、旧句柄关闭已确认、退避预算已到；然后显式再次 begin。无自动本地使能。

事件入口不会直接调用板级 I/O。失败会清除半包、待处理队列和本地待发响应，登记高优先级断线；**关断在下一次周期 service 应用**，适配器必须及时唤醒控制任务。若发现期限在运行层回调期间跨过，本轮返回前再应用断线并抑制响应。已经交付给工作线程的副本无法收回，必须由工作线程以 attempt 约束句柄并处理关闭；发送成功也不证明服务器收到或执行了响应。

## 状态与失败策略

| 状态 | 进入／离开条件 |
|---|---|
| DOWN | 初始离线；begin 分配 attempt 后进入 CONNECTING |
| CONNECTING | 等连接完成；connected 后进入 HANDSHAKE，超时进入 BACKOFF |
| HANDSHAKE | 等可信 ready，再由 service 打开协议会话；提前数据不进入 MCP，超时进入 BACKOFF |
| ONLINE | 接收完整 MCP 消息与有限待发响应；失败或关闭进入 BACKOFF |
| BACKOFF | 先应用断线、确认句柄关闭、等待 retry_ms；再显式发起新 attempt |
| HALTED | 单调时钟回退、代次耗尽或运行层故障；不能通过网络重连恢复 |

attempt 与协议 session 分开：握手失败也消耗 attempt，但不会打开协议会话。二者和发送 ID 均不允许回绕；重启前不重新初始化对象复用代次。旧 attempt 的连接、数据、关闭或发送完成事件均不影响新连接，旧发送 ID 也不能确认当前待发响应。已完成阶段的重复连接／ready 回调忽略。

断开或重新连接撤销本地使能；启动时或跨重连一直按住使能无效。半包和队列不带入新连接；新会话重新执行 MCP initialize，并要求新的本地使能边沿。关闭只是链路处理成功，不能替代实际物理停止反馈。

## 分片与期限

规范化 `ct_ws_chunk` 包含 opcode、fin、offset、total、length、data。offset／total 相对于**当前 WebSocket 帧**，而不是跨帧消息。SDK 中有符号长度必须先检查非负，再转为 size_t。

- 同帧回调必须连续、无重叠、无缺口；opcode、FIN 和 total 必须保持不变。空指针只能配零字节；非空帧的零进度回调拒绝。
- TEXT 开始一条消息，CONT 只能续接已有消息。帧内容完全收到且 FIN=true 后才入队。途中另一条 TEXT、孤立 CONT、未知类型、超长或溢出均关闭连接。
- 每条消息总计最多 2048 字节；在 memcpy 前检查单帧和跨帧累计长度。零长度消息和包含 NUL 的字节原样交给协议层判定；UTF-8 可跨回调或帧拆分，只在完整消息中解析。
- Ping／Pong 可在已完成帧之间穿插，不结束文本消息、不刷新其期限；控制帧要求 FIN 且最多 125 字节。一个帧的回调尚未收齐时不能交错另一帧。Close 清除本地待处理内容并请求关闭句柄。
- 同时只保存一条未完成消息。多个完整消息仍受 4 槽 inbox 限制；满队列撤销待处理内容并断线，不能静默丢掉停止请求后继续运行。

| 预算 | 起点／截止条件 |
|---|---|
| connect_ms | begin 起；连接完成必须严格早于截止点 |
| handshake_ms | connected 起；ready 和打开协议会话都必须早于截止点 |
| fragment_ms | 首个文本片段起；进度、CONT、Ping／Pong 不续期。无文本时，未收齐的控制帧也有期限 |
| send_ms | 响应生成起，包含等待工作线程取走的时间；取走及完整发送确认均必须早于截止点 |
| retry_ms | 失败／断线起；到点且完成断线／关闭后允许新尝试 |

期限采用单调差值比较，避免绝对截止时间加法溢出；精确到截止点即超时。测试 30／30／15／12／5 ms 仅用于分支覆盖，不是硬件或平台推荐参数。尚未实现在线空闲心跳／Ping 活性检测，未检测到断网时仍由动作自身期限限制输出。

## 发送、背压与故障

仅保留一个待发响应，未确认期间不消费下一条普通消息，但周期服务持续检查本地停止、故障和动作期限。远程停止仍是 FIFO 消息，可能等待此前响应；本地停止不经过该队列。若发送等待超时或队列满，会通过断线撤销输出。

发送返回失败、字节数不足／超出、未经取走就确认均关闭当前链路；完整确认晚于或等于截止点同样失败。不重试部分发送，不将未知交付结果作为成功；重连后不保留待发响应。缓存 accepted 是原请求接受快照，不代表当前仍在动作，也不因发送恢复而再执行。

`error` 保留最近链路失败原因。运行层关断失败时进入 HALTED、关闭协议会话、抑制响应；`off_acknowledged=false` 仍表示可能存在真实输出，链路层不将其覆盖成成功。库不调用阻塞发送或重连函数，真实网络任务不能阻塞控制服务或代喂控制看门狗。

## 资源与验证

当前主机 ABI 下 link 对象为 21000 字节，包含 inbox、半包、消费缓冲和单个待发响应；工作线程发送副本为 4120 字节，协议对象 137376 字节另计。无新堆分配或第三方依赖，移植时需重新核对目标 RAM／栈和队列交接成本。

[主机测试](tests/README.md#接收边界与连接流程)包含 13 组场景、376 个两段切分用例，另有逐字节、两层混合分片、精确超时、重连隔离、发送短写和关断失败。真实 SDK 事件映射、TLS／hello、WSS 端到端兼容、跨任务竞争、网络关闭时序和物理停止尚未验证。真实新鲜度证据未建立时，首片 `freshness_verified` 继续为 false；ONLINE 不授予动作权限。

会话恢复只清空原响应 FIFO，协议的启动期防重放过滤器继续保留。发送失败或超时后，即使重新握手、初始化、本地使能，并将旧请求重新标记为当前元数据，已记录的动作 ID 仍返回 `-32002`，不会再次执行。此项已在显式失败、短写、未取走和未确认四条恢复路径联测；不能把换 ID 自动重试作为恢复策略。跨复位边界见[协议契约](PROTOCOL.md)。
