# F2 与板型无关的启动与运行层

更新：2026-10-23。当前完成 F2a：纯 C11 启动顺序、周期执行器、板级 I/O 契约、输入处理、有界接收队列和假板卡故障测试。F2b 的 ESP-IDF 工程、真实板卡适配及实测尚未开始；输入资料见[开发板清单](BOARD-INFO.md)。

代码入口为 `include/cybertrack/runtime.h` 和 `src/runtime.c`。没有默认 GPIO、时钟频率、Flash／PSRAM 模式、FreeRTOS 任务或伪板卡配置。假板卡仅存在于测试程序，不链接到发布库。

## 已实现行为

1. **启动**：先调用 `force_off`，再验证回调与配置、自检、读取时钟及本地输入。自检成功后进入禁止动作状态；启动时按住使能不会自动解锁。自检不能开启负载，未验证的能力继续配置为零。
2. **周期服务**：检查距上一轮开始的间隔，推进本地动作期限，读取停止／故障／使能状态；过期或禁止状态先关断，再处理最多一个传输事件。
3. **本地使能**：仅在周期开始处理已去抖按键的上升沿；停止／故障持续存在或刚解除时不使能。已按住使能不能在释放停止、重连后自动恢复；需要松开后再次按下。
4. **协议连接**：支持空闲、连接、断开和一条消息事件。沿用 F1 的连接及使能代次，不刷新首次接收时间。断线撤销逻辑目标；旧队列仍由代次和期限拦截。
5. **输出应用**：写入前再次检查输入与时钟。写入后复查停止、故障和动作期限；若目标已撤销则再次调用关断路径。停止不等待普通消息解析；消息解析后才返回的接受响应不等于物理执行成功。
6. **看门狗服务**：当前检查和输出调用成功后才调用喂狗回调；其返回后再检查安全输入和时间。运行层故障锁定后不再喂狗，只重试关断。若喂狗回调自身阻塞，只能在它返回后发现，不能撤回刚发生的喂狗。
7. **故障上报**：配置、自检、时钟、调度、输入、输出、关断、喂狗错误保存在 `runtime.faults` 位掩码。出现运行层错误时关闭协议会话、清除缓存并抑制本轮响应；不会发送输出写入失败前生成的 `accepted`。

运行层故障需排查后重新启动，不提供在线清除入口。本地停止或正常故障输入属于控制状态：信号解除后可由新的本地使能事件恢复，不必将正常停止当成运行层崩溃。

## 板级回调契约

全部回调运行在同一控制任务中，必须有确定的返回和耗时边界；禁止等待网络、音频、用户输入或动态重连。调用层需防止并发进入运行层。

| 回调 | 必须满足的约束 | 当前状态 |
|---|---|---|
| `force_off` | 撤销所有普通执行器输出；可在自检之前调用；与普通写入失败路径分开。返回 false 必须保留失败信息 | 假板卡可注入成功／失败，真实路径未定 |
| `self_test` | 检查已知配置、所需资源及默认关闭，不得试转电机或开启液体模块；启动超时另由平台保护 | 假板卡验证启动门槛 |
| `now_ms` | 从启动起连续递增的 64 位单调毫秒值；失败必须返回 false，不能用墙钟或未扩展的回绕计数 | 假时钟验证回退／超时 |
| `read_inputs` | 返回逻辑化的停止、故障和使能按钮状态；按键已去抖；短暂停止／故障需保持到被控制任务采样 | 通用过滤器已实现；具体电平、去抖时间与捕获机制未定 |
| `write_outputs` | 完整应用逻辑目标，部分写入失败也返回 false；内部不得延长动作；时间与方向映射需板级验收 | 假板卡覆盖部分失败与延迟 |
| `watchdog_kick` | 服务当前控制任务已经配置的看门狗，报告失败；不能由无关网络任务代喂 | 未调用真实看门狗 API |

`off_acknowledged` 仅记录关断回调是否返回成功，不是电流、GPIO 或机械停止的测量反馈。若关断失败，可能仍有输出；记录失败并不替代独立物理切断。

解析内存失败先撤销逻辑输出并要求本地重新使能；运行层随后执行关断。关断成功可发送 `-32603`，若关断回调失败则按运行层故障关闭会话、清响应缓存、保留启动期防重放过滤器并抑制响应。可在运行层初始化后、首个 CONNECT 前配置本地解析器分配器，见[协议内存契约](PROTOCOL.md#解析器内存故障)。

## 调度与内存

每轮调用 `ct_runtime_step`。没有消息也要定期传空事件或 `CT_EVENT_IDLE`。运行层不创建线程、定时器或中断服务；新增的 `ct_inbox` 提供纯 C 接收队列，`ct_input_filter` 保留已捕获的短脉冲。真实调度、并发同步、任务优先级及中断捕获仍由板级工程提供。读取输入期间发生的新事件仍依赖下一次采样或独立硬件停止。

`max_cycle_ms` 为必须显式提供的预算，同时限制周期起点间隔及单轮执行耗时；超过预算会锁定。预算为零不能启动。测试使用 20 ms，仅用于检查分支，不是 ESP32 调度参数或 ≤100 ms 停止延迟的证明。时间检查无法抢占永不返回的回调；真实任务／中断看门狗和物理切断必须独立配置及实测。

`ct_protocol` 由调用方单独分配，避免将约 134 KiB 缓存放在任务栈上；`ct_runtime_response` 也含 4096 字节响应缓冲。解析器分配失败已完成主机注入与假板卡联测；真实堆／栈、链接产物、PSRAM 可用性、板上分配器及处理耗时仍需验证。库本身无新增第三方依赖。

F1 消息元数据仍由可信接收层提供。当前无真实网络新鲜度证据，生产接入时 `freshness_verified` 保持 false；测试中的 true 仅为合成条件。运行层不扩展使能权限或云端工具。

## 通用输入处理

`inputs.h`／`inputs.c` 的 `ct_input_filter` 接收已归一化的逻辑电平：true 表示相应输入被触发，不决定 GPIO 极性。适配器调用 `ct_inputs_observe` 记录带单调时间的观察，再由 `read_inputs` 回调调用 `ct_inputs_read`；返回失败必须向运行层传播，不能当成三个 false 的正常输入。

停止／故障的断言不等待去抖；只对释放做稳定时间检查。观察到的断言保留到至少一次读取，即使此时电平已释放，也不能丢失该事件。重复读取仍会返回尚未释放的有效电平。使能按钮的按下和释放均需稳定；启动时按住、与停止／故障重叠的按住均不能解锁，必须稳定释放后重新按下。时钟回退使过滤器持续失败，需重新启动。

释放时间和使能去抖时间均须显式提供且非零，测试中的 3／5 ms、3／2 ms 不是硬件推荐值。这个过滤器只能保留**已经观察到**的事件，不能恢复采样之间未捕获的脉冲。对象不含锁或原子操作；ISR 不能直接并发调用它，板级需提供可靠捕获、交接与定期观察。

## 有界接收队列

`inbox.h`／`inbox.c` 的 `ct_inbox` 使用 4 个固定槽位保存完整消息，不分配堆、不解析 JSON，也不是 WebSocket 分片组装器。每条消息复制最多 2048 字节及原始 `ct_rpc_delivery`；出队不改首次时间、会话、使能代次或新鲜度标记。普通消息（包括远程停止）按 FIFO 进入协议层；本地停止始终通过独立输入路径优先处理。

正常连接顺序：

1. 启动时初始化一次 inbox；在运行层成功处理 `CT_EVENT_CONNECT` 后，以返回的 `protocol.session` 绑定 inbox。
2. 在可信接收边界保留原始元数据，再将完整帧交给 `ct_inbox_push`。来源缓冲随后可复用；不能在出队时重新标记代次或刷新时效。真实新鲜度证据缺失时保留 false。
3. 控制循环每轮 `ct_inbox_take` 最多一条，把 item 的 `kind`／`frame`／`length`／`delivery` 传入 `ct_runtime_step`；空队列也继续空闲周期。item 由消费方持有，运行层返回之前不覆盖它。
4. 当前连接断开、接收超长帧、无效缓冲或队列溢出时丢弃所有待处理帧，保留一个不占槽位的断线通知。适配器应关闭传输并唤醒控制任务；下一轮优先交给运行层撤销输出和使能。**仅调用 inbox 并不会直接关断硬件**。
5. 必须先消费并向运行层应用断线通知，再处理新的连接和绑定。禁止自动恢复使能。过期连接的消息／断线回调不会影响新连接；session 不允许回退或复用。若运行层失败，同样关闭传输并丢弃队列，不继续发送本轮响应。

队列 API 为单一所有者契约；生产者与消费者必须由板级串行化，不能无锁跨任务／ISR 调用。不要持有交接锁运行网络操作或整个控制周期。主机 ABI 下 inbox 为 8456 字节，消费 item 为 2104 字节；这些和约 134 KiB 协议对象都应计入移植预算。4 槽是有界离线配置，不是吞吐率或真实停止延迟的验收结果。队列测试还覆盖 NUL 字节和零长度帧的原样传递；JSON 合法性仍只由协议层判定。

## 连接流程的运行层集成

`ct_link` 已实现两层分片组装与连接生命周期，持有 inbox 并通过周期 `ct_link_service` 驱动运行层。采用它后，不再从外部直接消费 inbox 或调用运行层；即使正在连接、等半包、等发送或退避，也持续 service。网络错误先登记断线，下次 service 优先应用；真实线程仍需可靠交接与及时唤醒。发送通过带 attempt／ID 的副本交付，不在控制周期执行网络 I/O。详见[传输契约](TRANSPORT.md)。
