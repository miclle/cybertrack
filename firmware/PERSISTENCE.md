# 跨复位防重放与持久化契约

状态：2026-10-23，独立存储接口、协议接入与主机掉电／会话恢复模拟已实现。没有 ESP-IDF、Flash／NVS 或文件系统驱动，没有真实断电和存储寿命验收。

## 存储接口与格式

`replay_store.h` 提供 `ct_replay_io` 的 read／erase／write／sync 回调。存储包含两个相互隔离的槽，每槽 32800 字节，共 65600 字节；实际擦除粒度、对齐、分区和磨损均由后续板级适配核对。返回 true 的读写必须覆盖完整范围，false 可以已部分完成。**sync 返回 true 必须保证此前擦除和写入已经按顺序持久化，不能只表示写缓存可读。** 回调须有界、串行、不可重入；不能在中断中调用。

每槽是明确的小端字节格式，不直接保存 C 结构体：

| 字节偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 8 | `CTRP`、格式／过滤器哈希策略版本 1、三个零字节 |
| 8 | 8 | 单调快照版本，非零，不允许绕回 |
| 16 | 8 | 已保留的连接会话代次 |
| 24 | 32768 | 防重放过滤器 |
| 32792 | 4 | 前 32792 字节的 CRC-32，小端，反射多项式 `0xedb88320` |
| 32796 | 4 | 提交标记 `DONE` |

版本奇数位于槽 0，偶数位于槽 1。相邻有效记录的版本必须连续、会话代次相同或增加 1，新过滤器必须包含旧过滤器的全部位。版本、哈希策略或格式不匹配均拒绝恢复，不自动迁移或清空。CRC 用于发现意外损坏，不提供认证、防恶意回滚或无碰撞保证。

## 写入与恢复

保存顺序：擦除非当前槽 → 写头部／过滤器／CRC → sync → 写提交标记 → sync → 完整回读并核对内容。只有全部成功，调用者才可使用新会话／动作授权。任何失败都将当前存储对象锁定为 FAULT；即使实际提交已经完成，也不能猜测成功或继续动作。重新启动后由 load 检查实际介质，完整记录可恢复为保守的“已见过”，不会恢复动作、原响应或本地使能。

load 只读，不格式化。两槽都空白返回 EMPTY；只存在一槽、任一槽损坏／读取失败、版本跳跃、位图倒退都返回 FAULT。不得自动回退旧槽；这会牺牲部分掉电后的可用性，但避免遗漏已接受动作。两槽都有效时取较新版本。整个旧的有效双槽镜像被回滚或介质被完整擦空，无法仅凭这些字节识别；设备绑定、可信版本锚点与维护恢复策略尚未实现。

首次 provision 只允许已 load 为 EMPTY 的对象，并再次核对双槽为空白，随后写入版本 1／2、会话 0、空过滤器。它是输出关闭时的显式本地建库步骤，不是启动自动恢复、网络工具或擦除已用记录的 API。建库中断可能留下 FAULT；本轮不提供清空历史的维修入口。后端换盘、恢复出厂、升级迁移不能默认为新介质建库。

对象为固定内存、无堆分配；包含当前过滤器和一个完整槽大小的工作缓冲，需静态或堆上分配。回调对象／context 生命周期需覆盖存储对象。`save` 拒绝减少位图、会话倒退或跳号，相同数据不执行 I/O。

## 协议与启动接入

启动时先关断输出并完成本地自检，使用 `ct_replay_store_load` 加载介质；仅真正首次使用且有本地授权时 provision 空白介质。在 `ct_runtime_init` 后、首个 CONNECT 前，调用一次 `ct_protocol_attach_store`。绑定恢复过滤器和会话代次，不恢复初始化标记、原响应、动作序号、使能或任何输出。适配器对象／存储对象需在整个启动期有效，存储对象由协议独占。

绑定失败（含空白、损坏、缺失接口／NULL）会锁定持久化动作，禁止重绑或回退到 RAM。当前 `ct_protocol_init` 的未绑定模式保留给离线兼容测试，状态显示 `scope=boot, storage=volatile`；**真实动作接入必须先成功绑定持久化存储，并提供独立的新鲜度证据**。不能把忘记绑定的 RAM 模式当作跨复位保护。

正常路径先保留下一会话代次并完整持久化，再使其成为协议会话。因此有效恢复后不复用旧会话代次。建立会话失败仍可开本地诊断连接，但 `storage=fault`，所有动作锁定；该诊断代次不作为已持久化的会话承诺。

对缓存未命中的非只读请求，先将规范化 ID 写入 RAM 过滤器，再持久化完整过滤器，最后才分派请求或接受动作；包括参数／能力／使能等原因拒绝的请求。写入失败返回 `-32005`，撤销逻辑输出并锁定所有后续动作，重连和本地使能均不能清除此锁定。运行层随后应用关断；关断失败仍按原有运行层规则抑制响应。已有缓存的原响应可以回放，但永不重新分派动作。

合法停止先执行且不等待存储；初始化、ping、工具发现、状态查询也不逐条写介质。它们的 ID 先记录于 RAM，下次非只读分派或会话切换前一并持久化。掉电前尚未检查点保存的只读／停止 ID 不承诺跨复位保留；它们此前未启动动作。已成功接受的动作一定先经过持久化，不存在后台异步补写窗口。故障状态下诊断与停止不再访问存储，状态返回 `scope=persistent, storage=fault`；正常绑定为 `storage=ready`。

如果存储已落盘而响应未发出、物理输出未发生，或 API 返回了不确定的失败，重启后也可能把该 ID 判为已使用并拒绝：保障是**相同 ID 的动作至多接受一次，允许不执行**，不是掉电后恰好执行一次或恢复未完成动作。成功恢复后仍需重新握手、协议初始化、本地明确使能和新鲜度验证。不同意图 ID 必须在持久化历史生命周期内唯一，不能每次复位重新从零计数。

## 资源与真实适配门槛

主机 ABI 下协议对象为 137392 字节，另有存储对象 65640 字节；双槽介质 65600 字节。每次改变过滤器／会话的提交会完整重写一个槽并同步两次，未提供磨损均衡、压缩或后台批写。这是便于验证的有界接口实现，不是 Flash 吞吐、寿命或存储选型结论。过滤器误拒绝会跨复位累积，不因重启变空；饱和与维修迁移方案仍待设计。

目前存储回调同步运行在单一控制任务中。后端必须满足控制周期和输入响应预算；不可直接接入可能长期阻塞的擦除／sync 实现。运行层会在回调返回后重新采样停止、推进时钟并检查周期，超时不应用新动作输出，但不能抢占永不返回的存储调用；已有动作期间的最坏停止延迟仍需真实后端和独立停止路径验收。启动期读取／建库另受启动看门狗约束。真实 SDK、写缓冲掉电语义、设备／分区绑定、完整旧镜像回滚、坏块和维修策略尚未验证。

## 验证边界

主机假存储分别模拟易失写缓存和持久化字节，掉电丢弃缓存。测试覆盖六个保存回调位置的 22 个边界长度、丢弃／部分落盘两种模式，以及首次建库中断；另翻转格式、版本、会话、过滤器、CRC 和标记中的位，拒绝单槽丢失、读取失败和有合法 CRC 的不连续版本。

这些测试验证接口契约下的恢复逻辑，不证明实际 sync、Flash 隔离、原子写、磨损、处理时延或独立停止能力。真实驱动必须提供上述持久化保证；不能把本机内存复制视为 Flash 已验证。
