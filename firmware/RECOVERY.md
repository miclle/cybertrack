# 持久化中断后的本地维护恢复

状态：2026-10-24，维护恢复接口与主机存储故障模拟已实现。只用于输出关闭、全部协议所有者退役后的显式本地维护，不是正常启动自动修复、远程工具或清空历史入口。

## 可恢复的证据与边界

现有独立锚点仅保存后端身份、版本、会话和 epoch，不保存防重放位图，也不区分某个预留版本是否最终接受过动作。如果锚点指向版本 N，而介质只有 N−1，可能是写入中断，也可能是 N 已经接受动作之后介质被回滚。两种状态不能仅凭这些字节区分；恢复 N−1 或把锚点降回 N−1 都可能丢失已接受动作的历史。

`ct_replay_store_recover(source, anchor, source_id, destination, destination_id)` 因此只接受**当前选中后端上与锚点版本、会话精确匹配的完整有效快照**。即使普通 load 因另一槽空白或损坏而返回 FAULT，维护流程仍可读取这个完整快照，将全部历史转移到空白替代后端。

| 状态 | 维护处理 |
|---|---|
| 当前快照完整，另一槽空白／CRC 损坏 | 可复制当前完整历史到独立空白目标 |
| 两槽完整，但最后一次回读失败使 RAM 锁定 | 重新读取介质与锚点，证据一致即可恢复 |
| 锚点已预留 N，介质只有 N−1 或 N 的半写内容 | 此快照恢复入口返回 HISTORY_UNAVAILABLE；若启用独立日志，另用日志恢复入口核验证据，不能凭旧槽补齐 |
| 有效另一槽比锚点更新，或包含当前快照缺失的位 | HISTORY_CONFLICT；不能静默丢弃这部分历史 |
| 源是退役后端、锚点无效／不可读、会话不匹配 | 拒绝，不登记新锚点、不重置历史 |
| 目标非空、与源同一对象／context／身份 | 拒绝，不覆盖已有介质 |

缺少完整当前快照时，不提供有损恢复路径。已增加[独立日志恢复](RECOVERY-LOG.md)，在领取尝试前持久化原历史的过渡记录，再保留它并准备新候选；预留数据版本前确认候选持久化，通过唯一尝试 epoch 绑定候选；另用 `ct_replay_store_recover_log` 核对日志与当前锚点。原快照恢复入口不放宽校验，旧版本仍不是足够证据。CRC 仍只检测意外损坏，不能代替认证。不可回滚的锚点、可信设备／后端身份、介质隔离与防固件降级条件沿用[原子切换契约](ATOMIC-SWITCH.md)。

## 仅快照恢复的执行顺序

1. 关闭输出、停止全部写入并退役原协议对象。源必须已调用 load（允许 FAULT）；目标须 load 为 EMPTY，物理独立且使用不同可信身份。存储回调与锚点由同一串行所有者独占。
2. 维护调用锁定源、目标 RAM 对象；重新读取锚点，核对源身份、非零版本及溢出边界。
3. 根据锚点版本定位当前槽，校验格式、CRC、提交标记、版本及会话，读取完整位图；读取另一槽，拒绝可识别的矛盾历史。再次核对锚点未变。任一读取失败均保守拒绝。
4. 重新确认目标双槽为空白，写入完整位图和原会话，使用锚点版本 +1／+2，两个槽都 sync 并完整回读。整个过程不擦写源，不减少任何历史位。
5. 比较并原子提交新目标身份与新版本、epoch +1，再回读锚点。只有全部成功才将目标标记为 READY、已绑定；源保持 FAULT。
6. 创建新的协议所有者，绑定目标与独立日志后通过 logged 入口导入历史，分配新的持久化会话、重新初始化，并等待本地使能。维护成功不恢复原动作、使能、缓存或网络消息。

以上 `ct_replay_store_recover` 保留无日志兼容路径，不在选择目标前准备独立日志。需要跨选择连续证据时使用 `ct_replay_store_recover_log`：目标两个快照完成后先持久化目标日志，保留原锚点精确匹配槽，再选择目标并继承日志绑定；无需等待首个会话保存即可再次恢复，详见[日志契约](RECOVERY-LOG.md)。

返回枚举区分参数错误、锚点不可用、错误源身份、历史缺失／冲突、目标失败、选择结果不确定和计数耗尽；日志路径另区分目标日志准备失败 `CT_RECOVERY_LOG_UNAVAILABLE`。任何有效维护尝试失败后都不能继续使用原 RAM 对象；重新启动／load 后以实际锚点为准。没有自动重试、自动擦空或非空目标复用：失败后必须重新加载核验目标；若已非空，需另备经本地核对的空白替代介质，不能擦空旧目标以重试。

若目标复制失败，锚点仍选源，源的完整证据保留，允许后续显式维护重试；若选择已提交却返回失败，只能恢复新目标。不得因旧源仍有完整快照而切回它。普通 load／bind 的双槽严格校验不变，维护接口是单独受控入口。

## 存储验证

`replay_recovery_test.c` 覆盖 5 组场景：168 次目标中断（14 个操作位置 × 6 个边界 × 2 种落盘模式）、8 次锚点失败、2 次源读取失败，以及 7 种历史缺失／矛盾状态。包含恢复再次掉电、完整提交但返回失败、故障 RAM 被改写、旧镜像、真实预留中断、当前槽损坏、合法 CRC 的矛盾位图和会话不符。

测试逐字节检查源介质不变、成功目标完整保留历史；失败目标不能绕过锚点启动，选择不确定时按实际锚点恢复。快照恢复接口不改变主介质布局和锚点字段，不增加动态分配；后续日志指针使当前存储对象为 65704 字节，另需 32864 字节日志对象。真实存储、维护授权流程、回调时延、擦除隔离及实物断电仍须后续验收。

## 协议联测

4 组协议场景通过：176 次维护过程故障、72 次原始动作写入中断、8 次原始锚点失败、50 次连续维护恢复及 1239 次拒绝断言，未恢复旧动作。成功恢复必须新建协议、保留下一会话并由本地再次使能；丢失原响应、换 RPC ID、回到旧后端均不能重放历史动作。证据不足时维持存储故障，查询与停止仍可使用。完整 21/21 ASan／UBSan 回归及 Release 纯库构建通过，详见[验证记录](tests/README.md#中断维护恢复验证)。
