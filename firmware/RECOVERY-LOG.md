# 当前快照缺失时的独立恢复日志

状态：2026-10-24，板型无关接口及主机掉电模拟已实现。日志为完整防重放位图的独立持久化证据；默认动作仍关闭，恢复仅限输出关闭、全部协议所有者退役后的显式本地维护。

## 写入与唯一候选

在 load／bind 成功后、打开协议会话前，使用 `ct_replay_log_init` 配置日志，再用 `ct_replay_store_attach_log` 绑定到已锚定存储。init 不读取、擦除或认证介质，也不为旧历史补写证据。每次改变位图或会话的 save 按以下顺序执行：

1. 核对当前锚点；以原子 CAS 将 epoch +1，保持后端、版本、会话不变，并回读确认。这个 epoch 专用于领取不会复用的写入尝试。
2. 为下一版本构造完整候选记录：epoch 再 +1、版本 +1、目标会话、当前后端和完整位图。写入独立日志的下一槽，sync、提交标记、再次 sync，完整回读确认。
3. CAS 并回读候选锚点，预留新的数据版本。此时日志已持久化，即使主快照尚未写入，也能找到唯一匹配的完整历史。
4. 写入并回读主快照，最后核对锚点；全部成功后上层才可接受会话／动作。任何失败都锁定存储，不回退到无日志写入。

每次改变历史消耗两个 epoch。无变化的保存不写日志；计数耗尽不能回绕。失败候选的完整 `(epoch, backend_id, revision, session)` 不会被其他内容复用：重试先领取新的尝试 epoch，再写候选。这也防止日志已经完整、数据版本尚未预留时留下的旧候选被误选。

| 断电位置 | 可用证据 |
|---|---|
| 领取尝试之前 | 原主快照和原锚点 |
| 领取尝试之后、日志尚未完成／候选锚点尚未提交 | 原主快照仍完整且匹配数据版本；未选中日志不能用于恢复 |
| 数据版本已预留、主快照尚未写完 | 独立日志精确匹配当前锚点，可本地维护恢复 |
| 主快照写完但返回失败／响应丢失 | 历史已保留；重新启动或维护后不执行旧动作 |

领取尝试改变 epoch 后，旧日志不再匹配；此阶段主介质未被修改。如果主介质同时独立丢失，可能无法恢复，必须保持锁定，不能放宽日志匹配条件。未启用日志的历史也不具备这项额外恢复保证。

## 介质与回调契约

日志复用 `ct_replay_io` 的 read／erase／write／sync 语义，但槽大小为 `CT_REPLAY_LOG_SLOT_BYTES = 32816`，双槽合计 65632 字节。每槽必须独立擦除，日志与主介质、恢复目标及不可回滚锚点须隔离。相同 context 会被拒绝；不同 context 并不能证明物理隔离，实际适配器仍须验收。

| 偏移 | 内容 |
|---|---|
| 0–7 | `CTLG`、格式版本 1 和保留零字节 |
| 8–39 | 四个 little-endian uint64：epoch、backend_id、revision、session |
| 40–32807 | 完整 32768 字节防重放位图 |
| 32808–32811 | 前述内容的 little-endian CRC32 |
| 32812–32815 | 最后提交的 `DONE` 标记 |

使用 `(revision - 1) % 2` 定位槽，准备下一版本时不改写前一版本日志。CRC32 仅检测意外损坏，不是认证。锚点布局不变，但驱动必须支持数据字段不变的 epoch-only CAS，并比较全部四个字段。每次成功必须真正持久化且不可回滚；返回失败可能已提交，不能按返回值推断旧值仍有效。沿用[原子切换契约](ATOMIC-SWITCH.md)的可信身份、防固件降级和串行所有权要求。

## 维护恢复

`ct_replay_store_recover_log(source, log, anchor, source_id, destination, destination_id)` 重新读取独立锚点，核对源身份，并读取与全部四个锚点字段精确匹配的日志槽。不能按“最新日志”、旧版本或候选内容猜测；缺失、半写、CRC 损坏、旧 epoch、退役源身份均拒绝。日志读取失败锁定日志对象，须重新初始化并重新核验证据。

源须已经 load 初始化（允许 FAULT／EMPTY）；恢复不读取或写入主介质，也不改写日志。空白且独立的目标重新验证后，写入两个完整快照（版本 +1／+2），各自 sync 并回读，再原子选择目标。源保持 FAULT。目标写入中断保留原日志，允许以后使用另一个经本地核对的空白目标重试；锚点选择结果不确定时重新启动，以实际锚点为准，不自动擦空失败目标。

恢复成功不会开启输出、恢复动作或旧会话。新协议所有者须绑定目标与日志，通过 `ct_protocol_attach_logged_store` 检查配置，持久化新会话、初始化并等待本地使能。旧日志仍绑定旧后端／版本，不能直接作为新目标的当前证据；新会话写入会生成目标日志。目标选择前其两个主快照已完整，因而无需把日志改写夹入选择事务。

接口无动态分配。当前 macOS arm64：存储对象 65704 字节，新增日志对象 32864 字节；均须静态／堆分配并纳入目标 RAM 和擦写预算。

## 主机验证

`replay_log_test` 的 6 组场景通过 ASan／UBSan：132 个日志中断、72 个主快照中断、12 个锚点故障、168 个目标恢复中断和 88 个单比特损坏；另覆盖未选中候选不能被重试重新命名、当前主快照完全缺失、日志与源不变、错误配置及 epoch 耗尽。历史位丢失为 0。协议／运行层 5 组联测另覆盖 132 次日志故障、72 次主快照故障、各 12 次动作／会话锚点失败、176 次恢复故障、100 次连续恢复和 6 种输出顺序，未恢复旧动作。完整 19/19 ASan／UBSan 回归、Release 纯库及测试符号排除通过，见[验证记录](tests/README.md#独立恢复日志验证)。

这里只验证接口和故障模型。真实 Flash／NVS、不可回滚锚点、介质隔离、磨损、时延及实物断电尚未验收。
