# 当前快照缺失时的独立恢复日志

状态：2026-10-24，板型无关接口及主机掉电模拟已实现。日志为完整防重放位图的独立持久化证据；默认动作仍关闭，恢复仅限输出关闭、全部协议所有者退役后的显式本地维护。

## 写入与唯一候选

在 load／bind 成功后、打开协议会话前，使用 `ct_replay_log_init` 配置日志，再用 `ct_replay_store_attach_log` 绑定到已锚定存储。init 不读取、擦除或认证介质，也不为旧历史补写证据。每次改变位图或会话的 save 按以下顺序执行：

1. 核对当前锚点，扫描双槽定位精确匹配记录，在另一槽写入**过渡记录**：完整复制当前已提交位图、保持版本／会话／后端不变，只令 epoch +1。sync、提交标记、再次 sync 并完整回读；此前不改变锚点。
2. CAS 将锚点推进到过渡记录并回读，领取唯一尝试 epoch。原主快照仍匹配数据版本；即使它随后丢失，也有已持久化的过渡日志。
3. 保留选中的过渡记录，在另一槽准备新候选：epoch 再 +1、数据版本 +1、目标会话、后端及完整新位图。两次 sync 和完整回读成功后，才 CAS／回读候选锚点，预留数据版本。
4. 写入并回读主快照，最后核对锚点；全部成功后上层才可接受会话／动作。任何失败都锁定存储，不回退到无日志写入。

每次改变历史仍消耗两个 epoch，但日志要写两个完整记录。无变化的保存不写日志；计数耗尽不能回绕。过渡记录只复制已提交历史，不包含本次尚未选中的动作。失败后重试过渡记录时，同一锚点元组始终对应相同已提交历史；新内容候选必须先领取新尝试 epoch，不能把失败候选元组用于其他内容。

| 断电位置 | 独立恢复证据 |
|---|---|
| 过渡记录准备中、领取尝试之前 | 原锚点仍有效，原匹配日志保持不变 |
| 过渡记录完整、领取尝试 CAS 返回失败 | 重读实际锚点；未提交用原日志，已提交用过渡日志 |
| 领取尝试之后、新候选尚未写完 | 过渡日志精确匹配当前锚点，完整保留此前防重放历史 |
| 新候选完整、数据版本尚未选中 | 仍用过渡日志，不追认未选中新动作 |
| 数据版本已预留、主快照尚未写完 | 新候选日志精确匹配锚点，包含待处理动作身份 |
| 主快照写完但返回失败／响应丢失 | 已选中历史完整保留；恢复不执行旧动作 |

这条连续性从已有匹配日志或首份过渡记录被选中开始成立，覆盖领取尝试后的整个候选准备窗口。首次接入、迁移或恢复刚选择新目标而尚未写入其首份过渡日志时，仍依赖已验证的完整主快照；init／attach 不会追溯生成日志。当前主快照和精确匹配日志都不可用时继续锁定，不能降低匹配条件或把旧版本当作当前历史。

## 介质与回调契约

日志复用 `ct_replay_io` 的 read／erase／write／sync 语义，但槽大小为 `CT_REPLAY_LOG_SLOT_BYTES = 32816`，双槽合计 65632 字节。每槽必须独立擦除，日志与主介质、恢复目标及不可回滚锚点须隔离。相同 context 会被拒绝；不同 context 并不能证明物理隔离，实际适配器仍须验收。

| 偏移 | 内容 |
|---|---|
| 0–7 | `CTLG`、格式版本 1 和保留零字节 |
| 8–39 | 四个 little-endian uint64：epoch、backend_id、revision、session |
| 40–32807 | 完整 32768 字节防重放位图 |
| 32808–32811 | 前述内容的 little-endian CRC32 |
| 32812–32815 | 最后提交的 `DONE` 标记 |

扫描两个槽，以完整锚点四元组定位唯一有效记录；不再由数据版本奇偶定位日志槽。同一数据版本可以经历多个尝试 epoch。准备记录只写另一槽，保留当前匹配记录；无匹配记录仅允许由已加载、已锚定的完整主历史开始建立过渡记录。读取失败或重复匹配记录保守拒绝，恢复不按最大 epoch 猜测。CTLG v1 字节布局不变，旧版按版本奇偶存放的有效记录仍可读取；旧固件不能据此宣称具备新的准备阶段连续性。CRC32 仅检测意外损坏，不是认证。锚点布局不变，但驱动必须支持数据字段不变的 epoch-only CAS，并比较全部四个字段。每次成功必须真正持久化且不可回滚；返回失败可能已提交，不能按返回值推断旧值仍有效。沿用[原子切换契约](ATOMIC-SWITCH.md)的可信身份、防固件降级和串行所有权要求。

## 维护恢复

`ct_replay_store_recover_log(source, log, anchor, source_id, destination, destination_id)` 重新读取独立锚点，核对源身份，并扫描双槽读取与全部四个锚点字段精确匹配的唯一日志记录。不能按“最新日志”、旧版本或候选内容猜测；缺失、半写、CRC 损坏、旧 epoch、退役源身份均拒绝。日志读取失败锁定日志对象，须重新初始化并重新核验证据。

源须已经 load 初始化（允许 FAULT／EMPTY）；恢复不读取或写入主介质，也不改写日志。空白且独立的目标重新验证后，写入两个完整快照（版本 +1／+2），各自 sync 并回读，再原子选择目标。源保持 FAULT。目标写入中断保留原日志，允许以后使用另一个经本地核对的空白目标重试；锚点选择结果不确定时重新启动，以实际锚点为准，不自动擦空失败目标。

恢复成功不会开启输出、恢复动作或旧会话。新协议所有者须绑定目标与日志，通过 `ct_protocol_attach_logged_store` 检查配置，持久化新会话、初始化并等待本地使能。旧日志仍绑定旧后端／版本，不能直接作为新目标的当前证据；新会话写入会生成目标日志。目标选择前其两个主快照已完整，因而无需把日志改写夹入选择事务。

接口无动态分配。对象大小未变。当前 macOS arm64：存储对象 65704 字节，新增日志对象 32864 字节；均须静态／堆分配并纳入目标 RAM 和擦写预算。

## 主机验证

`replay_log_test` 的 8 组存储场景覆盖 352 个日志中断（过渡／候选各 8 个回调位置 × 11 个字节边界 × 2 种落盘模式）、72 个主快照中断、12 个锚点故障、168 个目标恢复中断和 88 个单比特损坏；包含 100 次连续准备失败、日志槽位置变化、重复匹配及未选中完整记录拒绝。日志或锚点失败后移除主快照，仍只恢复实际锚点对应的完整历史，历史位丢失为 0。协议／运行层 7 组联测覆盖动作／会话各 352 次日志故障、72 次主快照中断、各 12 次动作／会话锚点失败、176 次原恢复故障、100 次原连续恢复、100 次准备阶段中断后恢复（含 25 次恢复再次中断）和 6 种输出顺序；5115 次拒绝断言未恢复旧动作。完整 19/19 ASan／UBSan 回归与 Release 纯库检查通过，结果见[验证记录](tests/README.md#独立恢复日志验证)。

这里只验证接口和故障模型。真实 Flash／NVS、不可回滚锚点、介质隔离、磨损、时延及实物断电尚未验收。
