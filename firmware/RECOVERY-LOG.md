# 当前快照缺失时的独立恢复日志

状态：2026-10-24，板型无关接口及主机掉电模拟已实现。日志为完整防重放位图的独立持久化证据；默认动作仍关闭，恢复仅限输出关闭、全部协议所有者退役后的显式本地维护。

本文描述保留的双槽模式。新增显式[四槽冗余模式](REDUNDANCY.md)以两份相同当前证据容忍单槽损坏，目标两份完成后才提交选择；双槽的重复匹配／读失败拒绝规则不自动套用于四槽模式，不能静默切换模式。

## 写入与唯一候选

首次登记使用 `ct_replay_store_enroll_logged`，已有锚点则在 load／bind 成功后调用 `ct_replay_store_attach_log`；均先使用 `ct_replay_log_init` 配置独立日志，成功后才允许协议接入。init 只配置回调，不读取、擦除或认证介质。每次改变位图或会话的 save 按以下顺序执行：

1. 核对当前锚点，扫描双槽定位精确匹配记录，在另一槽写入**过渡记录**：完整复制当前已提交位图、保持版本／会话／后端不变，只令 epoch +1。sync、提交标记、再次 sync 并完整回读；此前不改变锚点。
2. CAS 将锚点推进到过渡记录并回读，领取唯一尝试 epoch。原主快照仍匹配数据版本；即使它随后丢失，也有已持久化的过渡日志。
3. 保留选中的过渡记录，在另一槽准备新候选：epoch 再 +1、数据版本 +1、目标会话、后端及完整新位图。两次 sync 和完整回读成功后，才 CAS／回读候选锚点，预留数据版本。
4. 写入并回读主快照，最后核对锚点；全部成功后上层才可接受会话／动作。任何失败都锁定存储，不回退到无日志写入。

每次改变历史仍消耗两个 epoch，但日志要写两个完整记录。无变化的保存不写日志；计数耗尽不能回绕。过渡记录只复制已提交历史，不包含本次尚未选中的动作。失败后重试过渡记录时，同一锚点元组始终对应相同已提交历史；新内容候选必须先领取新尝试 epoch，不能把失败候选元组用于其他内容。

| 断电位置 | 独立恢复证据 |
|---|---|
| 过渡记录准备中、领取尝试之前 | 原锚点仍有效，原匹配日志保持不变 |
| 过渡记录完整、领取尝试 CAS 返回失败 | 重读实际锚点；未提交用原日志，已提交用过渡日志 |
| 领取尝试之后、新候选尚未写完 | 过渡日志精确匹配当前锚点，完整保留此前防重放历史 |
| 新候选完整、数据版本尚未选中 | 仍用过渡日志，不追认未选中新动作 |
| 数据版本已预留、主快照尚未写完 | 新候选日志精确匹配锚点，包含待处理动作身份 |
| 主快照写完但返回失败／响应丢失 | 已选中历史完整保留；恢复不执行旧动作 |

新登记、带日志切换和日志恢复均在选择目标前持久化目标的完整日志，因此选中后即使尚未打开会话、保存新状态或生成首份过渡记录，也能独立恢复。当前主快照和精确匹配日志都不可用时继续锁定，不能降低匹配条件或把旧版本当作当前历史。

## 首次登记与目标选择

- `ct_replay_store_enroll_logged(store, log, anchor, id)` 仅用于本地核对过的完整历史和从未使用的全零锚点。先写入并回读 `{1, id, revision, session}` 的完整日志，再 CAS／回读锚点；失败锁定。日志准备中断时锚点仍为零，不能自动认领候选；只能重新核对原完整主历史并显式重试登记。
- 旧存储通过 `ct_replay_store_attach_log` 接入时，先核对当前锚点，再建立其精确匹配日志，最后复核锚点。已有唯一匹配记录须逐字节核对完整位图，不重复写入；同一键对应不同历史、重复匹配或读取失败均拒绝。旧系统在接入完成前仍依赖原完整主历史，不能追溯保证此前没有日志的窗口。
- 带日志的 `ct_replay_store_switch` 和 `ct_replay_store_recover_log` 都先写入并回读目标的两个完整主快照，再在另一日志槽写入目标身份、版本、会话及完整历史，最后 CAS／回读选择目标。准备目标日志时保留原锚点精确匹配槽；中断后按实际锚点选择源或目标证据。成功目标继承日志绑定，不需要下一次 save 才建立证据。

日志登记／补种和每次目标选择增加一份完整日志写入、两次 sync；已有正确日志的 attach 仅扫描两槽。普通 save 的两个 epoch、两份日志及四次 sync 成本不变。旧的无日志 enroll／switch 和仅快照 recover 保留兼容测试用途，不提供这一独立证据保证；生产恢复路径使用 recover_log。维护前须关闭输出并退役所有协议所有者，不允许 JSON 或网络调用触发登记、擦除或选主。

## 介质与回调契约

日志复用 `ct_replay_io` 的 read／erase／write／sync 语义，但槽大小为 `CT_REPLAY_LOG_SLOT_BYTES = 32816`，双槽合计 65632 字节。每槽必须独立擦除，日志与主介质、恢复目标及不可回滚锚点须隔离。相同 context 会被拒绝；不同 context 并不能证明物理隔离，实际适配器仍须验收。

| 偏移 | 内容 |
|---|---|
| 0–7 | `CTLG`、格式版本 1 和保留零字节 |
| 8–39 | 四个 little-endian uint64：epoch、backend_id、revision、session |
| 40–32807 | 完整 32768 字节防重放位图 |
| 32808–32811 | 前述内容的 little-endian CRC32 |
| 32812–32815 | 最后提交的 `DONE` 标记 |

扫描两个槽，以完整锚点四元组定位唯一有效记录；不再由数据版本奇偶定位日志槽。同一数据版本可以经历多个尝试 epoch。准备记录只写另一槽，保留当前匹配记录；缺少匹配记录时不能仅凭候选恢复；首次登记／接入从已核对完整主历史补种，正常 save 则以当前完整历史准备过渡记录。读取失败或重复匹配记录保守拒绝，恢复不按最大 epoch 猜测。CTLG v1 字节布局不变，旧版按版本奇偶存放的有效记录仍可读取；旧固件不能据此宣称具备新的准备阶段连续性。CRC32 仅检测意外损坏，不是认证。锚点布局不变，但驱动必须支持数据字段不变的 epoch-only CAS，并比较全部四个字段。每次成功必须真正持久化且不可回滚；返回失败可能已提交，不能按返回值推断旧值仍有效。沿用[原子切换契约](ATOMIC-SWITCH.md)的可信身份、防固件降级和串行所有权要求。

## 维护恢复

`ct_replay_store_recover_log(source, log, anchor, source_id, destination, destination_id)` 重新读取独立锚点，核对源身份，并扫描双槽读取与全部四个锚点字段精确匹配的唯一日志记录。不能按“最新日志”、旧版本或候选内容猜测；缺失、半写、CRC 损坏、旧 epoch、退役源身份均拒绝。日志读取失败锁定日志对象，须重新初始化并重新核验证据。

源须已经 load 初始化（允许 FAULT／EMPTY）；恢复不读取或写入源主介质。空白且独立的目标重新验证后，写入两个完整快照（版本 +1／+2），各自 sync 并回读，再准备目标日志，最后原子选择目标。源保持 FAULT。目标日志准备失败返回 `CT_RECOVERY_LOG_UNAVAILABLE`；源精确匹配日志槽保持不变，另一槽可能部分改写。目标写入中断允许以后使用另一个经本地核对的空白目标重试；锚点选择结果不确定时重新启动，以实际锚点为准，不自动擦空失败目标。

恢复成功不会开启输出、恢复动作或旧会话。新协议所有者须绑定目标与日志，通过 `ct_protocol_attach_logged_store` 检查配置，持久化新会话、初始化并等待本地使能。新目标的当前日志在选择前已经完整；可在尚未打开新会话时再次恢复。恢复不依赖旧后端记录冒充新目标证据。

接口无动态分配。对象大小未变。当前 macOS arm64：存储对象 65704 字节，新增日志对象 32864 字节；均须静态／堆分配并纳入目标 RAM 和擦写预算。

## 主机验证

`replay_log_test` 的 8 组存储场景覆盖 352 个日志中断（过渡／候选各 8 个回调位置 × 11 个字节边界 × 2 种落盘模式）、72 个主快照中断、12 个锚点故障、168 个目标恢复中断和 88 个单比特损坏；包含 100 次连续准备失败、日志槽位置变化、重复匹配及未选中完整记录拒绝。日志或锚点失败后移除主快照，仍只恢复实际锚点对应的完整历史，历史位丢失为 0。协议／运行层 7 组联测覆盖动作／会话各 352 次日志故障、72 次主快照中断、各 12 次动作／会话锚点失败、176 次原恢复故障、100 次原连续恢复、100 次准备阶段中断后恢复（含 25 次恢复再次中断）和 6 种输出顺序；5115 次拒绝断言未恢复旧动作。新增 `replay_selection_test` 的 5 组场景覆盖登记、接入、切换各 176 个日志中断、220 个恢复日志中断、22 个锚点故障以及 100 次不经任何会话保存的连续恢复，历史位丢失为 0；新增 4 组协议联测覆盖 176 次登记日志故障、176 次切换日志故障、220 次恢复日志故障、168 次目标主快照故障、22 次锚点故障及 100 次切换后立即连续两次恢复，6987 次拒绝检查无旧动作。最终 21/21 ASan／UBSan 回归与 Release 纯库检查通过；执行和复跑细节见[验证记录](tests/README.md#首次接入与目标选择连续性验证)。

这里只验证接口和故障模型。真实 Flash／NVS、不可回滚锚点、介质隔离、磨损、时延及实物断电尚未验收。
