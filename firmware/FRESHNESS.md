# 命令新鲜度与意图身份

## 离线契约

设备在生产者创建新意图之前发布限时窗口：`session`、`enable_generation`、`window`。窗口到期时间来自设备单调时钟，预算采用 `max_queue_ms`；生产者不需要与设备同步墙上时钟。窗口续发立即废弃旧窗口；重连、本地重新使能、复位都不能沿用旧窗口。接收、分片、排队和重试不能延长到期时间。

生产者为每个真正的新意图分配非零 `uint64_t intent`。同一意图重试必须保留该 ID，包括更换 JSON-RPC ID、重连和设备复位；不能从 JSON-RPC ID、当前窗口或参数哈希临时生成。ID 在设备持久化历史的整个生命周期内不得复用；多生产者需共享唯一命名空间。耗尽时停止创建动作，不允许回绕。不同的新意图可以具有完全相同的动作参数。

`ct_action_proof` 是经过认证且绑定完整动作内容的元数据，必须随原始消息一同保存。未来的服务适配器负责验证来源、设备身份、窗口、意图与内容绑定。不能把收到消息的时间当作创建时间，不能在收到旧动作后向它补发新窗口或新意图。仅有字段或布尔值不构成认证证据；本模块不实现密码学或真实服务端。

## 已完成实现

- 第一阶段：`freshness.c` 提供不分配内存的窗口签发与检查，`freshness_test` 覆盖截止边界、延迟首次到达、时钟倒退、跨会话/使能、窗口更替及计数耗尽。ASan/UBSan 主机构建及该测试通过。
- 第二阶段：协议强制检查 proof；接收首片及队列按值保留原证据；RPC ID 与稳定意图 ID 在同次持久化提交中预留。换 ID／窗口、缓存淘汰、重连、复位及断电模拟通过。窗口已过期、参数错误或未就绪的意图在预留成功后同样退役。
- 输出前再次检查新目标窗口；存储成功但耗尽窗口时关闭会话、抑制回复，不调用非零输出回调。停止始终不依赖窗口或意图，不增加持久化等待。

## 保证边界

窗口只能约束“取得窗口后创建的意图”最迟被接受的时间。生产者重新包装旧意图为全新身份的行为必须由上游禁止，设备不能从相同的动作参数区分这种行为与用户真正重复的指令。跨复位还要求绑定已加载的持久化存储；实际 Flash/NVS、认证消息映射、真实网络时延及硬件输出均待验证。

## 本地集成顺序

1. 启动时加载持久化历史，绑定协议对象；打开连接、完成协议初始化、本地使能。
2. 串行控制任务调用 `ct_protocol_issue_window`，把返回的会话／使能／窗口发给经认证的生产者。未有真实证据源前不开放动作。新窗口立即废弃前一个窗口；更新窗口的频率需与网络时延共同评估。
3. 生产者取得窗口后创建新意图，分配稳定 `intent`，认证绑定完整动作和 proof。重试保持原 proof，不获取新窗口“救活”旧意图；即使违规更换窗口，相同意图也会被已保存历史拒绝。
4. 经认证适配器向 `ct_link_receive` 的首片传入原 proof；需要先完整收包才能验签的适配器必须保留原始首次到达时间，并在外层设计认证缓冲交接，不能提前信任未验证片段。该 SDK 映射尚未实现。
5. 缺失／过期／跨 scope 的证据拒绝动作；缓存原响应不表示重新执行。已接受动作有独立的结束期限，窗口到期不自动延长或重启它。

`max_queue_ms` 现在同时限定签发到动作分派的总预算，数值仍需实际网络测量确定。`uint64_t` 字段的未来线上编码须避免 JSON／JavaScript 的 53 位整数精度损失；本轮只有 C 结构和模拟，未冻结服务端线协议。
