# 持久化后端原子切换与回滚保护

状态：2026-10-24，独立锚点接口、受保护写入、离线切换及主机掉电模拟完成。此处定义后端必须兑现的原子持久化和防回滚契约，未实现或验收真实 Flash／NVS 锚点。

## 独立锚点

`ct_replay_anchor_io` 提供 `read` 与 `replace(expected, next)`。锚点包含四个 uint64：`epoch`、`backend_id`、`revision`、`session`。`replace` 必须比较全部字段，原子、持久地替换；不匹配时不写入，返回 false。成功不允许仅存在于写缓存；失败可能已经完整提交，但不能留下撕裂记录。锚点须绑定设备并独立于可替换、可恢复快照的历史介质，不能随历史镜像一起回滚。真实实现还需验证擦除隔离、耐久性、延迟与访问保护。

后端 ID 非零，由可信本地适配器稳定地标识实际存储，不接受网络传入的标签。源、目标、锚点必须由同一个串行所有者管理；不能在回调内重入，也不能有并发写入。epoch 每次提交增加 1，禁止绕回；所有动作历史／会话更新都推进锚点，不仅在迁移时更新。

全零锚点只能表示“从未登记过”，不能把读失败、损坏、丢失、擦除或恢复出厂转换成全零。`ct_replay_store_enroll` 是输出关闭、历史已通过本地核验后的显式首次登记／旧版本导入，不能用来修复已使用锚点。首次登记无法证明导入前从未回滚的历史；该信任边界由本地维护流程承担。正常启动只调用 `load` 和 `bind`，不自动建库或登记。

## 保存与启动

`ct_replay_store_bind` 核对后端身份、完整双槽的版本／会话和锚点精确一致。`ct_replay_store_check` 及每次 `save` 都重新读取锚点，拒绝过时所有者；没有变化的保存也检查锚点，但不写入。

受保护保存顺序为：锚点核验 → 原子预留新版本并回读锚点 → 双槽写入、sync、完整回读 → 最终核对锚点 → 返回成功。先预留不可复用的版本，防止“候选快照已完整写入但返回失败 → 恢复旧介质 → 再次使用同一版本写不同内容”形成历史分叉。任何失败锁定该 RAM 对象，不允许本地使能、重连或重试清除。掉电后双槽与锚点版本若不一致（例如锚点已预留、介质未写完），仍锁定动作，不自动追认或回退；这会牺牲可用性，但不会遗漏已经允许执行的动作历史。锚点与介质都确认后才可发布会话或接受动作。

旧后端 ID、同一后端旧双槽镜像、选中介质缺失／损坏、锚点读取失败均拒绝恢复。未绑定锚点的底层保存／复制 API 保留兼容用途，不能作为带回滚保护的真实动作入口。

## 协议接入

完成 load／bind 后，在首个 CONNECT 前调用 `ct_protocol_attach_guarded_store`。该入口拒绝未绑定锚点的普通存储，失败锁定且不允许重绑或回退 RAM。动作前及新会话保留都会通过受保护 save，再发布会话或分派动作；锚点失败返回存储错误并关断。初始化、查询和停止不增加锚点写入。运行层在回调后重新采样停止及复核时限，不能抢占阻塞回调。旧 attach_store 与未绑定模式只保留离线兼容用途。

## 离线切换

必须先关断输出、关闭并退役旧协议所有者；从复制开始到切换结束均禁止其他写入。

1. `ct_replay_store_switch(source, destination, destination_id)` 核验源锚点、不同非零身份及独立空白目标。
2. 复用完整迁移：重读源双槽，复制全部历史位和会话，写出源版本 +1／+2 的两个完整目标槽并回读。源介质不擦除、不改写。
3. 比较源锚点并原子选择目标身份／版本，epoch +1；回读确认。只有全部成功才将目标对象标记为已绑定。
4. 旧 RAM 存储对象退役为 FAULT。旧对象副本在再次保存时也会因锚点不匹配拒绝。迁移不是重新使能或恢复动作；新协议仍需新会话、握手和本地使能。

| 中断位置 | 重启后的唯一选择 |
|---|---|
| 目标写入或回读未完成 | 锚点仍选源；完整源历史可恢复，目标不可启用 |
| 完整目标已写入，选择尚未提交 | 仍选源；不能根据目标看似完整就启用它 |
| 选择已提交，但调用返回失败或回读失败 | 只选目标；旧源拒绝 |
| 目标已接收新动作后切回旧源／目标旧镜像 | 身份或版本与锚点不一致，锁定动作 |
| 选中的介质不可用 | 锁定动作，禁止自动退回另一个完整后端 |

切换失败后源、目标当前对象都锁定；重启重新加载和绑定，由锚点决定唯一后端。未完成或未选中的目标不自动擦空重用；维修策略另行制定。反向迁移只能从当前选中历史完整复制到独立空白介质并再次提交，不能直接恢复旧快照。

## 已验证与剩余边界

`replay_switch_test` 在 ASan／UBSan 下覆盖 6 组场景：168 次复制中断、72 次保存中断、22 次锚点失败（含首次登记），以及候选版本不可复用、过时对象、旧后端、伪装成当前身份的旧版本、同后端旧快照、全空白替代介质、读取失败和 epoch 溢出。相关原存储、迁移及持久化测试同时通过。另有 5 组协议／运行层联测：176 次切换中断、各 8 次动作和会话锚点失败、50 次连续切换、6 种输出顺序及 732 次拒绝检查，未恢复旧动作。完整 15/15 ASan／UBSan 回归和 Release 纯库验证通过，详见[验证记录](tests/README.md#原子切换与回滚保护验证)。

假锚点只在完整旧记录与完整新记录之间选择；它模拟接口保证，不能证明实际芯片有该能力。如果连独立锚点也被整体回滚、身份映射被替换，或旧固件绕过锚点，纯软件无法凭相同旧字节识别回滚。真实设备绑定、不可回滚锚点、固件降级限制、Flash 寿命与最坏停止延迟均须后续验收，当前不开放实物动作。
